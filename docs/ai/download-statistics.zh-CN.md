# 下载用时与平均速度

## 口径与实现

任务总览增加“下载用时”“平均速度”，目录任务详情顶部展示相同统计。采用持久化传输增量，不采用任务创建至当前时间之差，也不累加并发文件各自的耗时。

- 仅计文件 HTTP 响应体传输阶段；同一根任务多个并发文件的重叠区间只计一次。
- 排队、暂停、等待重试、程序退出后的离线时间、目录准备、下载链接查询、本地校验和网盘后处理不计入。
- 平均速度 = 实际接收网络字节 / 累计传输时间。包含失败后重传的数据；不含断点已有字节、直接复用的本地文件。它反映传输吞吐量，不是文件净大小除以创建后的自然时长。
- 传输开始、结束，以及数据读取期间距上次保存满 5 秒时，将累计纳秒数、网络字节、本机 UTC 观察时间原子保存到已有 SQLite job JSON。无数据库表迁移，不新增大量审计事件。
- 运行期并发计数和单调时钟不持久化；重启后只读累计增量，绝不从旧时间戳补算离线时间。正常退出通过取消读取及结束回调保存尾段；强制结束可能丢失最后未保存增量，长时间没有读取进展时也不会凭空补算崩溃前的等待时间。时间与字节一起保存。
- 旧任务没有该统计时显示“历史统计未记录”；旧任务在升级后重试才开始采集时标注“部分记录”。不从旧完成文件大小或创建时间伪造精确统计。

旧记录不能分离实际传输、目录准备、校验和等待时间，也不能还原重传字节，因此这里只是历史区间参考，不能当作新统计口径的实测平均速度写入任务。

## 验证

用确定时间验证并发区间并集、100 秒空闲不计时、带未结束传输的状态从 SQLite 重开后不补算离线时间；模拟提供方验证实际接收字节采集和本地完成文件复用不增加统计；前端实际构建产物验证总览列、详情和历史缺失提示。
