# 认证、续期与管理入口设计

目标：网页授权结果持久化后实际应用；长期后台自动续期；认证失败暂停根任务，恢复后继续；管理入口有认证与跨站请求校验。沿用根任务存储锁和 Go 1.22，无新增运行服务。

## OAuth 与认证状态

- 官方 SDK 样例使用 GET，保留端点与参数兼容；增加 context、30 秒网络上限、读取上限、明确 OAuth 错误类型，不输出原始响应、Token、Secret、完整请求 URL。
- 设备码的 interval/expires_in 由服务端获取并保管，不信任浏览器传入的时限；一次只允许一条设备授权会话，开始新的会话取代旧会话；用户断开请求时可以停止轮询。
- 管理器串行化应用/刷新操作；手动授权先核验账号，匹配后原子保存并应用，错误账号不能替换现有凭证。自动刷新可能轮换 Refresh Token，因此先保存新的一对凭证，再查询并校验账号后应用；查询暂时失败仍能恢复。
- 凭证放在受队列锁保护的独立 credentials.json，以 0600 创建（Windows 沿用目录 ACL）；仅保存 Access/Refresh Token、应用标识、签发与过期时间，不保存 App Secret。保存记录优先于启动环境中的旧 Token，避免重启回退已轮换凭证。显式重新授权是更新入口。下载目录应为受信任的私有目录，当前没有凭证加密或 Windows 专用 ACL 重设。
- 独立 account.json 绑定百度 uinfo 的 uk；后续授权/刷新必须为相同账号。更换账号使用独立下载目录，不能仅删除 credentials.json 绕过账号绑定。
- 启动时先验证账号后允许扫描/worker。已知过期时间提前续期；未知时间且有 Refresh Token 时先刷新；无刷新能力时如实显示 expiry_unknown，遇到认证错误需要重新授权。
- 刷新临时失败采用退避；未过期旧凭证可继续工作，过期或被拒绝时暂停新任务。业务错误与网络错误分开；后台重试尊重下次时间，不每个扫描周期重打刷新接口。
- 对外只返回状态、是否可刷新、过期/下次尝试时间、经过筛选的错误类型，HTTP/WS/任务状态均不返回完整凭证。

## 管理入口

- 全部页面、API、WebSocket 使用管理员 Basic/Bearer 认证。ADMIN_PASSWORD 可指定强密码；未配置时生成随机密钥并保存私有 admin-key.json，日志只给文件位置，不打印密钥。
- 管理认证与百度 OAuth 独立。默认回环监听保持，远程建议 SSH 转发或受信任 TLS 反向代理。
- 非安全方法与 WebSocket 校验 Origin；拒绝 cross-site Sec-Fetch-Site；命令行携带认证头可无 Origin。WebSocket 不再接受任意来源。
- 云端文件名/路径/错误按文本转义；OAuth 状态页不展示完整 Token，授权链接只允许百度 HTTPS 域名。

## 验证与交付

真实本地 HTTP/磁盘测试覆盖授权取消、pending/slow_down、响应错误脱敏、轮换持久化、保存失败不应用、并发刷新合并、账号拒绝、健康状态不泄密、认证与 Origin/WS 校验。主模块 Windows/WSL race、三平台构建、包内 HTTP/重启冒烟后才交付新独立版本。真实百度授权、NAS 和 TLS 反代继续独立验收。

首次从无账号绑定的旧版本迁移只能绑定用户首次提供并验证的账号，无法从旧内存历史反推出账号；升级时应核对账号或使用新的下载目录。
