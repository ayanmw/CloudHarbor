# 持久化队列与后台调度设计

目标：重启保留根任务、设置与重试时间；只执行当前扫描确认仍在队列内的任务；限制并发，支持取消和服务退出。沿用 preview.3 的实际文件下载与完成凭据。

## 存储

任务当前投影和追加式证据存于 `.nas-downloader/queue/queue.sqlite`，使用 SQLite 事务原子写入；同一队列保留 `writer.lock` 单写入者锁。回滚日志使用 DELETE 模式，`synchronous=EXTRA`、单连接、外键启用；打开时核对格式版本、队列范围、完整性和实际 pragma。损坏、缺失或格式不匹配时失败关闭，不静默创建空库。详细迁移和事件时间定义见[SQLite 中文设计](../superpowers/specs/2026-10-28-taskstore-sqlite-design.zh-CN.md)。

旧 v1 每任务 JSON 通过校验后迁入临时数据库；重新打开、完整性、记录数与逐 ID 原文等价验证通过后，才切换格式清单。迁移事件仅说明导入，不补造旧历史时间。`intake/*.json`、凭证、账户绑定、下载设置仍是独立 sidecar，保持原 API、权限和恢复语义。

事件表按 SQLite 序号排序，不以可能漂移的本机时间排序。`recorded_at_utc` 是本机观察/提交证据时间；provider mtime 独立放在云端元数据证据中；只有拿到可靠发生时间时才写 `occurred_at_utc`；未来重试截止时间只在当前任务投影中，不伪装成过去事件。源项操作先事务落盘 `sending` 和 operation/attempt ID，再发送请求；重启恢复为 `unknown` 并隔离，完成确认失败时也保持隔离。

只持久化根任务，目录子任务由根任务重新展开，文件级进度以实际临时文件为准。数据库位置随下载目录移动；绑定规范化的云端 QueueDir，拒绝用同一存储切换队列。设置与任务记录不保存 Token、Secret 或下载链接。

## 调度

根任务包含 FileInfo、创建时的后处理模式、状态、尝试次数、下次尝试时间、最近错误、创建/更新时间。状态变化事件与投影在一个事务内提交。固定 worker 数默认 2，上限配置 32。扫描只原子登记/更新任务，不启动逐任务 goroutine。重复扫描合并，同一根任务最多一个 worker。

重启时历史 done/failed/cancelled 保留，进行中任务回到 pending。恢复任务在一次成功扫描确认 fs_id 和元信息之前不执行，避免直接操作已经移动/消失的旧路径。相同版本完成任务不重复下载；源版本变化创建新的尝试。扫描与下载解耦。

失败分类：网络错误、超时、HTTP 429/5xx、断流可退避重试；本地文件冲突、权限/磁盘错误、无效路径、认证错误不盲目重试。重试次数及下次时间持久化，达到上限后 failed。后处理与本地错误保存原始错误链，目录聚合不能丢失错误类型。

## 生命周期

所有百度请求传播 context。元数据调用有总超时，文件下载使用可取消上下文，不能用短总超时中止正常大文件。取消/关停后不得进入源文件后处理；本地临时数据保留。Shutdown 停止接收扫描、取消请求并等待 worker，再关闭存储锁；超时退出不假称已经排空。

当前没有云端快照/条件删除保障，仍只处理静止的测试队列。管理认证及 OAuth 属于后续阶段。

## 验证

真实本地文件记录的往返、损坏/错误配置拒绝、OS 锁跨进程排他与进程被杀后的释放；本地 HTTP 实际下载并发峰值、重复扫描、停止中的读取、恢复门禁、重试时序与取消源操作。Windows 与 WSL Go1.22 race、三平台构建及独立版本包验证。
