# 版本维护规则（2026-11-04起生效）

## 最新修订：正式版本收尾（2026-11-16）

本节优先于下文旧启动标签规则。版本收尾必须完成源码提交、工作流验证、最终提交的 annotated tag、推送及 GitHub Release 产物检查，然后才可由用户人工确认开启下一版。新版本启动不再建立同名正式标签。版本内可多次提交和测试构建，但不自动切版。

当前 v0.8.32 的旧标签为启动基线；用户明确授权本次替换为最终交付标签。先推送工作流并通过 workflow_dispatch 构建测试（只上传 Actions artifacts，不发布），再建立并推送 v0.8.32；标签触发相同门禁，先上传 draft Release，确认产物齐备后发布。后续已发布标签不自动移动，修改须明确授权。

工作流：`.github/workflows/release.yml`。产物：`CloudHarbor-v版本.zip` 与外部 `SHA256SUMS.txt`，包含 Windows amd64、Linux amd64/arm64，启动脚本与内嵌前端；不包含账号数据或实际 `.env`。失败时按原测试标准修复重测，不省略门禁。每次登记提交、tag、Actions run、Release URL及已知验收限制。本次授权不改变“NAS服务与Client仅设计、暂不开发”的范围。

用户2026-11-08明确要求开始下一个版本，现进入v0.8.32。当前版本由[配置](../../release/current-version.json)指定；[v0.8.32内容说明](../releases/v0.8.32.zh-CN.md)持续维护。

## 固定版本

1. 当前版本内持续合并功能、修复、UI/UE和验证，同一运行目录与ZIP覆盖更新，不再递增preview号。
2. 只有用户明确说“开始下一个版本”或明确指定新版本才切版。功能数、验收通过、普通“继续”及打包请求都不构成切版授权。
3. 切版时归档本地源码，在新版本启动基线建立同名annotated Git tag。此次创建v0.8.32，含义为启动基线；同版后续更新不移动该tag。最终内容用持续版本说明、Git提交与每包SOURCE-SNAPSHOT定位。
4. 旧的至少五项门槛和自动规划/发布下一编号机制停止生效；历史包不清理、不改名。[旧规则与交付记录](release-versioning-history.zh-CN.md)仅供回溯。

## 内容说明与更新证据

每版说明固定包含：产品目标；承接基线；本版已完成/进行中/待做；功能与交互变更；验证层级与未验收项；已知限制；构建UTC、Git基线/快照和包校验记录链接。规划不能混写成成果，不把历史状态当成当前执行情况。
同版版本号保持不变，通过BUILD-INFO中的提交、内容快照和构建UTC区分每次更新。默认打包读取current-version.json；VERSION-NOTES.zh-CN.md随包交付。

## 程序与用户数据

只替换程序白名单：bin、启动脚本、部署模板、说明、版本说明、BUILD-INFO、SOURCE-SNAPSHOT及SHA256SUMS。保留.nas-downloader、SQLite/WAL/SHM、授权/管理员sidecar、.env、downloads和其他用户文件。不能整个删除发布目录再重建。
构建、测试和三平台包先在staging完成。用户已授权：若当前版本正在运行，可告知后按目标exe绝对路径结束，再进行事务式替换；失败回滚程序，不回滚用户数据。不得按名称终止其他版本。更新后是否启动遵循用户当前任务，不擅自恢复服务。
跨版本先停止/确认无writer，再移动唯一真实状态，逐文件SHA核对、原目录消失并做SQLite只读完整性检查；不复制真实授权，不改变保存的本地下载目录。

## 当前命令

```powershell
# 默认当前版本；同版存在时原位更新。
.\scripts\package.ps1 -AllowDirty
# 显式指定当前版本。
.\scripts\package.ps1 -Version v0.8.32 -AllowDirty -UpdateCurrent
```

本地提交不包含push。下次版本名称和切版时点由用户决定；后续候选不提前分配版本号。

## 包内说明与本地事务检查

当前版本打包生成VERSION-NOTES.zh-CN.md：本包身份和已交付能力摘要默认展示，构建前源码记录原文放入附录。摘要须在源码版本说明的“本版已交付能力”维护，缺失/为空时打包失败；不自动把历史待验收条目改成通过。ZIP自身哈希在外部验证记录保存，避免在自身内容内生成循环校验。

Windows可运行 `.\scripts\package-current.test.ps1` 验证同版更新事务；使用真实临时身份fixture，其余服务/进程为mock，绝不读取真实账号。此检查与正式三平台编译、包/安装文件和数据核对分别记账。
