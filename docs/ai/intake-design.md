# 服务端入队事务边界

沿用阶段 D 既定路径入队计划：用户在管理页提交绝对云路径，先预检再确认；移动到服务端配置的 QUEUE_DIR，不覆盖、不自动改名。当前不操作真实账号。

## 协议与身份

- 每批 1..20 项，路径严格规范且有长度上限，拒绝根/队列本身及祖先、队列内部、同批父子、重复路径、重复目标名与保留/旧标记名称。
- 从源父目录重新获取元信息，目标队列必须可列出且无同名项目；已存在相同 fs_id 的下载历史需要单独核对，不静默重置历史。
- 预检生成随机 128 位 ID，保存不可由客户端修改的项目、目标、模式、认证 epoch、进程标识和 2 分钟时限。重启/认证变化/超时均使旧预检失效。
- 确认时再预检全批，源身份变化/目标冲突不发出移动。客户端仅提交 ID，不传目标目录、Token 或修改后的项目。

## 请求与落盘顺序

- 新增独立 intake/ JSON 记录，不混入下载 jobs/ 或凭证。逐项状态 ready → sending → moved/failed/unknown/not_sent，整批 preview → running → finished。
- sending 在移动请求前同步落盘并隔离目标路径；不能先发请求再保存。落盘后再次检查 context/认证 epoch，撤销则记 not_sent，不发送。每项独立同步 move，ondup=fail；禁用会重放 POST 的重定向；检查 HTTP、全局 errno、单项结果以及异步 taskid，异步受理迹象优先于失败码。
- 对发送后的结果再查询源/目标：只有源已不存在、目标具有相同 fs_id/类型/大小/MD5 等身份时，才可能确认 moved。目录还要求严格同步成功响应的 SyncConfirmed 凭据已落盘；没有该凭据，根身份不足以确认内容完成。使用目标实际元信息创建待扫描的根任务，模式固定为预检时模式；任务先落盘，再保存 moved 并解除隔离。
- 网络/响应异常或查询失败不能推断未移动；保留 unknown，不自动重发。明确失败响应且重新核对源未变、目标不存在时可记 failed，异步/无明确回复除外。
- 一批可能部分成功；认证改变、取消或不确定结果会停止后续未发送项。返回逐项状态，不用一个总成功掩盖部分失败。

## 竞争、崩溃与恢复

- 云端移动与本工具扫描/后处理使用同一读写锁：扫描和已有源后处理可并发读，入队确认独占写。锁之外仍有外部客户端并发修改的边界，百度按路径 API 没有条件移动锁，测试使用静止副本。
- sending/unknown 目标按路径隔离。扫描、认领和源后处理不得绕过隔离；不影响无关根任务。隔离从持久化记录恢复，不能依赖内存标志。
- 重启中 sending 转 unknown，不重发。反复读取同一已提交 ID 返回记录，不重复云端修改。
- 重新核对只做读取；证明已移动后才能登记并放行。源仍存在/目标不存在不能证明迟到操作永远不会发生，仍保留 unknown，不能暗中自动推断失败并重试。
- 用户已明确决定：结果未知且没有完成凭据的目录继续保持隔离，暂不提供人工放行。没有 release/force/acknowledge 路由或按钮，不将人工确认当成目录完成凭据。
- 已知异步结果保留 taskid，普通身份核对不自动放行；未知目录若未保存同步完成凭据也持续隔离，即使异步响应本身在崩溃中丢失。可靠异步完成查询仍待核实接口契约，当前实现不声称能自动解决所有 unknown。
- 存储失败在发出请求前则不发送；发出后保存失败保持旧 sending 记录和隔离，服务进入停止/降级，不继续处理源。后台退出需等待这些共享存储操作排空。

## 实施顺序

1. 无覆盖、严格响应的 MoveFile 契约测试与实现。
2. intake 存储和重启恢复；下载器预检、确认、核对及隔离/锁集成。
3. 本地真实 API/磁盘故障测试、独立 review、两平台 race。
4. 管理 HTTP、交互页面、油猴安全衔接与新独立测试包；未完成项继续保留，不把本核心当整阶段交付。

步骤 1、2、3 及管理 HTTP/UI 已实现。云端列表分页展示、路径输入、短时预检、明确勾选确认、逐项结果、记录筛选和只读核对均受既有管理认证保护。实际本地 HTTP → 下载器 → 磁盘日志 → 重启读回测试通过，重复确认只移动一次；Windows/WSL 全模块 race/vet、Node 7 项及独立 review 通过。浏览器在隔离夹具页面验证了选择、预检、确认及 unknown 提示，不能代替管理登录或真实百度验收。油猴衔接和可靠异步完成查询继续保留为后续工作，人工放行按用户决定排除。
