# v0.8.31 上传浏览器导航生命周期修复

独立审查P2：popstate在busy时return，但地址已改变，旧retry/cancel回执仍通过代际检查并继续轮询旧批次。源码核实创建清单/start仅检查active；导航失效后重新active也可能让旧清单或XHR回调串回新页。

范围：增加页面生命周期代际，只在离页/历史导航失效，普通轮询不影响。popstate始终先失效读/控请求、轮询与前台XHR，再按当前URL恢复；已接收后台任务不停止、不重发服务端请求。清单创建/start/send和request处理401前核对代际；XHR使用自己的实例，不引用可能被替换的全局xhr。旧finally不能解锁新页busy。恢复草稿清空仅随历史导航，非法批次URL不请求。

验证：重试/停止延迟时后退、旧finally不解锁新批次操作、旧401不登出新页、旧清单不改新路由/继续接收、导航中止前台XHR而迟到回调无影响；既有BFCache/目录选择/暂停继续与全前端。测试只模拟API/XHR，不启动真实服务，不改上传后端。修复后独立只读复核，再同版交付。

结果：RED pending命令后退仍显示旧批次，修复后4组目标（含POST/DELETE、旧200/401与新busy、清单延迟、XHR迟到）通过；类型/构建、全前端443/443通过。独立复核原P2已修复、未发现新增问题，审查员另跑上传文件53/53。模拟浏览器实际history.back与延迟HTTP回执验证仍停总览，旧批次GET1/POST1无迟到读回。临时服务/脚本/标签清理；真实账号/浏览器BFCache平台未以模拟替代，同版交付见外部validation。
