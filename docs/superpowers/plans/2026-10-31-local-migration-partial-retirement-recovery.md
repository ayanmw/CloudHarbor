# 本地目录迁移部分清理恢复计划

实现位置：原主 checkout 内联；不建 worktree、不提交、不访问真实百度账号/NAS。

1. 先写集成回归：部分删除后目标树改变时，重试必须失败且保留残余源；观察旧实现错误完成（RED）。
2. 在迁移阶段追加事件证据中持久保存 verified target digest，保持与阶段 checkpoint 同事务提交；复用现有追加事件表，不改 schema。
3. 实现规范化目录树 SHA-256；在 `source_retired` 核验成功后把摘要与 `deleting_source` 检查点一事务提交。
4. 清理前重算目标摘要并验证隔离残余是目标的同身份子集；无摘要旧记录失败关闭。加入部分 RemoveAll 故障注入，验证未变目标可重试、目标变化保留残余。
5. 回退复制目标的 `Sync`/`Close` 失败时保留经过校验的 `.part`；重试只有在目标残片是其严格前缀时才能恢复。分别注入同步和关闭失败，先确认旧行为无法恢复，再验证重试得到完整目标。
6. 恢复活动迁移前校验持久目标是否与当前 `.env`/启动参数显式锁定路径冲突；冲突时记录失败并保留隔离源。先验证旧逻辑会继续删除，再验证本地和监控目录冲突拒绝、匹配配置允许恢复。
7. 允许用户在有效队列与本地路径值未变化、仍勾选迁移时重试匹配的失败迁移；复用 SQLite 记录的原源/目标及迁移 ID，普通同路径保存保持无操作。以失败清理记录验证原实现无操作、修复后能完成恢复。
8. 运行迁移专项、taskstore 专项、全仓 Go 测试和 vet；更新未编号路线图候选事项 5/5。
9. 达到发布门槛后执行 WebUI/userscript、全仓 Go 测试/vet、Windows AMD64/Linux AMD64/Linux ARM64 构建及包内校验，生成 `.115` preview；任何失败都修复并更新同一个版本。

成功标准：目标与持久摘要不一致时永不清除隔离源；部分删除且目标保持原摘要时可恢复完成；跨重启记录完整。验证边界为本机 SQLite/文件系统模拟，不代表 SMB/NAS 实机语义。
