# 自动监控请求退避实施计划

> **执行方式：** 主目录内联实施；保留现有 dirty/untracked 文件，不创建 worktree、不提交/推送。

**目标：** 自动监控目录列表失败时尊重 provider 重试时间，并跨重启安全退避。

**架构：** SQLite v41 使用按账号隔离的当前退避状态表，与 append-only 扫描运行历史分开。Downloader 在真实扫描开始前门禁，在列表失败后写退避，列表成功后清除。健康 API/UI 仅呈现绝对 UTC 和等待秒数。

**技术栈：** Go、SQLite、现有 `/api/health`、嵌入式 WebUI、Node `node:test`。

**Spec：** `docs/superpowers/specs/2026-11-02-queue-monitor-retry-backoff.zh-CN.md`

## 约束与审查重点

- 不重试远端写操作；不改变其它扫描器。
- Retry-After 最大 1 小时；本地指数退避最大 15 分钟。
- 历史失败不能伪造重试截止；迁移不回填旧数据。
- 账号切换不能读取或清除其他账号的重试状态。
- 冷却时不创建 run 或请求百度；写入截止和 run 失败若跨事务中断，采用保守冷却，不产生额外请求。
