# 全盘扫描分页重叠身份保护

## 已确认问题

全盘扫描按百度列表 API 的 offset 分页。目录在两次请求之间发生排序变化时，同一 `fs_id` 可能再次出现在后续页。此前 Store 会把后页对象写入同一缓存行，并可能把目录标记为 complete；扫描页时间仍会使它看起来是一次成功完整观察。

## 行为要求

- 仅对同一账号、同一运行、同一直接父目录中较早已提交的页做跨页重叠核对。
- 发现重复 `fs_id` 时拒绝当前页事务，不覆盖既有缓存，不推进 offset 或完成目录。
- 同页重复 ID 的历史 `UpsertCloudInventoryPage` last-row-wins 行为保持兼容；生产 API 的单页去重校验独立存在。
- 在调用方必须重新开始/重试前，该目录保持未完成状态，不作为完整缓存或重复文件候选依据。

## 验收

先写回归：第一页保存 fs_id，第二页重复该 ID 且路径/大小不同；第二页应失败，数据库保留第一页记录，目录状态不是 complete。无重复的正常多页扫描和原有同页直接 upsert 测试继续通过。
