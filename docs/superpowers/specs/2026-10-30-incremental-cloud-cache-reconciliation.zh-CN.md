# 增量网盘缓存核对与提交

## 意图

让全盘/目录缓存刷新期间仍可浏览最近一次完整缓存，并只在某个目录的实时列表确实变化后更新该目录的正式缓存。完整扫描得到的 SHA-256 可继续用于重复文件实时分组；远端操作回执与本地缓存冲突时，以刚取得的百度线上结果为准，并单独记录、修正本地缓存。

## 当前行为与问题

- `UpsertCloudInventoryRefreshPage` 逐页把远端结果写入正式 `cloud_inventory`，并逐页把目录标记为 `scanning`。
- 刷新目录状态变为不完整后，重复候选查询和重复组列表会排除这些目录，导致长时间刷新期间已有缓存虽可读却不能用于重复预览。
- `cloud_content_hashes` 已按文件身份、大小和 provider mtime 绑定 SHA-256；正式 inventory 的文件身份未变化时可复用，变化时应失效。
- 已确认远端操作会事务性更新本地缓存；如果本地对象身份与操作前记录不一致，会拒绝写缓存，留下远端已确认而本地未修正的差异。

## 目标

- 每目录刷新页先持久化到隔离的暂存区，目录最后一页成功后再在一个 SQLite 事务中对比与发布。
- 暂存期间正式目录状态、旧列表和已验证哈希可继续读取；暂停、失败或重启不会暴露半份新列表。
- 若 provider 列表与旧缓存完全一致，保留 inventory 行和 SHA-256，仅刷新目录观测时间；若内容变化，原子更新当前目录项、移除云端已不存在项，并仅使身份/内容变化文件对应的 hash 失效。
- 刷新按目录增量提交：尚未刷新的子目录继续提供上次完整缓存；父目录确认子目录已删除时，按远端结果删除该子树缓存和 hash。
- 远端操作已 confirmed 时，以操作后重新核验到的线上对象身份和位置为准修正本地 inventory；远端确认不存在的对象从缓存和 hash 表移除。修复/失效事件留有 SQLite 时间证据，不把缓存更新失败伪装成 provider unknown。
- SQLite 暂存数据和刷新检查点跨进程重启恢复；账户隔离、目录边界、单次列表分页及现有刷新节流保持不变。

## 非目标

- 不改变百度 API 请求频率、全盘缓存调度策略或重复扫描的 hash 下载策略。
- 不在本批对真实网盘执行写操作、扫描、删除或开启用户真实账号；不自动删除远端重复文件。
- 不保证暂存期间缓存反映最新云端状态；UI继续标示正式缓存的观测时间。暂存内容只在目录完整读取后生效。
- 不用 size/mtime 以外的字段伪造内容 hash；只有原文件身份及内容元数据匹配时才复用 SHA-256。

## 方案与取舍

1. **继续逐页原地更新正式缓存**：改动小，但目录会在刷新期间不完整，重复预览停用，失败时可能留下部分新内容。
2. **每目录持久暂存，完成后比较并原子发布（采用）**：以 SQLite staging 表保存远端分页结果；完整目录列表是提交边界。刷新期间读取旧正式缓存；完成时事务性核对新增、变化、删除项与 hash。实现和数据库迁移较多，但满足可用性、重启恢复与 hash 复用要求。
3. **整次全盘复制后全局切换**：一致性边界更大，但需要复制/保留整库，空间和恢复成本高，也会让整轮扫描期间所有本地结果保持旧版本，不符合按目录变化更新的目标。

## 行为规则

- 目录在刷新期间保持原有 `status`、`observed_at_utc` 和正式行；进度仅在刷新任务状态展示。
- 每页实时 API 成功后，仅提交暂存行、下一页 offset、页面计数与队列检查点。
- 最后一页提交时比较规范化的 `(fs_id,path,name,is_dir,size,provider_mtime,content_md5)`。完全相同时只更新已完成目录的观测时间并清空本目录暂存；目录列表变化时事务性替换差异并更新 generation。
- 文件 SHA-256 只有在 `fs_id,path,size,provider_mtime` 都保持匹配时保留；其他情况删除该 fs_id 的 hash。目录项删除导致子树消失时删除子树 hash。
- 已确认远端操作采用调用方传入的操作前/后对象证据与 `ResponseObservedAtUTC`。线上确认对象消失则删除本地行/hash；线上返回新身份则 upsert 并对内容变化失效 hash。无法从实时线上响应确认完整状态时，保留隔离/失效状态，不猜测。
- 目录刷新暂停、失败或进程重启，暂存结果保留并按检查点继续；用户显式开始新的刷新时清理由旧 run 不再引用的暂存数据。

## 验收

- Store/API 测试证明刷新中旧列表、完整状态、目录大小和已验证重复组仍可读。
- 多页目录测试证明暂存不泄漏；完整结束后一次提交新增/更新/删除项，刷新失败和重启时正式缓存保持旧值。
- 相同列表重复刷新不增加 generation，不丢失有效 hash；仅变更文件清除该文件 hash；删除项清除对应 hash；子目录独立刷新不干扰兄弟目录。
- confirmed 远端结果与旧缓存身份冲突时，缓存最终和真实 API 响应一致，事件保存旧/新身份及 UTC 时间；unknown/未确认不被当作 confirmed。
- 覆盖 SQLite 迁移和版本恢复；全仓测试、vet、WebUI、userscript、Windows AMD64/Linux AMD64/Linux ARM64 打包与 ZIP 检查通过。
- 本批只做模拟/本地测试，真实百度账号和远端写操作均不在验收范围。
