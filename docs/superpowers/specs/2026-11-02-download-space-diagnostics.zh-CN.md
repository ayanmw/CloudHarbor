# 下载空间诊断与恢复提示

## 意图

`.121` 已在容量不足、容量不可读和写入中磁盘满时，将本机路径、所需/可用/预留字节和容量检查 UTC 写入 `download_attempt_finished` SQLite 事件。当前任务列表只显示通用错误；任务事件页把结构化证据作为原始 JSON 折叠内容，用户需要自行识别字段含义才能判断是否可重试。

本批把同一组本地证据保存到失败任务快照，并在任务列表和事件时间线中提供中文诊断与恢复提示，避免把本机容量检查时间误认为百度观测时间。

## 五项用户结果

1. **失败任务详情可跨重启读取。** 下载失败时在持久化队列任务中保存可选的 `local_storage` 摘要；旧任务没有该字段时继续正常读取。成功、非空间错误、用户重试和新尝试清除旧摘要。
2. **三个空间故障类型一眼可辨。** 分别显示容量不足、无法读取容量、写入时磁盘满；用户可看到目标本地路径及 required/available/reserved 字节，并同时看到易读容量值。
3. **未知数据与时间不伪造。** `available_bytes < 0` 显示“无法读取”，不显示负字节数；展示 `checked_at_utc` 时标注本机空间核对时间 UTC，不给它贴百度/云端时间标签。
4. **两个任务页面一致且安全。** 轮询任务页与 WebSocket 任务页使用同一渲染帮助函数；路径、消息和时间按普通文本转义，点击已有手动重试入口仍由用户明确触发。
5. **事件历史具备专用诊断卡片。** 空间失败事件显示中文结论、容量和本机核对时间；保留原始结构化证据折叠区及现有导出，通用/provider 事件时间标签不变。

## 方案与取舍

1. **只把原始事件 JSON 展开。** 无 API/任务模型改动，但需要用户理解字段，且任务行仍只有通用错误。本方案不选。
2. **任务列表再请求最近事件。** 可复用事件数据，但会为分页列表增加 N+1 请求、额外轮询负担及迟到响应状态。本方案不选。
3. **把已存在的本地容量摘要随任务快照持久化并共用前端渲染。** `queueJob` 是已有任务状态的权威来源；增加可选 JSON 字段不需要 SQLite schema 迁移，也不发起新请求。任务页直接读取该字段，事件页以事件证据使用相同渲染逻辑。采用此方案。

## 限制与非目标

- 摘要只表示应用最近一次本机空间查询；外部进程可能随后占用空间。预检不能保证之后写入成功。
- `reserved_bytes` 是当时本 Downloader 统计的活动 reservation，不是整个卷的全局锁，也不代表其他进程/设备用量。
- 不新增自动重试、自动清理、空间回收、百度 API 调用、管理员配置或 SQLite schema 迁移。
- 不改写入失败分类或 attempt event 的时间字段；远端错误维持原呈现。

## 验收

- Go 回归确认队列 JSON 读回 local_storage 摘要、旧 JSON 无该字段兼容、手动重试/成功或非空间失败不遗留过期摘要。
- WebUI 回归确认任务轮询页和 WebSocket 页正确渲染三种分类、字节值、路径、未知容量与本机 UTC；HTML 类字符串不得被执行。
- 事件时间线将空间诊断时间标为本机本地检查 UTC，provider/云端时间保持各自字段语义；原始 JSON 折叠和证据导出不丢字段。
- 页面仍只在用户点击时发送现有 retry 请求；空间详情渲染不调用百度 API。
- `.122` 全仓 Go 测试、vet、WebUI/userscript、三平台构建、ZIP/SHA-256、源码快照和私有运行数据校验通过后交付。
