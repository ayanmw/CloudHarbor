# 远端操作事件时间线 UTC 日期筛选与导出

## 目标

远端操作可能经过多次重试、恢复和结果核对，单笔事件时间线会逐渐增长。管理员需要在已有状态筛选基础上按 UTC 日期定位事件，并将当前筛选后的事件证据下载留存。

## 本版范围

- 每个操作详情的事件筛选增加 UTC 起始日和结束日；开始日包含 00:00:00Z，结束日包含整日（SQLite 使用次日 00:00:00Z 的排除边界）。与状态筛选、sequence 游标和 operation ID 组合。
- 清除筛选同时清空状态和日期；应用筛选从最新匹配事件开始；更早事件页保持相同条件。
- 新增受保护的只读事件导出接口，导出操作摘要及当前状态/UTC 日期范围命中的事件，使用同一 SQLite 只读事务快照、稳定序列顺序、现有递归脱敏和 100 条事件上限。超过上限拒绝整份。
- 现有“导出全部证据”入口和接口语义保持不变。

## 不在范围内

- 不搜索 evidence JSON 文本，不新增 SQLite schema、事件写入或云端请求。
- 不增加确认、重发、放行、修改或删除操作。
- 结果未知继续隔离；不改变事件、不自动证明云端操作完成。

## 实现取舍

- 复用 `recorded_at_utc` 纳秒列及 `sequence` 游标，不增加时间索引/缓存；查询仍被 operation ID 限定，状态/日期谓词只缩小候选。这样避免维护新状态并保留现有追加日志排序。
- 日期控件明确标记 UTC 日历日期，避免浏览器时区隐式换算。API 严格解析单一日期参数，拒绝重复、非法、逆序或 SQLite 纳秒可表示范围之外的日期。
- 导出与在线分页共享同一个 Store 过滤模型；导出使用单一只读事务，100 条上限在过滤后计算。

## 验收

- Store：状态与 UTC 日期边界组合、包含开始日/结束整日、sequence 游标、跨 operation ID 隔离、空结果、无效范围、导出快照及过滤后 100 条上限。
- API：重复/非法/逆序/越界日期返回 400；未知 ID 404；成功下载含 UTC 导出时间并进行敏感字段递归脱敏，响应 no-store；超限整份 413。
- 页面：UTC 日期筛选应用后重置分页、旧页继承全部条件、清除恢复全部；只在点击后下载当前过滤证据；切换条件后迟到响应不能污染事件视图。读取失败时仍保留筛选和重试控件。
- 全仓 Go 测试/vet、WebUI/userscript、Windows AMD64/Linux AMD64/Linux ARM64 构建、ZIP 校验和私有数据排除通过。
