# 目录缓存刷新运行历史

## 目的

`.87` 已将刷新生命周期和逐目录发布事件持久写入 SQLite，但网盘管理页只从“当前刷新状态”取得 run ID。新一轮刷新覆盖该状态后，旧事件仍留在数据库中，却没有网页入口可查。本功能让用户在本机浏览历次刷新运行，并点选某一轮查看其既有事件。

## 范围

- 增加只读 SQLite 运行列表，按启动事件的全局序号从新到旧稳定分页；每项展示启动 UTC、最新事件类型/状态/阶段/目录及进度快照。
- 增加经过管理认证的 runs API。账号指纹只从授权上下文读取，不接受客户端指定；响应不暴露指纹。
- 网页用户点击后读取最近 20 轮，支持加载更早运行；选择某一轮后复用 `.87` 事件 API 查看该轮事件，并继续按事件序号加载更早事件。
- 运行列表和时间线仅读取本机 SQLite，不触发百度 API 请求或任务状态变化。
- 为账号/事件类型/序号增加索引，schema 从 19 迁移到 20；迁移不得伪造旧运行。只有已有 `started` 事件的运行才会出现在列表中。

## 不做

- 不访问或修改百度网盘，不重放事件，也不提供删除历史入口。
- 不添加运行状态过滤、日期筛选、导出或保留期清理。
- 不改变现有单次运行事件 API 和刷新执行/续跑语义。

## 行为与稳定性

- `start_sequence` 是每轮启动事件的不可变全局序号，并作为运行列表游标；新开或恢复旧运行都不会改变它，因此分页边界不会被顶部新增运行推动。
- 运行摘要中的当前最新事件可以随恢复而变化，但其分页位置保持固定；这属于实时历史，不承诺跨页冻结的数据库快照。
- 每轮最新事件通过账号/run_id 和序号索引读取。查询结果严格按授权账号隔离，限制单页最多 100 轮。
- SQLite 19→20 迁移只建索引；manifest 落后恢复、重复打开与已存在索引均保持幂等。
- 事件起始时间来自本机时钟。沿用 `.87` 对本机事件记录时间和本机完整读取百度目录列表的 UTC 时间的区分；不将观测时间描述成百度服务器时间。

## 验收

- Store 覆盖跨 run 排序、稳定启动游标、每轮最新状态、账号隔离、关闭重开和 19→20/manifest 恢复。
- API 覆盖账号上下文、参数和页大小边界、游标分页、错误响应与不暴露账号指纹。
- WebUI 覆盖默认不请求、点击取运行列表、选择旧 run 后查询对应事件、两个层级的加载更早、转义路径与异步响应过期保护。
- 发布验证覆盖全仓 Go 测试/vet、WebUI/userscript、Windows/Linux AMD64/Linux ARM64 构建及 ZIP/源码快照/私有运行数据检查。
- 只做本地 SQLite 和模拟环境；不访问真实账号或 NAS/SMB。
