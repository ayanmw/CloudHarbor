# 百度网盘只读请求限流与恢复可靠性

## 目标

降低目录浏览和缓存扫描期间的突发只读请求，并使限流错误后的扫描等待在进程重启后仍保持一致。所有远端写操作的确认、unknown 隔离和不自动重放语义保持不变。

## 当前确认的问题

1. `Client.get` 承载文件元数据、下载链接和账号信息读取，但共享节流只放在目录列表方法中，导致其他只读 API 绕过节流。
2. 全盘扫描和局部目录刷新只在内存中保存指数退避时长；SQLite 检查点没有下一次重试 UTC 时间，重启会将等待重置为 5 秒。
3. HTTP `Retry-After` 响应头未被保留，扫描无法尊重服务端明确给出的等待时间。

## 设计

- 将可取消共享 pacing 移至 `Client.get`，覆盖所有通过统一 metadata HTTP 客户端发出的只读 API GET。原始文件内容下载不走此 helper，避免将大文件传输节流误当作 API 请求间隔。
- 在 `APIError` 中携带经过解析的 `Retry-After` 截止时间；只接受合法秒数或 HTTP 日期，负值/非法值忽略。退避采用本地指数时长与服务端要求的等待时间中较大者，并受 1 小时上限保护。
- SQLite 扫描检查点保存 `retry_delay_millis` 与可空 `retry_at_utc`（Unix 微秒）。全盘扫描和局部刷新均在每次退避前先持久化这两个值；重启恢复时，若截止时间仍在未来则先等待，已过期则立即继续。取消时保留原截止时间，不清除错误证据。
- 成功发布一个目录页后清空该目录的重试字段并把退避恢复到基础值；新一轮扫描初始化为空重试字段。字段与扫描状态在同一事务更新。
- 状态接口和管理页显示 UTC 重试截止时间及退避时长，区分本机记录时刻与远端观测时间。

## 不在范围

- 不改变写操作重试或 unknown 策略。
- 不引入后台并行重试、请求速率配置 UI、跨不同进程实例的全局限流或原始下载带宽限制。
- 不把百度账号、NAS/SMB 的真实验收替换成本地测试结论。

## 验收标准

- 同一个带 pacer 的 Client，其目录、元数据、下载链接和账号只读请求均调用共享 pacer；取消等待时不发 HTTP 请求；下载文件流不调用该 API pacer。
- 解析秒数与 HTTP 日期两种 `Retry-After`；非法值忽略；应用服务端下限并遵守上限。
- 全盘扫描与局部刷新在 SQLite 重开后精确恢复退避时长和 UTC 截止时间；未来截止时间不提前请求，过期截止时间不额外等待；成功页清理重试状态。
- schema 22→23 原子迁移保留既有队列、缓存、事件和运行证据；迁移失败关闭打开，不回退到旧语义。
- 全仓 Go 测试、`go vet`、WebUI/userscript 回归、Windows/Linux AMD64/Linux ARM64 构建与 ZIP 哈希/私有数据检查通过。
- 不执行真实百度写操作；NAS/SMB 验收单独保留。

## 发布批次计数

1. 为所有 metadata GET 应用共享 pacer。
2. 解析并遵从服务端 `Retry-After`。
3. 全盘扫描跨重启保存退避时长与 UTC 截止时间。
4. 局部目录刷新跨重启保存退避时长与 UTC 截止时间。
5. 暂停后重新启动/恢复扫描时保留原错误原因和重试计划；成功发布页后才清除已恢复的暂时错误和重试计划，避免等待期间丢失故障证据或完成后继续显示旧故障。
6. 在扫描状态与网页中呈现可审计的重试等待信息（UTC 截止时间与剩余毫秒），不把本机等待时间误标为云端时间。

以上为同一只读 API 恢复主题中的五个独立交付项；实际实现若发现其中一项只是同一根因的重复表述，将继续审查并替换，不以条目数量降低验收质量。
