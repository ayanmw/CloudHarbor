# 已确认网盘变更与待执行队列身份同步

## 意图

用户在网盘管理页改名、移动或删除一个尚未开始下载的队列项目后，网页任务列表和持久化 SQLite 任务记录应继续对应同一个百度 `fs_id`，避免显示旧路径或把原任务重建成新任务。该补全直接落实网盘管理设计中“按 fs_id 更新待执行任务”的既有要求。

## 范围

- 改名/移动成功且随后取得目标对象信息时，只更新从未开始的 `pending` 或 `auth_wait` 任务。
- 对“后处理时发现身份变化”而失败的任务，后续成功完整列表再次观察到同一 `fs_id` 时，清除已解决的 `changed` 标记并恢复同一任务；保留下载模式和尝试历史。
- 仅因源项目离开监控目录且下载从未开始而失败的任务，在远端确认移回或后续成功列表重新观察到同一 `fs_id` 后更新路径并提示手动重试；不自动开始下载。
- 成功删除从未开始的任务时，将其标记为 `cancelled`，并保存专用事件。
- 每个变更事件关联远端操作 ID，保留本地记录时间、云端观测/响应时间和变更前后 `FileInfo`。
- 保留相同 fs_id 已有的下载模式、创建时间、尝试数和失败数。
- 对普通已尝试、终态、活动中或 source-operation `sending`/`unknown` 的任务，不重写记录；扫描到变化时不能用新 pending 任务覆盖原任务。`changed` 是已收到身份冲突回执、等待下一次成功列表重新确认的专用恢复状态；源缺失且零尝试任务移回监控目录后只恢复手动重试能力。
- 远端结果为 `unknown` 或 `failed` 时不更新队列任务；维持既有隔离语义。

## 不在范围

- 不自动重试远端操作，不解除隔离，不更改文件下载内容或已完成任务。
- 不增加 SQLite schema；复用任务 JSON 投影、追加事件和已有远端操作 journal。
- 不更改用户对队列外移动的语义：改动后的完整监控目录扫描仍决定其是否可执行；移出监控目录的 pending 任务会按既有源缺失规则失败，留在目录内的可继续执行。

## 安全条件

一般任务只有状态为 `pending`/`auth_wait`、`attempts == 0`、`failures == 0`、没有 source-operation 状态且没有活动 worker 时才可重基任务对象。`SourceState=changed` 且状态 `failed` 的任务只在成功队列扫描后恢复为 `pending`，不清零尝试/失败历史。因监控目录缺失而失败且零尝试的任务，可在同一 `fs_id` 重新进入监控目录时仅更新身份并保留 `failed` 状态，由用户手动重试。确认回执仍是远端事实，后续对象信息读取和队列目录列表分别记录其观测时间；二者不能被伪装成同一时间。任何持久化失败都停止调度并保留已有 SQLite 事务语义。

## 验收

1. rename/move 按 fs_id 更新安全任务的路径和元数据，保留任务模式及历史，并通过关联事件可追溯。
2. delete 将安全任务转成取消态，事件包含远端操作 ID 与 response-observed UTC。
3. 普通 retry/failed/done/source-unknown 等有历史任务即使扫描到同 fs_id 新身份也不会被重建或重置；`changed` 专用恢复只清除冲突标记并保留计数/模式；零尝试的源缺失任务回到监控目录后只允许手动重试。
4. unknown mutation 不改队列记录；远端调用仍至多一次。
5. Go 全量测试、vet、WebUI/userscript、Windows/Linux AMD64/Linux ARM64 发布包校验通过；新 preview 只在完成门禁后产生。
