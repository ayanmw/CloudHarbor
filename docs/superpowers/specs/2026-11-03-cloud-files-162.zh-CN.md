# .162 网盘文件工作台

用户已授权按最佳推荐持续实施。当前.161测试包冻结，沿原目录内联，无worktree/自动提交或push。下一步将常用网盘文件管理整合到Vue工作台，避免旧cloud页面中浏览、扫描与大量证据控件混杂。

方案：独立`/cloud/files`复用现有API和管理认证，完成主要浏览与文件操作后引导常用导航进入；保留`/cloud`高级扫描/去重/缓存历史，明确链接，不删既有能力。相比一次替换全部扫描和文件操作，本版边界是完整文件浏览管理，后端迁移/队列协调算法保持。不是只读浏览替代用户的文件管理目标。

本版五项交付：
1. 紧凑目录表格与固定导航，文件名、类型、大小、更新时间分列，父目录/面包屑/绝对路径可用，空目录仍有完整浏览容器；目录未知大小不显示0B。
2. 实时/本地缓存切换与缓存搜索，清楚展示来源、覆盖范围与更新时间，不把缓存无结果当远端不存在。目录大小复用本地缓存统计，提供明确刷新入口，不自动触发全盘扫描。
3. 路径、来源、查询与分页URL恢复；按后端分页边界变化信号回到可核对页面。读取失败标记历史，取消/迟到/401单在途，精确fs_id不经Number。
4. 文件操作确认：新建目录、重命名、移动、删除均复用`/api/cloud/mutations`及已有身份前置；固定对象/路径/目标确认，缓存模式不得拿旧身份直接执行写操作，必要时在线预核对。未知不重发，旧队列暂停/更新/恢复仍由后端负责。
5. 操作结果与浏览协调：受理/完成/失败/未知分开，绑定operation_id；每项成功刷新相关目录，后台操作反馈可收起并继续浏览，链接只读操作历史。按已有接口能力实现批量操作，不添加无依据的批量远端协议。

已核实`/api/cloud`默认100项分页，后端对重复分页/漂移重核并返回边界证据；缓存浏览/搜索、目录统计、mutations及operations已存在，实施前需逐项核实DTO/枚举。兼容精确字符串格式按实际需要最小增加，不改旧默认或SQLite架构。默认扫描至完成，不添加猜测的百度每日配额；只有确定限流响应/可复现限制才降频。

验证用本机合成数据与mock，无真实账号写操作/凭据复制或真实目录迁移。每项TDD，一个最终fresh-context审查，桌面390px键盘、完整Go/vet/前端/旧页/脚本/三平台/ZIP快照门禁，五项一起完成后发布.162。
