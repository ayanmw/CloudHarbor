# 网盘缓存覆盖不完整原因分布

## 目标

当全盘扫描历史状态为 `complete`、但当前缓存覆盖为 `incomplete` 时，管理页除总数外，展示可解释的本地缓存原因分布，帮助决定是否需要用户主动启动扫描或局部刷新。

## 范围与约束

- 同一 SQLite 只读事务返回扫描检查点、覆盖总览和原因分布，确保都来自同一数据库快照。
- 仅统计当前已绑定账号；接口不返回账号指纹或逐目录私密路径。
- 返回目录状态行中的 `scanning`、`stale`、`unknown`、`failed` 数量。
- 返回缓存结构问题计数：有缓存目录项但缺少目录状态行、状态表有目录但缓存项缺失、父目录不完整的缓存子项数、缓存路径与父目录/名称不一致的条目数、根目录未完整。
- 明确父目录和路径异常两类数值以缓存子项/条目计，不是目录数；根目录计数为 0 或 1。
- 结构类别按各自 SQL 条件计数，类别之间允许重叠；不得把这些数字相加当作去重总数。
- 状态读取只访问 SQLite，不触发百度 API、自动扫描或目录刷新。
- 管理页在原有运行/覆盖状态下方展示各原因数量；状态读取失败时继续明确显示不可读，不用旧细分数据冒充当前数据。

## 验收结果（5 项）

1. API 在现有 `inventory_coverage` 中返回目录状态分布及结构问题计数。
2. 所有计数限定为当前授权账号，并能覆盖不存在状态行/缓存项等边界。
3. 原总覆盖状态与计数语义保持不变，扫描运行 `complete` 可以同时对应当前 `incomplete`。
4. 页面展示每个原因类别及数量，且清楚说明结构类别可重叠。
5. API/UI 状态读取不调用百度列表接口；数据库读取错误失败关闭并保留“上次成功”边界。
