# 局部缓存刷新完成后的浏览上下文一致性

## 背景

网盘管理页会每两秒读取目录缓存刷新状态。当前检测到由本页启动的刷新完成后，无条件调用 `browse()` 和目录大小读取。若用户已切换到实时百度列表，这会额外发起一次百度 GET；若用户已切换到无关路径，也会重读并重绘无关视图。局部缓存刷新只发布所选目录及其子树，完成通知应按此范围处理。

## 目标

刷新运行完成后，仅更新受该次刷新影响的本地缓存浏览视图；保留当前导航上下文，避免意外请求百度或覆盖用户正在浏览的无关目录。

## 决策

- 将本页发起/恢复的刷新 `run_id` 与其 `root_path` 一起保存在页面状态中；仅匹配当前运行 ID 的完成响应可触发收尾。
- 仅当当前数据源为本地缓存且当前目录等于刷新根目录或位于其子树时，自动从第一页重读缓存并更新目录大小。
- 当前为本地缓存搜索时，若刷新根目录可能影响搜索结果，则保留搜索词、回到第一页并重读本地搜索。
- 当前为实时百度视图或不相关的缓存目录时，不调用 `browse()` 或大小 API，不改变路径、模式、页码和现有列表。
- 恢复上次刷新时使用服务端返回的 `root_path` 绑定范围。刷新状态读取失败、仍在运行、暂停或失败都不触发完成收尾。

## 验收标准

1. 当前浏览受影响缓存目录时，刷新完成会更新列表和目录大小。
2. 当前缓存搜索可能受刷新范围影响时，搜索词保留、页码回到第一页并更新结果。
3. 当前为实时列表时，刷新完成不额外调用 `/api/cloud`，也不更改实时列表和导航。
4. 当前缓存目录不在刷新根目录内时，不重读或改写该目录的列表、页码和大小。
5. 恢复流程绑定服务器报告的刷新根目录；过期、失败和非完成状态不触发缓存浏览刷新。

本变更只控制本地页面收尾行为，不修改百度远端操作、刷新调度、缓存事务或隔离策略。
