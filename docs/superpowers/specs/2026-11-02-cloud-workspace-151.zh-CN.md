# .151 网盘管理交互完善设计

## 范围与版本边界

.150 已交付下载工作台及网盘浏览、统计和扫描节奏修正，继续保留为用户当前运行版。.151 集中交付以下五项可独立验收的能力，不拆成五个预览版本；五项均完成并通过发布门禁后才创建测试包。

1. 浏览位置可恢复：URL 保存目录、列表来源、缓存搜索、分页；刷新及浏览器前进/后退恢复相同浏览条件。
2. 属性面板：选择文件/目录查看列表快照中的路径、大小、身份和时间；明确实时/缓存来源，不将旧快照当作操作凭据。
3. 页面内操作对话框：新建、改名、删除使用统一可访问表单，保留输入和错误反馈；移动沿用现有目标选择器。结果不确定时引导操作历史核对，不提供盲目重发。
4. 可缩小的扫描进度面板：复用既有状态轮询，在网盘管理各分区持续显示后台全盘/局部刷新进度和暂停/继续入口，不增加一套轮询。
5. 明确扫描次数控制：默认“扫描至完成”，高级模式才填写本工具请求次数上限；恢复有限扫描可显式切换无限，旧 API 的 request_budget=0 语义保持兼容，变更原子保存并有事件证据。

## 实现选择

延续现有管理页与共享主题，先补足交互；不为本轮更换全部框架或重写远端操作协议。URL 使用浏览器 History API；仅 sessionStorage 会丢失可复制地址及前进/后退语义。浏览历史只包含明确的浏览参数，不含授权或管理密钥。

新交互脚本按职责放在 internal/webui/res，保留既有列表 API、分页边界核对、缓存 generation、远端身份核对及 SQLite 隔离机制。API 新增显式次数模式，而不将旧 request_budget=0 重新解释为“清空上限”，避免旧调用悄悄扩大扫描范围。

## 验收与不变量

- URL 恢复只发只读请求；不从地址启动扫描或执行远端操作。未知参数不透传给 API，异常目录/来源/分页安全回退。
- 前进/后退不新增历史项；内部边界回锚、缓存 generation 恢复替换当前历史项，避免产生循环导航。
- 列表迟到响应不覆盖新路径；离开目录后旧属性面板不能继续执行操作。
- 属性的时间是列表观察/提供方时间，来源明确；缺失信息显示未记录，不伪造过去。
- 写操作仍由现有后端实时核对并暂停/恢复下载队列。账号、隔离、删除确认与未知结果边界不变。
- 后台进度只显示已观察计数，不将未知总量伪造成百分比；收起面板不暂停后台任务。
- 显式 unlimited 切换保留 RequestsUsed 和原事件，新的总次数状态与恢复事件同事务保存；重启恢复一致。旧请求不改变语义。
- 全盘/目录扫描正常页没有额外固定 1 秒等待；共享 250ms 请求调度和错误退避保持本版基线，不根据假定的百度 QPS 降频。

## 验证边界

每项覆盖实际构建/完整页面交互及相关 Go/SQLite 行为。最终执行全仓测试、vet、前端、userscript、三平台构建、载荷校验和桌面/窄屏实屏。真实账号只读浏览可验证 UI；本轮不以真实账号删除、移动或压力扫描作为自动验收，不宣称 NAS/SMB 验收。

用户状态继续只保留一份，默认留在 .150；.151 测试包不包含授权和任务数据库。没有另建 worktree、自动 push 或删除旧 release 的计划。
