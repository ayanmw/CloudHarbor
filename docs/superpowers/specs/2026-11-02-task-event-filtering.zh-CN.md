# 下载任务事件筛选与证据导出

## 意图

长时间运行的下载任务会积累扫描、下载尝试、重试、暂停、授权和源项处理事件。现有逐任务时间线支持稳定分页及完整证据导出，但只能浏览全部事件；用户定位某次失败需要逐页查找，且导出不能限定到相关事件。

## 目标

1. 每个任务事件面板可按固定事件类型筛选。
2. 可按 UTC 日历日期范围筛选，范围只作用于本机 `recorded_at_utc`；提供方发生、云端观察、HTTP 响应观察及未来重试时间继续独立展示。
3. API 返回当前过滤器匹配的总数和稳定序列分页；过滤、总数和页面数据从同一 SQLite 只读快照读取。
4. UI 在翻页、返回较新事件和手动刷新时保留过滤条件；修改条件后回到最新匹配页并清除旧游标。
5. 显式导出当前过滤结果；同一 SQLite 快照内最多 100 条，超过上限整份拒绝，敏感证据遮蔽规则不变。

## 非目标

- 不增加全局跨任务搜索、自动重试、状态修改、远端百度请求或数据库 schema 迁移。
- 不按其他时间字段筛选，也不把本机记录时间描述为云端发生时间。
- 不改变既有未筛选事件排序、分页上限 50、完整导出上限 100 及匿名拒绝行为。

## 方案与取舍

1. **只在浏览器已加载页内筛选。** 不需 API 改动，但无法得到完整命中数，翻页后会漏掉匹配项，导出仍不精确；不采用。
2. **新建跨任务事件搜索页。** 可做全局排查，但扩大查询范围、权限和索引设计，也重复任务列表；超出当前“查看一个任务”的既有流程；不采用。
3. **扩展现有单任务事件 API/面板并在 SQLite 只读事务中应用过滤。** 使用既有 `job_events(job_id,sequence)` 稳定分页和单任务边界，导出同一过滤器及上限；改动局部且证据一致，采用此方案。

## 行为和实现约束

- 事件类型必须来自源码中实际写入的固定白名单；空值表示全部类型，未知值拒绝为 HTTP 400。
- 日期采用 `YYYY-MM-DD` UTC 日历形式。开始日含当日 00:00:00，结束日含整日并转换为次日 UTC 00:00:00 的排除上界；反向范围拒绝。
- 数据库过滤字段为整型 `recorded_at_utc`。类型、日期条件、总数和当前页在同一只读事务中读取。
- 分页仍按不可变事件 `sequence` 降序取最近一页后正序展示；`before_sequence` 是排他上界。过滤改变后客户端回到最新页。
- API 的 `total_matches` 表示当前任务和过滤器下的全量匹配数，不等于当前页条数。不存在任务保持 404；存储不可读返回 503。
- JSON 导出包含导出 UTC、任务 ID、标准化过滤条件、匹配总数及所有匹配事件。匹配数大于 100 时返回 413，不截断、不导出部分数据；保留当前敏感字段遮蔽。
- UI 的路径、事件证据与错误文本继续转义；筛选和读取仅访问本地任务 SQLite API。

## 验收标准

- Store 回归覆盖事件类型白名单语义、日期开闭区间、组合条件、total_matches、稳定分页、空结果、不存在任务、重启后筛选可重复及同快照导出。
- API 回归覆盖 query 校验、默认兼容行为、401/404/413/503、过滤参数和总数，不触发百度 API。
- WebUI 回归覆盖初始全量、应用/清除筛选回到最新页、旧页迟到响应丢弃、筛选保留在较旧/较新分页、仅显式点击导出、超限提示和敏感内容不进入 UI。
- 全仓 Go 测试/vet、WebUI/userscript、Windows AMD64/Linux AMD64/Linux ARM64 发布包与载荷清单通过。

## 版本批次

计划作为 `.144` 的独立用户结果合并批次，至少计 5 项：类型筛选、UTC 日期筛选、匹配总数、筛选分页/刷新一致性、筛选结果同快照有界导出。只有实现和发布门禁通过后才标记交付。
