# 本地目录迁移部分清理恢复

## 问题

迁移进入 `deleting_source` 后，程序会重新核验隔离源目录与目标目录，再调用 `os.RemoveAll`。若 NAS/SMB 或本地文件系统只删除了隔离源的一部分就返回占用/IO 错误，重试时仅核验仍残留的项目；目标目录可能已在失败期间丢失了先前从隔离源删除的文件，程序却会继续清除剩余隔离源，导致唯一副本丢失。

## 设计

- 在追加式 SQLite 迁移阶段事件中持久保存已核验目标目录的规范化 SHA-256 树摘要。摘要按相对路径、目录/文件类型、文件长度及文件内容计算，路径使用相对路径字节，遍历顺序稳定；不包含本机绝对路径、时间戳或权限。
- 只有在源/隔离目录核验通过后才计算目标摘要，并与进入 `deleting_source` 的阶段检查点及事件在同一个 SQLite 更新事务提交。不改变 schema；旧活动检查点没有该证据时失败关闭。
- 每次清理隔离目录前，重新计算目标树摘要并要求与持久摘要相同；再确认隔离目录当前残余均为目标目录的匹配子集。部分删除后可安全重试，因为目标树仍须完全匹配原核验摘要。
- 目标变化或隔离目录出现目标中不存在/内容不同的项目时停止，保留所有剩余数据并记录失败。
- 旧数据库中已处于 `deleting_source`、但没有摘要的活动迁移失败关闭，不猜测历史完整性，不自动删除剩余隔离源。
- 既有迁移历史、任务和缓存数据保持不变；追加事件仍为只追加证据。

## 验收

1. RED/GREEN：模拟隔离目录部分删除失败，重启后目标未变时能够验证并清理剩余隔离源。
2. 目标在部分删除后丢失、增改文件时，重试拒绝删除隔离源，保留剩余唯一副本。
3. 缺少持久摘要的旧 `deleting_source` 检查点失败关闭，不执行 `RemoveAll`。
4. SQLite 重开后摘要和迁移阶段保持，迁移失败/事务回滚不产生半更新状态；本改动不增加 schema 版本。
5. 本批达到 5 项前不生成 preview；完成时再跑全仓测试、`go vet`、WebUI/userscript 和三平台构建。全程不访问真实网盘账号或 NAS。

## 同批次补充：回退复制同步失败后的恢复

在不支持硬链接的文件系统上，迁移会把已校验的 `.part` 复制到独占目标文件。目标写入后的 `Sync` 或 `Close` 失败时，源文件仍在，但若程序删除 `.part` 并留下部分目标，重试就无法判断或修复这个残片，会持续报冲突。

- 若临时副本已核验、复制本身成功，而目标同步或关闭失败，保留 `.part` 和目标残片作为恢复所需的本地证据。
- 重试仍要求残片是 `.part` 内容的严格前缀；只有通过该校验才移除残片并重新发布完整文件。非前缀冲突维持失败关闭。
- 若复制本身失败且本次独占创建的目标可清理，移除该目标与临时文件，源文件继续作为完整副本；若目标因占用无法移除，保留已校验 `.part`，以便重试用严格前缀核验修复。
- 回归分别注入目标同步错误和关闭错误，确认重试恢复完整目标；本机文件系统模拟不替代 NAS/SMB 实测。

## 同批次补充：重启后启动配置锁定路径变化

迁移记录在 SQLite 中跨重启保留。如果停机期间用户修改 `.env`，将本地下载目录或监控目录显式锁定到与迁移记录不同的位置，旧恢复逻辑仍会继续旧迁移，并可能清理旧源，尽管本次启动的有效配置不会使用该迁移目标。

- 恢复活动迁移前，比较记录的目标下载目录和监控目录与当前显式启动配置。
- 对不匹配的路径将迁移记录为失败并写入证据，不启动复制、改名或删除阶段；隔离源保留。
- 非显式启动配置不构成冲突；显式配置与迁移目标一致时允许继续恢复。
- 回归覆盖显式本地路径冲突以及监控路径冲突/匹配情况。

## 同批次补充：路径未变化时重试失败迁移

启动配置与迁移目标冲突时，恢复会安全失败并保留隔离源。用户之后修正配置后，如果有效路径本身已等于迁移目标，原路径设置 API 会将同路径提交当作无操作，导致不能从网页重试保留的失败迁移。

- 用户在页面选择“迁移文件”并提交与当前生效设置相同的路径时，若最近一条失败迁移的目标监控路径和本地目标都匹配该提交，则复用原迁移 ID 重试。
- 普通同路径保存仍保持无操作；成功迁移不会被重复执行；来源、目标或队列路径不匹配时不复用历史迁移。
- 回归确认失败记录、相同路径提交、迁移 ID 复用和隔离源最终清理。
