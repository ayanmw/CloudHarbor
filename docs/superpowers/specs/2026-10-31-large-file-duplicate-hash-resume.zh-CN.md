# 大文件重复内容哈希断点恢复设计

## 背景

当前重复内容扫描对一个候选文件从头请求下载链接并流式 SHA-256。`processed_bytes` 仅在整文件完成后增加；单文件网络中断、点击暂停或进程重启，会丢弃该文件已读取的数据。约 120 GiB 的候选扫描中，单个大文件失败会造成明显的重复流量和长时间无可见进度。

## 目标与五项可验收结果

1. 扫描状态显示当前文件路径、已读取字节和文件总字节；总进度由已完成文件字节加当前文件字节组成，始终不超过总量。
2. SHA-256 内部状态与当前文件身份、Range 偏移在 SQLite 同一行原子持久化；进程重启后可还原哈希状态并续读。
3. 网络暂时失败进入既有退避后，从最后已持久化的字节偏移继续；每读取 16 MiB 提交一次检查点，暂停/读错误时立即提交本次读到的状态。
4. Range 恢复响应必须通过已有 `206 Content-Range` 完整后缀校验；若 provider 忽略 Range，则丢弃检查点并从零重算。开始、续算和最终入库都必须匹配 fs_id、路径、名称、大小、mtime 及可用 MD5。
5. 文件流 HTTP 错误解析 `Retry-After`，复用重复扫描已有的退避上限和 SQLite UTC 截止；成功完成文件时，SHA-256 入库、完成进度和清除活动检查点在同一 SQLite 事务提交。

## 边界

- 不改云端文件，不改变预览/删除流程；哈希扫描只发 GET。
- 新增 SQLite schema 24，现有账号绑定、扫描记录、缓存、已验证哈希和管理员会话必须保留。
- SHA-256 状态不可用、文件身份变化、Content-Range 错误或偏移/长度不一致时失败关闭；不把部分哈希写入已验证哈希表。
- 检查点每 16 MiB 写入 SQLite；强杀进程时最多重读上一个检查点之后的数据。暂停与可观察的网络读错误会先保存当前偏移。
- 暂不把 provider 的 Range 能力当作所有错误的可重试保证；仅在正确响应 Range 后续读，Range 被忽略时安全重算。
- 本地模拟不能证明百度下载节点的 Range、断连行为或 NAS/SMB 网络质量。

## 数据与执行流程

`cloud_duplicate_scan_state` 增加活动文件身份、当前字节偏移和 SHA-256 二进制状态列。二进制哈希状态不包含在 JSON API 或事件证据中。启动候选哈希时先在线核验身份，再将初始空 SHA 状态和偏移 0 持久化。每次 Range 响应验证后读取数据，按 16 MiB 间隔保存 offset/hash state，并更新可见字节进度。暂停或错误时保存最后实际读取状态。恢复时从 SQLite 还原状态、获取新的下载链接并请求 `bytes=<offset>-`。完成后重新读取线上身份，再由一个 SQLite 事务保存 SHA-256、推进已完成文件/字节计数并清空活动检查点。

若当前缓存候选与持久化活动身份不一致，旧检查点先被丢弃，之后按新的候选从头开始。只有完整读取到声明大小且前后身份一致的内容才可进入重复组。

## 验收

- taskstore 测试覆盖 schema 23→24、已有数据迁移、活动检查点跨 Store 关闭/重开一致、哈希状态不出现在 JSON/事件证据，以及完整哈希提交与活动检查点清理的原子性。
- baiduapi 测试覆盖下载错误中的 Retry-After 秒数/日期，Range 状态与 Content-Range 仍严格校验。
- downloader 测试覆盖分块续算 SHA-256 与完整内容一致、网络错误退避后 offset 不归零、暂停重开不读取已检查点前缀、Range 忽略回零、MD5/元数据漂移拒绝旧 SHA、取消期间检查点保留。
- WebUI 测试覆盖当前文件路径、当前文件字节、已完成字节和总字节的展示及转义。
- 发布门禁：全仓 Go 测试/vet、WebUI/userscript、Windows AMD64/Linux AMD64/Linux ARM64 构建、ZIP/哈希/源码快照检查。真实账号只读启动可验收；不得对真实云端执行写入或启动大规模哈希扫描。
