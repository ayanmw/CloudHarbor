## v0.8.30-preview.141：全盘扫描覆盖历史筛选

### 目标

扫描历史已有完成时覆盖状态、未完整目录数和原因快照，但列表只能按扫描运行状态与开始日期查找。增加本机 SQLite 历史筛选，帮助定位扫描当时的覆盖结果；不把当前缓存状态套用到历史运行。

### 用户可见结果（5 项）

1. 按完成时覆盖状态筛选：完整、不完整、扫描中/未知、历史未记录。
2. 按完成时未完整目录数的最小值、最大值筛选；旧运行无快照时不匹配数值范围。
3. 按一个结构原因类别筛选，条件为该快照计数大于零；原因计数可重叠。
4. “覆盖快照未记录”和“覆盖原因未记录”分开筛选：前者匹配 v36 及更早 NULL 覆盖状态记录，后者匹配已有覆盖快照但没有原因 JSON 的历史（例如 v37 记录）。
5. 新筛选与现有运行状态/UTC 日期筛选组合，翻页保留条件；清除条件后回到第一页。

### 方案与边界

- 延展现有 `CloudScanRunFilter`、Store SQL、扫描历史 API 和页面筛选表单，不新增 schema、索引、路由或远端请求。
- 覆盖状态允许 `recorded` 状态码与 `unrecorded` 虚拟筛选值；缺省表示全部。
- 最小/最大目录数允许 0..1,000,000，最小值不能大于最大值；过滤要求历史快照字段非 NULL。
- 原因允许 9 个已定义字段之一；匹配 SQLite JSON 计数大于 0，只对已有原因快照的运行生效。
- 所有查询继续按稳定 sequence 游标分页。筛选只在本页内存保留，与既有日期/运行状态一样。
- 公共响应仍用历史 DTO；过滤条件不包含账号标识或敏感信息。

### 验收

taskstore 覆盖有效组合、零边界、legacy NULL 排除、原因筛选与稳定分页；API 覆盖非法状态/原因/数值/重复或倒置范围；WebUI 覆盖条件序列化、清除与分页保持。然后运行全仓 Go/vet、WebUI/userscript、三平台构建和 preview ZIP 校验。只读本地 SQLite，不触发百度请求或远端操作。
