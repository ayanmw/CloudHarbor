# 本地目录迁移事件时间线设计

## 意图

在迁移历史中展开任一条记录后直接查看其阶段变化和 UTC 证据，方便先在页面诊断迁移过程；需要保存完整证据时仍可使用现有 JSON 下载。

## 目标与范围

- 新增管理员 GET `/api/settings/local-migrations/{id}/events?before_sequence=&limit=`，严格限定所选迁移 ID。
- 事件按 `sequence DESC` 分页，每页默认 20、最多 50；下一页游标是当前页最小 sequence。查询、记录存在性和事件读取在一个只读 SQLite 快照中。
- 返回事件的 sequence、status、phase、recorded_at_utc 和 evidence；API 对 evidence 递归遮蔽 token/secret/password/authorization/app-key 类敏感字段。
- 页面每条摘要提供“查看事件”按钮；展开时加载第一页，可继续加载更早事件；切换记录或新请求后，旧响应不得覆盖当前记录时间线。
- 未知迁移 ID 返回 404；非法 ID、负数游标、无效或超限 limit 返回 400；内部错误返回中文通用信息且不泄漏错误内容。
- 不改原始证据，不提供恢复、重试、删除或本地/远端文件操作。

## 方案比较

1. **按 ID 的 SQLite 只读事件分页（采用）**：页面按需加载有限事件，维持稳定序列游标并复用已有脱敏；单条导出继续给出完整受限证据文件。
2. **前端调用完整证据导出并解析**：会把附件流程变成页面请求，最多 100 事件限制也无法逐页浏览，不采用。
3. **列表响应内嵌所有事件**：使分页摘要变成无界响应，且每次刷新都读取事件，不采用。

## 验收

- Store 覆盖 ID 隔离、最新事件、向前分页、同一 SQLite 快照、空事件与关闭/未知记录。
- API 覆盖游标/页长验证、ID 404、敏感字段递归遮蔽、UTC、no-store、内部错误隐藏和不调用云端。
- WebUI 覆盖按需加载、继续读取更早事件、XSS 转义、切换记录时旧响应忽略。
- 全仓 Go 测试、vet、WebUI/userscript、三平台构建及 ZIP 检查通过。
