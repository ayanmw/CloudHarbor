# 下载队列暂停与恢复

## 目的

提供网页可用的全局下载队列暂停/恢复控制，方便用户临时停止本机下载并继续查看、扫描网盘。暂停是持久控制状态，重启后继续保持；监控扫描和队列对账仍照常进行，暂停期间只是不领取新的下载任务。

## 五项用户结果

1. **暂停状态跨重启保存。** SQLite 应用设置记录 `paused` 与最近一次用户切换的 UTC 时间；旧设置没有队列暂停字段时默认为未暂停。
2. **暂停采用排空语义。** 提交暂停后不再领取新任务，已经开始的任务继续完成或按既有错误策略结束，不强行中断文件写入/Range partial。
3. **暂停时监控继续工作。** 定时/手动扫描照常把新网盘项目登记为 pending；不因用户暂停而误报源缺失、跳过对账或产生远端操作。
4. **控制 API 清楚处理冲突。** 管理认证保护暂停/恢复入口；重复设置同一状态幂等；维护、服务停止或队列持久化故障不能被恢复入口绕过。维护门禁独立于用户暂停，结束维护不得清除用户暂停。
5. **两个任务页提供一致的可见控制。** Poll 与 WebSocket 页面展示当前暂停状态、修改时间和按钮；按钮只在点击后发送控制请求，返回结果以服务端持久状态为准。

## 方案

- 将 `queue_paused` 和 `queue_pause_updated_at_utc` 放入现有 SQLite 应用设置 JSON，不增加 schema migration。
- 在 scheduler 上增加独立 `userPaused` 状态；`claimAt` 同时检查 user pause 与 maintenance。设置前持有 scheduler 锁并先保存设置，写库失败时内存状态不改变；恢复时也先持久化再唤醒 worker。
- startup 从 SQLite 设置恢复；缺字段按 false 处理。正常扫描和 `reconcileObserved` 不检查此值，确保队列仍能记录新项目。
- 加入受管理认证保护的 `POST /api/queue/pause`、`POST /api/queue/resume`；任务状态接口返回 pause flag、UTC 时间与当前 active 计数。
- 页面不自动暂停当前下载，也不杀 worker。按钮状态更新需使用接口响应或下一轮任务状态读回。

## 非目标与限制

- 不逐任务暂停，不取消正在下载的任务，不清理或移动本地/网盘文件。
- 用户暂停期间，运行中的下载可能需要较长时间才能排空；页面应清楚说明其继续运行。
- SQLite 写入失败时控制操作失败，不能只显示暂停/恢复成功。
- 不影响认证续期、网盘扫描、缓存刷新、手动远端操作或已有维护门禁。

## 验收

- Go 回归：设置 JSON 持久化/重启恢复/旧数据兼容；写入失败不改变内存状态；claim 在 pause 与 maintenance 的交叉组合下行为正确；暂停时 reconciliation 仍新增 pending 项；resume 不解除 maintenance。
- HTTP/WebSocket 回归：需要管理认证；状态包含暂停时间与活动数；重复设置返回稳定状态；维护/队列故障不能通过 resume 清除。
- UI 回归：两种任务页都显示服务端状态和排空说明；控制仅由明确点击发起；失败保留最后已知状态并展示错误。
- 发布门禁：Go 全仓测试/vet、WebUI/userscript、Windows AMD64/Linux AMD64/Linux ARM64、ZIP 与源码快照验证。
