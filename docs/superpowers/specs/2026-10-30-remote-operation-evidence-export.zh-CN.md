# 单条远端操作脱敏证据导出设计

## 目标

在只读远端操作历史中，允许管理员导出单笔操作摘要及其完整追加事件，便于留存核对时间线和请求结果证据。当前页面可以逐页查看证据，但无法一次保存。

## 约束

- 仅读取当前下载目录对应的本地 SQLite，不访问百度 API，不修改队列、云端或缓存。
- 导出的摘要与事件必须来自同一个只读 SQLite 事务快照；不得分页拼接不同时间点的数据。
- JSON 只包含单笔操作的摘要和事件，不包含账号指纹、Cookie 或会话数据。
- `evidence` 使用事件 API 相同的递归敏感键遮蔽规则；原始敏感值不能进入响应、日志或下载名。
- 事件数设置明确上限，超过上限时拒绝整个导出，不返回部分时间线。
- unknown 操作仍仅供审计，不增加重发、放行、删除或继续操作入口。

## 建议接口与交互

- 新增受管理认证保护的只读 `GET /api/cloud/operations/{id}/export`。
- 响应为 JSON attachment，包含 `exported_at_utc`、操作摘要、按序号升序排列的 `events` 和事件数；文件名只使用稳定操作 ID 的安全字符。
- 历史条目增加“导出此操作证据”按钮；同源 fetch 检查错误，成功后保存 Blob，失败写入历史区错误栏。
- 不改变既有列表、分页和逐页事件查看接口。

## 验收标准

- Store 回归验证同一只读事务返回摘要及完整排序事件；无事件操作、缺失操作、超限和取消上下文均有明确结果。
- API 回归验证 GET-only、attachment、事件排序、递归敏感字段遮蔽、无 fingerprint/evidence 原值泄露及 provider 零调用。
- WebUI 回归验证精确操作 ID URL、独立导出按钮、错误反馈和 unknown 状态没有写操作入口。
- 全仓 Go 测试、vet、WebUI/userscript 与三平台打包门禁通过；真实账号只进行受保护 GET。

## 上限决策

每条操作事件的 evidence 写入限制为 64 KiB，事件本身可追加增长。每笔完整导出最多 100 条事件，最坏 evidence 载荷约 6.25 MiB，另加有限 JSON 元数据；Store 查询第 101 条用于检测超限。超过上限时拒绝整个下载并提示继续在页面逐页查看，不静默截断。
