# 网盘本地缓存浏览设计

## 意图

在网盘管理页增加本地 SQLite 清单浏览模式，让用户查看已扫描缓存的目录和文件，减少重复打开目录时的百度 API 请求。用户必须能识别当前数据来自实时网盘还是本地缓存，以及缓存覆盖状态和最近云端观测时间。

## `.56` 实施前基线

- `GET /api/cloud?dir=...` 每次调用百度实时列目录，并返回实时对象信息；现有远端改名、移动、删除按钮都使用这份实时列表。
- `GET /api/cloud-inventory?dir=...` 已从 SQLite 返回目录的缓存条目、页码、总数和目录元数据 `status` / `observed_at_utc`。目录状态可为 `complete`、`stale`、`scanning`，或者没有缓存记录。
- `GET /api/cloud-inventory/size?dir=...` 已本地聚合缓存大小，并返回覆盖完整性、最近云端观测时间和本地计算时间。
- 实施前，缓存列表中的目录行没有附带聚合大小；本变更为目录行增加本地聚合值及覆盖完整性。
- 全盘与目录局部扫描会逐步更新 SQLite；缓存列表在部分扫描时可能保留旧条目，因此仅显示条目数量不能证明目录为空或完整。

## 目标

- 在目录浏览区明确选择“实时网盘”或“本地缓存”，默认保持现有实时模式。
- 缓存模式只访问本地库存 API，不因缓存不存在、过期或不完整而静默请求百度实时列表。
- 缓存模式展示该目录覆盖状态及云端观测时间；无记录、stale、scanning、complete 使用清楚且不同的状态文案。
- 缓存模式允许分页、进入已有缓存条目指向的子目录，并继续使用已有本地目录大小接口。
- 缓存列表应在同一页直接展示每个目录的本地聚合大小和覆盖完整性；复用 generation-scoped SQLite 大小缓存，不能逐目录请求百度 API。
- 缓存模式为只读；改名、移动、删除等远端写操作隐藏或禁用。用户切回实时模式后可使用现有操作。
- 当前目录刷新控件继续对所选路径执行局部远端刷新；任务完成后按当前选择的数据源重新加载列表和大小。
- 浏览页保持可用，切换来源时重置分页位置，状态和空列表不会误导成远端实时结果。

## 非目标

- 不改变全盘或局部扫描策略、限速、SQLite schema、路由或分页语义；缓存列表条目只增加可选的目录聚合大小字段。
- 不自动回退、合并或覆盖实时列表与缓存列表。
- 不允许缓存模式直接执行网盘写操作或作为删除空目录/重复内容的候选依据。
- 不改变 API/CLI 权限，不新增后台周期任务。

## 方案比较与本轮默认选择

1. **显式切换实时/缓存（默认选择）**：页面清楚显示数据来源，缓存模式只读并展示状态/观测时间。浏览多一步，但数据边界最清楚，也不会因为缓存缺失而悄悄增加 API 请求。
2. **缓存优先，缺失时自动回退实时**：操作少一步，但缓存命中与回退可能让相同页面操作请求百度；用户难以判断列表是否实时，缓存不完整时也容易把部分列表误认为远端空目录。
3. **始终只用本地缓存**：API 调用最少，但已有用户无法通过浏览立即看到缓存未覆盖的目录，也改变当前实时浏览语义，故不采用。

此默认方案根据连续版本推进目标及当前源码边界作出；用户审阅时可调整。

## 缓存目录大小展示的实现选择

1. **扩展现有缓存列表响应（采用）**：在每页目录条目上附带本地聚合字节数和覆盖完整性，复用 SQLite 代次大小缓存。浏览仍只进行一次分页 API 请求，且没有对网盘的读请求；列表 UI 直接显示结果。仅扩大现有响应字段。
2. **浏览器逐目录调用大小接口**：无需改列表响应，但每页最多触发 100 次本地 HTTP 请求，列表加载更慢且产生许多重复请求。
3. **列表不显示大小，继续逐项点击**：实现范围最小，但无法满足全盘缓存后在目录列表中直接查看所有目录大小的需求。

按当前持续推进授权采用方案 1；缺失或失效覆盖仍显示“不完整”，不可把其当成准确总大小。`directory_size_bytes` 与 `directory_size_complete` 只用于缓存目录行，不替换 `size`/provider identity。

## 交互与状态语义

- 实时模式：保持现有 `/api/cloud` 行为、实时条目和远端管理按钮。
- 缓存模式：请求 `/api/cloud-inventory`，顶部显示“本地缓存”标签、目录状态和观测时间；显示条目总数与 SQLite 分页结果。
- `complete` 表示该目录列表在标示的云端观测时间完整，不代表之后没有变化。
- `stale` / `scanning` 表示条目仅供参考且当前覆盖不完整；允许查看，但必须显眼提示。
- 缺失元数据表示本地尚无该目录清单，显示“无缓存记录”，不显示“此目录为空”；用户可切回实时模式或启动当前目录局部刷新。
- 缓存模式内不可执行远端改名、移动和删除。打开目录仅能进入缓存中已记录的目录项；目录缺少缓存记录时仍展示无记录状态。
- 缓存模式目录条目提供 `directory_size_bytes` 和 `directory_size_complete`。大小在本地根据 SQLite 库存计算或命中 generation-scoped 大小缓存；不完整覆盖可以显示暂算字节值，但必须同时明确标记不完整。文件条目的 `size` 和远端写操作身份字段含义不变。
- 切换来源时重置 offset 并重新载入当前路径；返回实时模式后继续由实时列表产生写操作身份信息。

## 验收

- API/Store 回归验证 complete、stale、scanning、无缓存记录及分页数据语义；空目录只在 `complete` 状态下显示为空。
- Store/WebUI 回归验证缓存目录行显示本地聚合大小，stale 子树保留字节值但显示不完整，文件大小与目录大小字段分离；列表操作不访问实时百度目录接口。
- WebUI 脚本测试验证默认实时模式、来源切换后的请求地址/offset、缓存状态/观测时间显示、缓存只读以及缺失缓存不触发实时回退。
- 现有实时浏览、远端 CRUD、目录大小刷新和全盘/局部扫描回归保持通过。
- `.56` 预览包须满足至少一项新功能的版本门槛，完成 Go 测试、`go vet`、WebUI/userscript 检查、三平台构建和包内私有数据检查。
- 本地缓存测试不替代百度真实账号或 NAS/SMB 环境验收；真实验证只读浏览和缓存状态，不对用户文件执行远端写操作。

## 已采纳并完成

- 已采用显式切换、缓存只读、缺失时不回退实时。
- 缓存模式显示 stale/scanning 中已有条目并醒目标记不完整；不将其用于任何远端写操作。
- 已在 `.56` 实现缓存列表目录行大小，复用现有 generation-scoped SQLite 大小缓存；未新增配置或 schema。Store 与 WebUI 回归、全仓测试与发布包验证记录见 `docs/ai/progress.md`。
