# 监控目录切换影响预览与确认

## 意图

切换自动监控目录前，让管理员看到旧监控目录中可能因此失去调度资格的未执行队列任务，并明确确认后才保存路径。任务身份、状态和历史仍由 SQLite 队列记录负责；新目录的后续成功扫描仍是云端存在性证据。

## 已确认决策

- 采用路线 A：切换前列出受影响任务，用户确认后继续。
- 在下载任务运行、目录扫描运行或入队操作未完成时，保持现有拒绝规则。
- 不提前把队列任务标记为缺失。路径保存后，下一次成功扫描仍按现有规则将新目录中不可见的 `pending`、`auth_wait`、`retry_wait` 任务记为 `failed/source_missing` 并写入扫描观测时间。
- 保留已失败任务和事件；切回旧目录并成功扫描后，仍由既有身份/状态规则决定是否可手动重试，绝不自动重发远端操作或下载。

## 范围

- 为监控路径变更提供只读影响预览，列出当前监控路径内、切换到目标路径后不会作为目标目录直接子项被扫描的 `pending`、`auth_wait`、`retry_wait` 根任务。
- 预览包含来源监控目录、目标目录、任务 fs_id、路径、名称、状态及有限计数，并带可重算的内容指纹。
- 网页显示任务明细和影响说明；无受影响任务时可直接保存，有受影响任务时需针对当前预览显式确认。
- 影响明细按稳定 fs_id 排序并以每页最多 50 条读取；总数和指纹覆盖完整快照，翻页不改变确认内容，避免大队列通过单个 HTTP 响应和 DOM 一次性展开。
- 保存前在路径维护门禁内重新计算影响指纹。若队列或目标发生变化，拒绝本次保存并返回新的预览，要求用户重新确认。
- 新目录成功扫描后将任务标记为源缺失时，事件证据保存当次 `monitored_queue_dir` 和云端观测时间，明确这是相对于哪个监控路径未发现，不推断为网盘全局不存在。
- 取消确认不修改路径、SQLite 设置或队列；路径配置仍按已有原子设置方式立即生效并跨重启保留。

## 不在范围

- 不保留旧目录的后台监控，不迁移云端文件，不自动重建或删除任务。
- 不将远端新目录扫描结果预先当成完整或原子快照；预览只描述本机队列记录与路径关系。
- 不改动本地下载目录迁移行为，不对真实百度账号/NAS 作验收。
- 不新增 SQLite schema；预览指纹只用于检测确认期间的本机队列变化，不是认证凭证或远端身份凭据。

## 验收

1. 影响列表稳定排序，覆盖三类状态，并只列出切换后不会直接出现在目标目录列表中的根任务。
2. 空影响列表无需二次确认；有影响任务时无确认/错误确认不会改路径。
3. 确认期间任务状态、身份或影响集合变化时保存被拒绝，并返回最新影响列表；用户再次确认后才保存。
4. 取消、服务端拒绝和路径保存失败都保持原路径；成功后运行时及重启读回目标路径。
5. UI 说明源缺失失败发生在之后的成功监控扫描中，并提供受影响任务清单；不显示为已完成的远端核验。
6. 大于一页时 API 仅返回当前页，分页总数与排序稳定，所有页共享相同完整快照指纹；翻页请求过期时不能覆盖新目标的预览。
7. 源缺失事件包含产生该判断的监控路径、扫描 epoch 与云端观测 UTC；事件不生成远端响应时间或全局删除结论。
8. 全仓 Go 测试/vet、WebUI/userscript、三平台构建及 `.117` ZIP/源码快照/私有运行数据检查通过后才交付。
