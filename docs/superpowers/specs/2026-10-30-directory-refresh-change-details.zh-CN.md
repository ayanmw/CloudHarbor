# 目录刷新变更明细设计

## 目的

`.92` 已在完整旧缓存的目录刷新事件中记录新增、移除和元数据变化的数量。用户还需要知道具体是哪条缓存对象变化，以便核对远端目录与本机 SQLite 缓存，且能区分百度列表观测时间和本机记录时间。本版本为每个完整发布的目录保存精简前后快照，并允许在刷新历史中按需查看。

## 分类规则

- **新增**：当前完整清单存在、旧完整直系缓存不存在的 `fs_id`。
- **删除**：旧完整直系缓存存在、当前完整清单不存在的 `fs_id`。
- **元数据变化**：两边 `fs_id` 相同，path、name、目录类型、size、provider mtime 或 content MD5 有变化。保存旧/新快照。
- **身份变化**：旧/新 `fs_id` 不同，但完整 path 相同，且该 path 在本次被移除与新增项中各自唯一匹配。保存一条包含旧/新对象的明细。若同一路径存在歧义，则分别记录新增和删除，不擅自配对。
- `.92` 已有数量语义保持不变：身份变化仍贡献一个新增和一个删除；元数据变化计入变化数。
- 刷新前目录缓存必须为 `complete` 才保存明细。基线未知时数量和明细均未知/不存在；完整基线且无变化时明细列表为空。

## 持久化与证据

- SQLite schema 21→22 新增 `cloud_inventory_refresh_changes`。每条明细绑定账号、run、父 `directory_published` event sequence 和稳定变化序号；表内保存类型、旧/新紧凑 JSON 快照、本机 event recorded UTC、百度目录 listing observed UTC。
- 快照包含 fs_id、path、name、对象类型、大小、provider mtime、content MD5、该身份/元数据仍匹配时可证明的本地 SHA-256 及其验证 UTC。绝不把失配或过期哈希标成有效。
- 目录缓存发布、计数事件与全部变更明细在同一 SQLite 事务中提交。事件或明细插入失败时，目录库存、刷新状态、事件和明细全部回滚。
- 变更明细只追加；SQLite 更新/删除 trigger 拒绝修改。无需为历史记录虚构快照，迁移前事件的明细自然为空。
- 不设置自动清理期限。仅对实测到的目录差异生成行；空变化目录不生成明细。

## 查询与网页

- 受保护只读 API 按账号、run ID、父事件 sequence 读取明细，稳定分页，每页最多 50 条；返回本机记录 UTC 与云端观测 UTC，不返回账号指纹。
- 刷新时间线对已有完整基线且数量非零的 `directory_published` 事件显示“查看变更明细”。用户点击后才请求；可展开旧/新对象快照和 SHA-256 证据，分页独立于运行和事件游标。路径、名字、哈希等远端文本必须转义。
- 事件类型筛选可继续作为时间线导航。完整运行 JSON 导出保持现有格式及边界，不隐式拼入可能很大的明细集合；明细在页面/API分页读取。
- 空明细、未知基线、读取错误、切换运行后的迟到响应均明确处理；改变类型或父事件时重置明细页并忽略旧响应。

## 非目标与风险

- 不请求百度文件详情、不触发刷新、不修改远端对象、不改变任务队列。
- 完整目录发生大量变化时，明细表会增长并增加发布事务写入。每个变化只写一行紧凑快照；页面按需分页，不一次性加载全量详情。暂不增加采样或截断，避免显示不完整记录却误导用户。
- 本地/mock 验证不能替代真实账号、百度限流、NAS/SMB 耐久与浏览器验收。

## 验收

- Store 覆盖新增、删除、同 fs_id 元数据变化、同路径身份变化、歧义路径不配对、未知基线、零变化、缓存哈希匹配/失配证据及账号/run/event 隔离。
- 游标只翻阅对应父事件明细；schema 21→22 保留旧事件；manifest 落后恢复；append-only trigger 生效。
- 注入变更明细插入失败，确认目录缓存发布、刷新 checkpoint、summary event 和明细一起回滚。
- API 拒绝非法/重复参数，不泄露账号指纹；UI 点击加载、稳定分页、转义、切换筛选/运行后迟到响应忽略；完整运行导出不变。
- 全仓 Go 测试/vet、WebUI/userscript、Windows AMD64/Linux AMD64/Linux ARM64 打包、ZIP 载荷/来源快照/私有数据检查通过；不访问真实百度账号或 NAS/SMB。
