# 远端操作历史摘要导出设计

## 意图

让管理员可将当前筛选条件下的远端操作摘要保存为 JSON 文件，供离线留档和对照。当前网页支持检索与逐笔查看事件，但历史仍只存在本地 SQLite 中；更换运行目录或出现数据库故障时，管理员可能需要独立保留一份摘要。

## 目标

- 在远端操作历史页添加“导出筛选摘要”入口，导出当前 status/query/from/to 条件命中的操作摘要。
- JSON 包含导出 UTC 时间、规范化后的筛选条件、匹配记录总数和操作摘要；摘要字段与列表一致，不包含 account fingerprint 或事件 evidence。
- Store 在 SQLite 单个只读事务快照内取得总数和有界记录，确保同一文件内的查询结果一致。
- 每次最多导出 5,000 条；超限时拒绝整个导出，不截断、不生成部分文件，并提示缩小筛选范围。
- 导出只使用本地 SQLite；不会请求百度 API、更新本地状态或执行云端操作。

## 非目标

- 不导出事件 evidence；用户仍可在历史页逐笔查看 `.59` 已有的脱敏事件详情。
- 不新增日志上传、云端备份、自动排程或服务端文件留存。
- 不支持 CSV/Excel，不添加外部依赖，不改变 SQLite schema。
- 不提供修改、重发、unknown 放行或历史删除。

## 方案比较

1. **服务端 SQLite 只读事务快照后返回 JSON（采用）**：一次请求内使用相同筛选和稳定排序；先计数并拒绝超限，再读取结果。响应可通过浏览器直接下载，数据不经第三方。
2. **浏览器逐页请求后拼装 JSON**：无需新增数据库层接口，但多个请求之间可能新增/更新记录，导致导出跨越不同时间点；客户端还需保存整个结果集，故不采用。
3. **只导出当前已显示页**：限制明显，容易被误认成完整筛选结果，故不采用。

## 设计

- 新增受现有管理认证保护的 `GET /api/cloud/operations/export`，接受 `.60` 相同的 `status`、`q`、`from`、`to` 参数。
- 新增 Store 导出方法：验证现有过滤器，在当前 store 锁下启动单一只读事务；在事务内先统计匹配行数，若超过 5,000 返回固定超限错误，再按 `created_at_utc DESC, operation_id DESC` 读取摘要并提交/回滚。
- JSON 结构为 `exported_at_utc`、筛选器、`total`、`operations`。结果不包括 evidence 或账号指纹。响应设置 `Content-Disposition: attachment` 和 `Cache-Control: no-store`。
- 页面使用当前筛选发起同源认证 GET，读取附件响应后下载 Blob；服务端错误显示在历史区错误提示，成功时显示下载文件名。unknown 继续显示只读隔离状态。
- 导出数量基于事务快照；采用固定上限限制响应大小和事务持有时间。过滤器仍遵守 128 字符及 RFC3339 校验。

## 验收标准

- Store 测试证明 count 与摘要来自同一筛选；状态/关键字/UTC 时间条件正确；超过 5,000 条时无部分结果；context 取消/closed store 报错且不改数据库。
- API 测试验证 GET-only、筛选参数复用、JSON/下载头、超限 413、未泄露 account fingerprint，且不调用任何 provider/list/mutation。
- WebUI 测试验证导出 URL 包含当前筛选、不带分页参数、不触发其他接口；unknown 记录没有操作入口。
- 全仓 Go 测试、`go vet ./...`、WebUI/userscript 和三平台包门禁通过。
- 真实账号只用受保护 GET 验证导出记录数与当前筛选一致；不执行远端写入。

## 实现选择

- 导出上限固定为 5,000；错误提示要求先用关键字、状态或时间范围缩小结果。
- 使用 JSON 而非 CSV，避免公式注入与 CSV 转义歧义；导出摘要不含证据 JSON，逐条 evidence 仍在现有只读详情页内查看。
- 文件名使用 UTC 导出时间生成，不包含用户路径或百度账号标识。
