# 全盘扫描完成后刷新不完整目录清单

## 背景

`.136` 已让已打开的不完整目录清单在本页局部刷新完成和远端操作响应后更新。全盘扫描同样会改变 SQLite 覆盖状态，但清单当前不会因扫描完成自动更新，用户仍需手动刷新记录。

## 目标

当页面观察到一轮全盘扫描运行并完成，且不完整目录清单已加载时，自动从本地 SQLite 重新读取清单。处理应支持扫描由另一标签页启动或恢复的情况，不把历史 `complete` 或暂停/失败状态当作本轮完成。

## 决策

- 以服务端 `run_id` 关联运行与完成状态；只处理页面已观察到处于 `running` 的同一轮 `complete`。
- 页面初次状态读取时已是历史 `complete`，不触发清单重读。
- 同一 run 只处理一次；后续两秒轮询不重复读取。暂停状态不完成收尾，恢复后再次观察到运行则继续跟踪；失败不触发收尾。
- 已加载清单时按当前筛选从第一页重新查询，清理旧游标和 generation；未加载时不产生请求。
- 不增加百度请求、服务端接口、SQLite schema 或后台轮询。

## 验收标准

1. 页面从 `running` 观察到同 `run_id` 的 `complete` 后更新已加载清单。
2. 首次状态已为旧 `complete` 时不更新。
3. 一轮完成即使后续被轮询多次也最多发一次清单请求。
4. `paused`、`failed` 不触发完成更新；恢复后的实际 `complete` 可以更新。
5. 本页与其他标签页开始的扫描遵循同一完成规则。
6. 更新保留筛选、回第一页，清单请求仅使用 SQLite API；未加载清单不发请求。
