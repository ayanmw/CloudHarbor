# 重复文件扫描运行历史与证据

## 目标

重复文件扫描目前把每次状态变化追加到 SQLite 事件表，但网页只按账号读取一条混合时间线；新扫描会覆盖当前状态，旧 run 缺少可发现的摘要入口，不能按 run 查看事件或导出单轮完整证据。本变更为每轮扫描建立可跨重启读取的历史摘要，并提供按轮查询、筛选与导出。

## 当前源码证据

- `cloud_duplicate_scan_state` 每账号只保留一个当前检查点；新扫描会替换该行。
- `cloud_duplicate_scan_events` 按账号追加 `run_id/status/phase/recorded_at_utc/evidence_json`，但只有状态转换时写入，详细 SHA-256 流检查点不会进入事件。
- `CloudDuplicateScanEventPage` 仅按账号和 sequence 分页；页面可以看到事件上的 run ID，却不能先列出历史运行、筛选或选中某轮后单独浏览。
- 全盘扫描与局部刷新已有 run 摘要、状态/UTC 日期筛选和有界单轮证据导出，可作为项目内部参考。

## 设计

新增 `cloud_duplicate_scan_runs` 可变摘要投影，账号/run 唯一，保存开始 sequence/time、最新 event sequence/status/phase、累计文件/字节进度、最新更新时间与错误摘要。新事件、状态 checkpoint 与摘要投影在同一 SQLite 事务提交；事件仍只记录关键状态转换，不为每个 hash/page 写无界事件。

schema 32→33 迁移从已有 append-only 事件按 run 分组，取最早记录作为开始证据、最新事件作为摘要基线。旧事件没有记录的字段保持默认/未知，不从后来当前状态推断过往进度；迁移时只允许当前账号当前 run 的 SQLite 检查点覆盖其对应摘要。迁移保留事件 sequence、索引和 append-only 触发器。

API 提供按账号分页的 run 列表，支持状态和 UTC 开始日期过滤；提供同一过滤条件下有界摘要 JSON 导出；事件查询和完整证据导出显式要求 run ID，证据从单个 SQLite 读事务取得并有上限，超限时整次拒绝。所有响应使用显式 DTO，不包含内部 `account_fingerprint` 或 SHA-256 流状态。

云管理页面按需加载历史 run，支持筛选、稳定分页、选中某轮后分页查看其事件，以及显式点击导出摘要/单轮完整证据。事件 JSON 使用现有 evidence 脱敏和 HTML 转义规则。历史仅读 SQLite，不调用百度 API；不会通过历史记录推断远端文件当前状态。

## 五项独立用户结果

1. 多轮重复扫描摘要跨进程重启保存；升级后历史事件可回填摘要，当前 run 与检查点一致。
2. 可按最新开始顺序稳定分页历史 run，并按状态及 UTC 开始日期筛选。
3. 当前筛选结果可显式导出有界摘要 JSON，导出记录过滤条件和导出 UTC 时间，不含账号指纹。
4. 可选定一个 run 分页查看其事件，避免不同轮次混在单一时间线上。
5. 可显式导出一轮完整有界事件证据；超限整次拒绝，不静默截断，导出不含内部账号指纹或 SHA 状态。

## 失败与兼容要求

- 事件插入、run 摘要更新或 checkpoint 写入任一失败时，本次状态事务整体回滚。
- 迁移要覆盖无事件/孤立事件、重复 run、旧证据字段缺失、Sequence 保持、索引/trigger 保持和 SQLite integrity。
- 无效状态/日期/sequence/run 查询参数返回客户端错误；跨账号查询不得返回其他账号结果。
- 页面迟到的旧 run/旧筛选响应不得覆盖当前选择；导出必须由用户点击触发。
- 当前 run 摘要按最新持久化 checkpoint 更新；已结束的历史 run 只使用其当时 append-only 事件能够证明的值。

## 非目标

- 不记录每个候选文件、每页或每个 HTTP 请求的独立事件。
- 不导出或恢复 SHA-256 中间流状态，不重启旧 run，不修改候选排序/重复认定/删除逻辑。
- 不依据旧扫描历史执行远端操作；不调用百度 API，不覆盖真实账号/NAS 验收。
