# 重复文件预览分页

## 意图

重复文件预览会把每组摘要、保留项和所有删除候选一次性渲染到页面。候选很多时，DOM 节点和按钮数量随文件数增长，用户难以逐组核对。本改动为预览列表提供分页浏览。

## 目标与非目标

- 每页显示 25 个重复组，并显示当前范围和总组数。
- 上一页/下一页仅切换当前渲染窗口，不发请求；翻页后回到上一页时保留 `.79` 中当前页面会话的保留项选择。
- 刷新预览时仍重新读取完整组列表并回到第一页，恢复服务端默认保留项。
- “删除预览中的全部多余文件”仍作用于全部已载入预览组，而非当前可见页；确认提示显示全量待删文件数。
- 不改 API、SQLite、扫描或远端删除语义；不声称缩小服务端响应/内存中的完整预览。

## 方案与取舍

1. **页面内分页（采用）**：完整预览继续保存在内存中，只渲染当前 25 组。保留批量删除所有预览结果和现有组内选择行为；不改变 API 合约。限制是服务端响应和浏览器内完整数据仍随重复组数量增长。
2. **API/SQLite 服务端分页**：减少单次响应和客户端数据，但完整批量删除必须额外遍历所有页，且要处理逐项删除导致结果集变化、用户分页内选择跨页持久化等问题；本版不扩展删除流程。
3. **虚拟列表**：可降低 DOM 数量但引入滚动窗口与焦点管理复杂度；对当前表格卡片式页面没有足够收益来抵消新机制。

## 约束与验收

- 每页固定最多 25 组，分页边界按组数而非文件数计算。
- 不改变 `duplicateGroups` 的完整数组；渲染范围只影响列表显示。重复删除计数及批量循环必须遍历完整数组。
- 翻页不得覆盖保留选择；刷新预览仍通过新响应替换完整数组并回到第一页。
- 空列表显示 0/0，无效或越界页码不得导致负索引或空白错误状态。
- 页面测试覆盖 0、25、26、51 组，上一页/下一页和翻页后 keeper 选择保留，以及完整候选总数仍参与批量删除。
- 不访问真实百度账号或执行删除；通过 UI mock 与全量发布门禁验收。

## 实现决定

采用完整数组加页面内 25 组渲染窗口。导航不请求服务端。继续保持全预览批量删除语义，避免当前页筛选造成不完整删除或被隐藏候选意外漏审。
