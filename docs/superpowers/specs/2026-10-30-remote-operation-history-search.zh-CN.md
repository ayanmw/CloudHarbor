# 远端操作历史检索设计

## 背景与意图

`.59` 已提供本地 SQLite 远端操作历史、状态筛选和分页。随着操作记录增长，仅逐页浏览难以定位某个网盘对象或某次操作。本批为历史列表增加本地检索与时间范围筛选，让管理员可按操作 ID、文件 ID、源路径或目标路径找到记录。

## 目标

- 在远端操作历史页按关键字、状态和创建时间范围筛选操作记录。
- 关键字按字面子串匹配 `operation_id`、十进制 `object_id`、`source_path`、`destination_path`。
- 时间筛选使用 RFC3339 时间戳，`from`/`to` 均为包含边界；网页的本地日期时间输入转换为 UTC 后发送。
- 查询在当前账号绑定的 SQLite store 内执行，保留稳定排序、页大小和 offset 上限。
- 不因查询访问百度 API，不更改操作、任务或缓存；unknown 仍隔离。
- 搜索词中的 `%`、`_` 和反斜杠按普通字符处理；输入长度最多 128 个 Unicode 字符。

## 非目标

- 不在云端搜索网盘当前文件，不补全历史表中本来没有的操作。
- 不增加历史导出、重发、人工放行或日志清理功能。
- 不增加 SQLite schema、索引或外部依赖；当前操作记录规模不证明需要 FTS/新索引。
- 不改变历史保留策略、操作证据或访问权限。

## 方案比较

1. **在现有 SQLite 查询中加入字面关键字与时间条件（采用）**：实现范围小，历史页保持单一数据源，无新增 API 请求或迁移；查询仍受分页上限约束。关键字对 SQLite `LIKE` 的 ASCII 字符按不区分大小写匹配，非 ASCII 字符按 SQLite 的原生匹配语义处理。
2. **调用百度网盘搜索接口**：只能查当前远端对象，不能完整检索已删除/改名对象的操作历史，还会受网络延迟与 API 限流影响，语义不匹配。
3. **只在浏览器筛选已加载页**：无法搜索尚未加载的历史页，容易让“无结果”被误解为全量无记录，故不采用。

## 设计

- Store 提供带筛选器的 `RemoteOperationPageFiltered` 查询；旧 `RemoteOperationPage` 保留为无关键字/时间范围的兼容包装。
- 所有筛选值通过 SQL 参数绑定。路径/ID 子串通过 `LIKE ... ESCAPE '\\'` 匹配，输入 `%`、`_`、反斜杠先转义为字面字符；开始和结束时间转换为 Unix 纳秒后与 SQLite 整数列比较。
- API 继续使用 `/api/cloud/operations`，新增可选 `q`、`from`、`to` 参数。日期解析失败、关键字超过 128 个字符、开始晚于结束时返回 400；响应结构不变。
- 页面增加关键字、起止本地时间和“搜索/清空”控件；点击搜索重置到第一页。时间控件以用户本地时区输入，并将标准 UTC RFC3339 值发送给 API。
- 历史列表和单笔详情仍遵守 `.59` 的字段脱敏与只读规则。查询失败只显示本地读取错误。

## 验收标准

- Store 测试验证按操作 ID、object ID、源/目标路径查找；`%`、`_`、反斜杠字面匹配；状态与时间边界组合；过滤后分页和稳定倒序；非法过滤器被拒绝。
- API 测试验证 q/from/to 校验、UTC 归一化和原有状态/分页组合；GET 外方法拒绝；不调用百度后端。
- WebUI 测试验证筛选参数转换、输入变化后第一页读取、清空恢复未过滤历史、XSS 转义、unknown 无操作控件。
- 全仓 Go 测试、`go vet ./...`、WebUI/userscript 测试及三平台发布包门禁通过。
- 不执行百度远端写操作；真实 `.59` 仅用 GET 验证筛选查询。

## 实现选择

- 查询词按 Unicode rune 数限制到 128；前后空白去除，纯空白等同未填写。
- 时间范围端点都包含；Web `datetime-local` 按本机时区解析，再格式化为 RFC3339 UTC。
- 不增索引。若操作历史规模增长到实测查询延迟不可接受，再以数据证据另行评估索引或全文检索。
