# 本地缓存全盘搜索设计

## 意图

在网盘管理页提供全盘缓存搜索，用户可以按文件名或完整网盘路径定位已扫描的文件和目录。全盘缓存已有 8,050 项且浏览以逐目录分页为主；逐层翻找大量目录耗时，缓存本身已可在本地完成搜索，不需要额外访问百度接口。

## 当前状态与范围

- `cloud_inventory` 已按账号隔离保存名称、路径、类型、大小和云端观测时间；目录浏览接口支持分页并附带本地聚合目录大小。
- 当前没有跨目录搜索 API 或 UI。
- 本变更只搜索本地 SQLite 库存；不查询百度搜索 API，不改变实时列目录行为，不新增 schema 或依赖。
- 搜索结果只读。每条结果提供其父目录路径；“实时查看所在目录”将来源切回实时并请求该父目录，以新鲜百度列表为远端操作依据。

## 目标

- 从当前账号的 `cloud_inventory` 按名称或完整路径做字面子串搜索，支持中文、拉丁字母和字面 `%` / `_`。
- 后端分页，单页最多 100 项；搜索词为空或超过 128 个 Unicode 字符时拒绝请求。
- 结果包含完整路径、文件/目录类型、文件大小或缓存目录聚合大小，以及命中总数和分页游标。
- 返回全盘缓存覆盖状态：`complete` 仅在全盘扫描状态为 complete 且所有已记录目录均 complete 时成立；运行中显示 `scanning`；扫描缺失、失败、暂停或目录覆盖不完整时显示 `incomplete` / `unknown`。非 complete 时，即使零命中也明确说明缓存不完整，不能据此判断远端不存在。
- UI 仅在“本地缓存”来源启用搜索；显示覆盖警告；结果不提供改名、移动、删除或清理按钮。点击实时定位时切换到实时来源、打开命中项的父目录并从 offset 0 重新请求。
- 缓存为空或搜索失败时不回退实时请求。

## 不做

- 不实现实时全盘搜索，不启动后台扫描，不为了搜索自动补齐缓存。
- 不将缓存结果用作远端操作的 `expected` 对象身份。
- 不增加缓存排序、筛选语言、正则或模糊匹配配置。

## 方案比较与决定

1. **SQLite 搜索接口 + 显式缓存搜索（采用）**：数据库负责筛选和分页，界面显示来源与覆盖完整性；百度 API 调用为零，内存用量有界。每条结果进入远端操作前必须定位到实时父目录。
2. **浏览器下载全部缓存再过滤**：可省后端代码，但会一次加载所有行、无法随账号规模增长，并增加浏览器内存和传输量；不采用。
3. **实时百度全盘搜索或缓存未命中时静默回退**：当前 provider 只有目录分页契约，跨全盘搜索需要遍历远端目录；会产生大量请求、限流和不可预测等待，且让数据来源不清楚；不采用。

## API 与数据语义

- 新增受保护只读 `GET /api/cloud-inventory/search?q=<term>&offset=<n>&limit=<n>`。
- 响应包含 `query`、`entries`、`total`、`offset`、可空 `next_offset`、`coverage.status`、`coverage.incomplete_directories` 及 `coverage.scan_updated_at_utc`。
- 条目沿用 `CloudInventoryEntry`；目录行附带本地聚合大小与覆盖完整标记。
- 查询必须绑定当前授权账号指纹；SQL 使用字面子串函数，不把用户输入拼入 LIKE 通配符或 SQL 文本。
- 查询结果的元数据来自全盘扫描状态与目录覆盖状态，绝不把局部刷新标成全盘完整。

## 验收

- Store 回归证明：名称/路径中文子串匹配、`%`/`_` 按字面搜索、账户隔离、分页/总数、目录本地聚合大小，以及 complete/scanning/incomplete/unknown 覆盖语义。
- HTTP 回归证明：仅允许 GET，空/超长词和非法分页拒绝；响应结构正确；搜索不触发实时 `ListCloud`。
- WebUI 回归证明：仅缓存模式使用搜索 endpoint；缓存未完整和无命中分别清楚提示；结果只提供实时定位；定位切换实时父目录并 offset 归零；失败不回退实时列表。
- 全仓 Go 测试/vet、WebUI/userscript 检查、Windows AMD64/Linux AMD64/Linux ARM64 构建及 ZIP 私有数据检查通过。
- 更新同一 `.57` 直到以上门禁通过；真实账号仅进行只读搜索验证，不执行搜索结果对应的远端写操作。
