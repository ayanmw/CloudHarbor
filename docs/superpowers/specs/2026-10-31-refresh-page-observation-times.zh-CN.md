# 云目录刷新逐页观测时间证据

## 目标

分页目录刷新必须分别保存每个百度列表响应的本机观测时间。目录只有在最后一页成功后才作为完整快照发布，因此目录发布事件的 `cloud_observed_at_utc` 继续表示最后一页完成整个目录观察的时刻。两者语义不同，不互相回填。

## 规则

- 刷新暂存条目保存该条目所在成功响应页的 UTC 观测时间，并跨 SQLite 关闭、重启保留。
- 刷新发布后，缓存条目和新增/变化明细使用各自页的观测时间；目录事件仍使用发布时最后一页的观测时间。
- schema 24 中仍在进行的旧刷新没有逐页时间。迁移以 0 表示未知，查询 JSON 对该条目返回 `observed_at_utc: null`；不得伪造为最后一页时间。
- 完整目录快照的其他入口继续使用其整页传入的观测时间。
- 本机 `recorded_at_utc` 仍表示 SQLite 写入证据的时间，与云端响应观测时间独立。

## 持久化

SQLite schema 25 为 `cloud_inventory_refresh_entries` 增加 `observed_at_utc INTEGER NOT NULL DEFAULT 0 CHECK(observed_at_utc>=0)`。新暂存页写入 `UnixMicro`；旧活动暂存项保留 0 未知标志。发布时根据每行观测时间写缓存；0 行不生成虚假的条目观测时间，变化快照字段为空。

## 验收

- 先暂存第一页并关闭/重开 Store，再暂存最后一页并发布；缓存及明细精确保留两个不同的页时间，目录发布事件使用最后一页时间。
- 模拟 schema 24 的活动暂存行，迁移到 25 后发布，条目时间仍未知而目录事件时间有效。
- 非 staged 的完整扫描路径及既有 refresh 查询/导出保持兼容。
- 运行 taskstore 相关测试、全仓 Go 测试/vet、WebUI 测试和发布脚本门禁。
