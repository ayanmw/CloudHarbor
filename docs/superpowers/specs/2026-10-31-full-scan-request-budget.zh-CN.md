# 全盘缓存扫描请求额度

## 目的

全盘扫描会递归读取整个百度账号目录。每页低频间隔可以控制请求速率，但不能限制一次扫描累计的请求数量。让用户能为单次全盘扫描设置持久化的列表请求额度。

## 行为

- 新扫描输入 `request_budget`，范围 0–100000；0 表示不限额。
- 恢复暂停/重启遗留检查点时，输入值表示追加额度。未输入或 0 使用原额度剩余量；原不限额检查点可从已用次数基础上转为有限额。
- 每次 provider 列表 GET 前，在 SQLite 事务中耐久预留一个额度。失败 GET 与重试也计入；预留后进程崩溃会消耗额度，绝不超额发送。
- 额度耗尽时将状态保存为 `paused/request_budget_reached`，保留目录队列、offset 和页边界；不发布不完整缓存。用户追加额度后从检查点继续。
- 状态 API 展示额度上限与已预留次数；现有检查点默认 0，升级不改变旧扫描的不限额行为。

## 数据与边界

- 扫描状态的 `request_budget` 与 `requests_used` 和现有游标同属 SQLite 持久状态，单次预留只更新已用次数和更新时间。
- 额度只约束全盘缓存的百度列表 GET，不约束实时浏览、局部目录刷新或重复内容哈希读取；它不是百度服务端速率限制或快照保证。
- 本功能不改变每页间隔、并发、发布事务及扫描恢复语义。

## 验收

- SQLite 测试证明每个检查点不可超额预留，关闭/重开后额度和用量保留。
- Mock provider 证明额度耗尽后不再发送 GET、队列与页边界保留，追加额度后可续扫到 complete。
- API 拒绝负数和超过上限的额度；WebUI 显示并发送预算，状态显示已用/上限与耗尽状态。
- schema 28→29 迁移为旧扫描设置 0/0，既有记录可继续加载。
- Go 全模块测试/vet、WebUI/userscript、`git diff --check` 通过。只用本机 SQLite/mock，不当作真实百度或 NAS 验收。
