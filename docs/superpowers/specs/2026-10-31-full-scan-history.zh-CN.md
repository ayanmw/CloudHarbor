# 全盘缓存扫描历史

## 目的

全盘扫描目前只保存每个账号的当前检查点。下次启动新扫描会覆盖上一轮状态，导致过去扫描的开始/结束时间、暂停/失败原因和请求额度证据无法回看。新增只读 SQLite 运行历史和关键事件，明确保存过去每轮与当前轮的状态边界。

## 行为

- 每次创建新全盘扫描时，在同一事务建立 run 摘要并写 `started` 事件；续跑写 `resumed`，用户暂停写 `paused`，终态写 `completed`/`failed`，限额暂停写 `request_budget_reached`，退避变化写关键 retry 事件。
- 运行摘要随现有扫描检查点更新，保留 run ID、开始/更新时间 UTC、状态/阶段、目录、页数、条目数、请求额度/已预留数、待扫目录数和最后错误。
- 事件只写状态跃迁或关键恢复，不为每页或每个请求生成事件，控制数据库增长；请求预算计数仍在摘要中更新。
- 页面按稳定 sequence 分页显示历史。选择一轮后只读加载该轮事件；内容可继续翻阅当前网盘缓存。
- 新表追加写，不受当前检查点覆盖影响；旧数据库迁移不伪造历史，历史从升级后新建的 run 开始。

## 非目标

- 不导出历史、不提供删除历史入口、不修改扫描队列/缓存发布方式。
- 历史是本机 SQLite 对扫描过程的观察证据，不是百度端原子快照或远端事件日志。

## 验收

- 两轮扫描历史都保留；新 run 不覆盖旧 run，分页顺序稳定。
- 暂停、恢复、失败、完成、限额暂停的事件与状态事务同步；SQLite 回滚时不出现半条历史证据。
- 页面只读显示 UTC 时间、额度与错误，转义远端/错误文字；历史读取不触发百度 API。
- schema 29→30 迁移、append-only 约束、旧状态兼容、全 Go/vet/WebUI/userscript/diff 门禁通过。
- 只使用本机 SQLite/mock，不代表真实百度或 NAS 验收。
