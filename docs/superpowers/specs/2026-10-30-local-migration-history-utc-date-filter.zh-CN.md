# 本地目录迁移历史 UTC 日期筛选

## 意图

迁移记录较多时，管理员可按迁移开始日期缩小历史范围；日期语义固定为 UTC，与数据库和导出中的 UTC 证据一致。

## 用户行为

- 历史筛选表单增加“开始日期（UTC）”和“结束日期（UTC）”两个日期控件。
- 两项可单独填写或同时填写，并可与现有状态、源/目标路径关键字组合。
- 起始日包含该日 `00:00:00Z`；结束日包含整日，后端以结束日期次日 `00:00:00Z` 作为排他上界。
- 搜索回第一页；翻页、刷新和摘要 JSON 导出继续使用当前全部筛选。清除筛选清空所有条件。
- 日期格式必须是有效且规范的 `YYYY-MM-DD`；起始日期晚于结束日期时返回 400。重复参数、非法日期不进入 SQLite 查询。

## 设计

- `LocalDirectoryMigrationFilter` 增加 `StartedFromUTC` 和 `StartedThroughUTC` 日期字段，保持 JSON/API 使用明确的 `started_from_utc` / `started_through_utc`。
- 归一化时严格解析真实公历日期；存储层将日期转为 UTC Unix 微秒边界，SQL 对 `started_at_utc` 做 `>= start` 和 `< day-after-end` 参数化比较。
- 列表计数、稳定分页和摘要导出共用同一筛选 SQL；导出 JSON 明确包含这两个筛选值。
- 页面用 `input type=date`，标签显式标明 UTC，不执行浏览器本地时区转换。
- 未提供日期时 SQL 和既有请求行为保持不变。

## 非目标与安全边界

- 不按更新时间或完成时间筛选；日期仅筛迁移开始时间。
- 不修改迁移记录，不提供恢复/重试，不读取迁移文件夹，不调用百度 API。
- 不改变已有路径搜索、状态筛选、排序、分页上限或摘要导出上限。

## 验收

- Store：起止边界包含/排除、仅起始、仅结束、跨日组合、状态/路径联合、稳定分页和导出复用；非法日期与反向范围拒绝；无日期结果与原行为一致。
- API：日期格式、真实日历日期、重复参数、反向范围验证；列表与导出传递相同 UTC 条件；no-store 和错误信息安全。
- WebUI：UTC 标签、提交参数、分页/刷新保留值、清除重置全部条件、摘要导出使用当前控件值。
- 发布：全仓 Go 测试/vet、WebUI/userscript、Windows AMD64/Linux AMD64/Linux ARM64 构建、ZIP 校验与私有数据排除。
