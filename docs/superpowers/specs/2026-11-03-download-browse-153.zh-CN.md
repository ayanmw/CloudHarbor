# .153 下载列表查询与浏览连续性

状态：前三项已实施并完成针对性验证，余两项继续推进；.152 发布包冻结，不回改旧包或迁移真实状态。

## 五项用户可见交付

1. 根任务总览先分页再读取当页历史汇总；大任务队列首屏不再为未显示根任务逐个查询历史。
2. 文件状态计数优先读取持久化总数及未完成状态投影，空搜索时不为计数重复遍历完整清单；搜索结果仍由 SQLite 准确筛选。
3. 明细翻页固定清单 ID；遇到新尝试发布新清单，明确提示重新载入，不把不同清单悄悄拼成一次翻页。
4. 下载列表的状态、搜索、页码与根任务位置写入受控 URL；刷新和浏览器前进/后退恢复浏览条件，不触发操作。
5. 文件信息中复制网盘路径或已知本地历史目标；目标缺失时不猜测，复制失败给页面内反馈。

## 当前依据与技术选择

.152 的 `GetTaskWorkspaceSnapshot` 已只复制根和活动文件，但仍为全部根任务查询历史，然后在 main 中筛选/分页。`DownloadManifestFilePage` 的内容响应已限制 200 行，但计数仍从完整 file_rows CTE 聚合。Vue URL 当前只保存 task，不保存筛选/页码；API 没有预期清单 ID，后台新清单发布可能让后续页换轮次。

沿用 Go、SQLite 和 Vue。根任务候选从已有调度器 jobs 选择，只为最终页复制 Task 并读取历史；不新增全量镜像表。状态计数复用 .152 totals 与 states，并在同一只读事务与文件页读取；不添加异步不一致计数缓存。默认分页增加预期 manifest 校验，新清单冲突明确返回 409，不提供目录未知结果人工放行或云端操作。

## 边界与验收

- 现有根排序语义（状态优先、路径、精确 ID）及 unfiltered counts 保持；目录子项不混入根队列。
- 只计完成证据，旧进程 downloading 仍降为 pending/interrupted；数据库不可读仍显式失败，不回退到虚假的空列表。
- 查询不能修改队列、历史、网盘或本地文件。URL 白名单仅含浏览条件，不携带 admin-key、令牌或操作参数。
- 新清单冲突保留已展示内容、禁用状态不可靠的操作，并提供明确重新载入入口；不自动切换到新轮次继续旧 offset。
- 本地路径仅复制已有历史目标；复制成功与失败均通过 aria-live 提示，不使用浏览器 Basic/alert。
- 使用临时数据库、大候选集合、轮次切换、Unicode、特殊字符、刷新/后退及剪贴板模拟验证；最终完整门禁与模拟可见验收后，达到五项再发布。
- 主目录内联，无 worktree、自动 commit/push、真实授权复制或真实云端写操作。本批暂无 schema 升级需求；若证据表明需要，先补充迁移设计及验证。
