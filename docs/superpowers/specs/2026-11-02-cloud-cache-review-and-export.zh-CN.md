# 网盘缓存覆盖复核与证据导出

## 背景

当前页面能筛选和分页查看缓存不完整路径，但要找某类异常需手动逐项选择；列表也只能在线查看。浏览器被挂起时还可能错过全盘扫描 `running → complete` 的状态边沿，导致已打开清单没及时更新。

## 目标

让用户快速定位不完整路径、离线保存一份有明确 SQLite generation 证据的清单，并在页面恢复运行时追上错过的扫描缓存更新。

## 决策

- 使用现有扫描状态里的 `inventory_coverage.incomplete_reasons` 在页面显示原因计数；点击原因计数设置现有筛选并从第一页读取本地清单，不新增 Provider/API 请求。
- 支持显式导出当前页和全部筛选结果两个 JSON 文件。导出字段使用白名单：路径、原因、目录状态、缓存目录存在标记、百度观察 UTC、运行 ID；顶部包含导出 UTC、筛选和 generation。不得导出账号指纹、Token 或凭据。
- 全部结果导出以首页返回的 `cache_generation` 固定后续游标页；任何页返回 409 或 generation/total 不一致时中止且不下载部分结果。
- 全量导出上限 10,000 条。超限时先拒绝，不生成截断文件。
- 若页面未观察到 `running → complete`，但一个已加载清单的 generation 与当前扫描覆盖 generation 不同，页面恢复后只从第一页刷新一次；只有当前扫描状态为 complete 时进行该追赶。已有的 run 边沿逻辑仍负责正常完成收尾。
- 不触发百度请求，不增加 API、SQLite schema、后台任务或自动全量清单读取。

## 验收标准

1. 页面显示所有支持筛选原因的计数；零值明确显示为 0，原因类别可能重叠时仍提示不可相加。
2. 点击原因计数保留路径搜索，选择该原因并从第一页读取本地结果。
3. 当前页 JSON 导出只包含当前展示页，记录筛选、generation 和逐项时间/run 证据。
4. 全部匹配结果跨页导出完整且稳定；期间 generation 或 total 改变时全有或全无地失败。
5. 超过 10,000 条时提示上限且不下载截断文件；不导出 fingerprint、Token 或百度凭据。
6. 页面挂起错过扫描状态边沿但醒来发现已完成 generation 变化时，已加载清单追赶刷新一次；重复状态轮询不会重复请求。
7. 上述操作只读本地状态/SQLite，不访问百度 Provider。
