# .159 账号与授权工作台

目标：把/oauth迁移到现有Vue工作台，完成全站UI重构中的账号入口；使用用户的持续最佳推荐授权，原目录内联实现，不创建worktree/提交Git。保持既有配置和授权业务，不引入新的服务依赖。

五项体验范围：
1. 账号状态总览：明确可用、未授权、待验证、需要重新授权、存储失败和读取失败；到期/下次续期/错误分列，保留原时区证据，缺失不推算。状态自动刷新沿用既有5秒且单请求在途，401/离页停止。
2. 应用凭证首次填写与申请引导：仅GET /api/app-config明确editable=true才出现表单，四字段齐全，说明官方开发者平台 https://yun.baidu.com/union 创建应用及复制位置；保存中防重复，成功立即启用并清明文，再读回状态。保存失败与是否已生效需区分，不能盲目重复提交。
3. 已配置掩码与来源：AppID/AppKey/SecretKey/SignKey只展示服务器掩码，明确env/.env优先或queue；非空/部分环境配置不可从网页覆盖，无清空按钮。未知读取状态不当作未配置，不把掩码当原始凭据。
4. 设备码授权：清晰呈现获取→百度授权→验证等待→结果，设备码有效期和安全链接/二维码；新请求使旧码及迟到响应失效。device_code只在内存用于API请求，不放URL/存储/日志/显示为用户码。保留https百度域名白名单。
5. 续期、取消和失败恢复：手动续期/停止本次等待的操作互斥和反馈，取消不宣称撤销已经完成的授权；401引导表单登录，更新账号状态后再判断可用。窄屏/键盘/读取失败/过期不沿用旧可执行状态。

接口沿用/api/app-config与/api/oauth/status、/device-code、/token、/refresh。服务端配置优先级、sidecar、仅空可写、Cookie/Bearer与账号绑定保持。本工具当前设备码流程无需本机OAuth回调；平台必填时说明应用类型/授权模式，不能冒充已实现回调。保存后无需重启。

模块：OAuthWorkspace.vue负责状态和共享动作；OAuthAppConfig.vue负责首次表单/掩码；OAuthDeviceAuthorization.vue负责设备授权生命周期；oauth-types.ts只放实际DTO/校验和标签，不新建全局状态框架。复用WorkspaceSidebar及已有样式，避免遗留通用th宽度污染新表格。

不使用真实账号/密钥作开发验收，不复制唯一授权。模拟测试与真实百度/NAS验收分开。五项全部完成、旧页能力对照、独立审查、桌面/390px可见验收及完整打包门禁后发布.159；.158冻结不更新。
