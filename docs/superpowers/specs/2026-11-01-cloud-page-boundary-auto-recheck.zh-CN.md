# 云目录分页边界漂移自动重核

## 目的

全盘扫描和指定目录刷新使用 offset 分页，并保存相邻页边界身份。当前检测到下一页首项与持久化边界不一致时会失败关闭，需要用户重新启动扫描。本设计在可观察到边界漂移时，从同一目录第一页自动重核，减少人工恢复，同时保持请求预算、缓存发布和跨重启证据安全。

## 已确认决策

- 用户已选择：边界漂移后自动从当前目录第一页重核。
- 每个当前目录最多自动重核 2 次。次数属于当前目录，跨进程重启及额度暂停/恢复持久化；该目录成功完成或启动新 run 时自然归零。
- 仍以现有边界身份核验为触发条件；不增加常规页面请求，不声称远端原子快照。

## 行为要求

1. 页 GET 前按现有规则耐久预留请求额度。只有 GET 成功返回且新页首身份与保存的边界不符时，才算一次可观察的边界漂移。
2. 若当前目录 `boundary_restart` 事件数小于 2，SQLite 单事务复位 `next_offset` 和 boundary、更新状态并追加一条事件。事件追加即构成一次重核凭据；下一次首页 GET 仍须先预留请求额度。
3. 若额度耗尽，沿用现有 `paused/request_budget_reached` 语义；已持久化的首页检查点和重核事件保留，追加额度后可继续。若当前目录已有 2 条重核事件，再次漂移则进入 `failed`，不自动继续请求。
4. 进程关闭或崩溃后，状态、当前目录、offset/boundary、请求用量和事件必须共同恢复；重核次数只从 SQLite 事件计算，不使用进程内计数。
5. 事件记录本机 `recorded_at_utc`、账号指纹、run_id、当前目录、事件种类、状态和现有请求额度证据。事件追加失败时，状态与重核检查点不得单独提交。
6. 自动重核是运行中检查点复位，不走现有终止失败保存路径：否则 worker 会退出，局部刷新还会按失败策略删除 staging。重核达到上限后才走终止失败路径。

## 缓存事务

### 全盘扫描

- 重核事务把当前目录的直系 `cloud_inventory` 条目标回当前 run 未见，同时将目录覆盖状态保持为未完成；保留对象数据及哈希，不能因开始重核提前删除缓存。
- 新页按现有逻辑逐页写入并标记为当前 run 已见。只有重核遍历到最终页后，才由现有最终页事务删除仍未见的直系项目、更新目录 complete 并推进目录队列。
- 目录尚未完成时，如果又发生身份冲突或其它终止错误，不得把旧检查点伪装成完整结果；按既有失败状态处理。

### 指定目录刷新

- 在重核事务中删除该 run、该目录的旧 `cloud_inventory_refresh_entries` 暂存行，复位 offset/boundary 并追加事件。
- 现有已发布 `cloud_inventory` 和目录大小/哈希缓存保持可读；重核目录完整后沿用既有原子发布事务更新或失效受影响缓存。
- 重核事务只删除当前目录 staging，不删除同 run 其它待扫目录的 staging，也不清空局部刷新队列。

## SQLite/API/UI

- 当前 schema 为 30；升级 schema 31，仅扩展两类事件表允许的 `boundary_restart` 值，不增加重复的状态计数字段。旧 run 没有该类事件，派生重核次数为 0。
- 两种 append-only 事件表增加 `boundary_restart` 允许值，并新增仅包含该事件类型的部分索引 `(account_fingerprint,run_id,current_directory) WHERE event_kind='boundary_restart'`，让大量目录/历史事件下的计数查询仍有界。迁移必须保留既有事件序号、时间、请求额度、既有索引和禁止更新/删除的触发器。
- SQLite 重核事务在同一事务内按账号、run_id、current_directory 统计事件；小于 2 时才重置检查点并插入新事件。状态读取/API 返回的 `boundary_restart_count` 是由事件派生的只读值，不另行持久化，也不放入私有边界 JSON；状态和计数必须在同一 SQLite 语句/读快照读取，避免并发重核时两者错配。
- 页面显示当前目录“重核 N/2”；事件时间使用本机 UTC 证据标签，与百度观测时间分开。额度暂停、次数耗尽分别显示可操作的状态说明；不得显示成无错误的成功扫描。

### 现有代码接入点

- `SaveCloudScanCheckpoint` 在同一 run、同一目录的 offset 从非零复位到 0 时，已把该目录本轮写入项的 `last_seen_run_id` 清空，供后续成功完整遍历时清理；边界重核应复用该事务行为，并在同一事务中统计/插入 `boundary_restart` 事件，避免两套复位逻辑分叉。
- `saveCloudInventoryRefreshState` 将状态写成 `failed` 时会清除刷新队列和 staging。自动重核必须使用专用的活动检查点事务，仅清除当前目录 staging 并保留队列；不得借用失败后再恢复的流程。
- 两类事件表均有 `event_kind` 检查约束、稳定分页索引及 append-only trigger；schema 31 迁移需事务性重建/替换约束并恢复这些对象及新部分索引，迁移失败时旧 schema 和历史记录保持完整。
- 已有全盘扫描历史事件 API 和局部刷新事件 API，无需新建历史路由；须更新其 kind 校验/过滤和导出验证，并在 WebUI `scanHistoryEventLabels`、`refreshEventLabels` 增加中文“目录分页漂移，重新核对”标签。

## 验收

- 全盘扫描：模拟第一页/中页已提交后发生边界漂移；状态在同事务中重置，缓存直系条目标回未见但不提前删除，重读成功后仅最终页清理远端已消失对象并标记 complete。
- 指定目录刷新：漂移后清除本目录旧暂存页并重读；旧发布缓存在完成前保持原样，最终发布仍原子。
- 连续漂移最多自动重核两次；第三次漂移进入失败，不提交漂移页、不把目录标为 complete，也不发送额外自动请求；次数由同 run、同目录事件条数决定。
- 在漂移后额度耗尽，检查 SQLite close/reopen，追加额度后从第一页继续；事件条数不丢失、不重复。
- 对旧 schema 30 数据迁移到 31：既有事件可读、旧 run 派生计数为 0、事件表仍 append-only；迁移失败须整体回滚。
- 重核次数统计按账号/run/目录使用部分索引；回归核对索引存在，并通过 `EXPLAIN QUERY PLAN` 确认 count 查询使用索引而非全表扫描。
- HTTP 状态、历史事件及 UI 显示路径、UTC 时间、派生重核次数、额度暂停和次数耗尽；运行 WebUI 定向回归。
- 全仓 Go 测试/vet、WebUI/userscript、三平台构建、版本命令和 preview 打包/载荷快照检查通过。

## 非目标与限制

- 不提供百度远端原子快照保证；边界未变化时仍可能发生不可观察的并发遗漏。
- 不启动第二轮全盘扫描，不对已完成目录后台重扫，不提高正常分页 GET 数。
- 不改百度远端文件，不重发 move/delete，不改变扫描与局部刷新互斥规则。
- NAS/SMB 和真实账号验收与本机/SQLite/mock 自动化分开记录。

## 批次门槛

候选批次至少计 5 项独立用户结果：全盘扫描漂移恢复；指定目录刷新漂移恢复；计数跨重启及每目录封顶；额度耗尽后安全续跑并保留时间证据；状态页展示进度和结束原因。仅完成设计与内部重构不能计入门槛。版本号待实现、回归和发布验收完成后再确定。

## 重核原因证据补充（2026-11-02）

- 全盘扫描及目录刷新 append-only 事件使用固定原因码：`page_boundary_mismatch`、`provider_duplicate_page_id`；目录刷新另有 `staged_page_duplicate_id`。页面显示对应中文说明，事件导出保留原因码。
- SQLite schema v34→v35 为目录刷新事件加原因列，v35→v36 为全盘扫描事件加原因列。旧事件保留空值，不根据状态或错误文本反推原因。
- 实时网盘浏览已有首页回读信号补充 `boundary_change_reason`，区分页边界变化和百度单页重复 ID；只给已有回锚请求加响应字段，不额外请求。
- 此证据改善不改变“自动回第一页、每目录最多重核两次、请求前持久预留额度”的既有行为，也不构成远端原子快照保证。
