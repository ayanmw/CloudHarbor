# 本地目录迁移筛选摘要导出设计

## 意图

管理员在迁移历史中使用状态或源/目标路径筛选后，可以一次导出所有匹配迁移的摘要，便于离线整理和排查；逐条完整事件仍通过已有的 ID 专属导出取得。

## 目标与范围

- 新增受保护的 GET `/api/settings/local-migrations/export`，复用历史列表的 `status` 和 `q` 过滤语义，不受当前页 offset/limit 限制。
- 从一个只读 SQLite 快照读取全部匹配摘要，按 `started_at_utc DESC, migration_id DESC` 排序，最多导出 5,000 条；第 5,001 条存在时拒绝整份导出，不截断。
- JSON 包含导出 UTC 时间、筛选条件、匹配总数和迁移摘要数组；不包含每条追加事件。单条事件证据仍由 `/api/settings/local-migrations/{id}/export` 导出。
- 页面新增明确的“导出当前筛选结果”按钮；导出使用当前筛选控件值，清空筛选后导出全部摘要。下载需用户点击。
- 错误响应不泄漏 SQLite 内部错误；成功和失败均禁止缓存。

## 不做的事

- 不导出百度网盘数据、迁移目录内容或额外事件证据。
- 不新增记录删除、恢复、重试或修改入口，不执行文件系统或网络访问。
- 不新增 schema、依赖或后台作业。

## 方案比较

1. **一致快照内有界全量导出（采用）**：导出全部筛选结果，字段和顺序稳定；超过 5,000 项时明确拒绝，避免无声截断或无界内存增长。
2. **逐页导出当前页**：实现简单，但用户容易将页面结果误认为完整筛选结果，因此不采用。
3. **前端循环翻页后拼接**：会跨多个 SQLite 快照，记录变化时文件可能自相矛盾，也让浏览器承担无界聚合，因此不采用。

## 验收

- Store 覆盖当前筛选匹配、稳定排序、空结果、SQLite 一致快照、5,000 上限及 5,001 拒绝；列表和导出使用一致的状态/关键词语义。
- API 覆盖过滤参数、JSON 字段/UTC、附件名、no-store、非法条件、超限与内部错误隐藏；不触发云端 API。
- WebUI 覆盖当前输入条件被带入导出、导出按钮只在点击时请求、附件下载和错误提示。
- 全仓测试、vet、WebUI/userscript、三平台构建与包检查通过。
