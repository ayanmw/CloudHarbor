# 重复文件扫描字节进度设计

## 意图

重复文件扫描会逐个从网盘读取候选文件并计算 SHA-256。当前页面只展示文件数，启动前的读取量估算不能反映运行中的已完成/剩余数据量。本变更让大扫描进度同时按文件和字节展示，并在重启后保持一致。

## 目标与约束

- SQLite 扫描状态持久记录 `total_bytes` 和 `processed_bytes`；只在文件完整下载、长度匹配、SHA-256 保存成功后累加已完成文件数/字节数。
- 新运行从完整缓存估算候选文件数与字节数；同一 run 续跑时以累计已处理数/字节加当前游标后的剩余候选重新计算总量。
- 因候选缓存变化导致扫描已无后续项时，完成状态的总量收敛到已处理量；运行中不把 partial/retried download 算作已完成。
- 从 schema 16 升级到 17 时原子增加两列并保留现有扫描状态。旧暂停扫描的已处理字节根据当前库存与已验证 hash 尽力重建；无法对应到当前文件身份的字节不得伪造。
- UI 显示文件和已核验字节两种进度；0 字节任务正确显示，不计算 NaN/Infinity 百分比。长任务详情可折叠，现有页面浏览行为保持不变。
- 事件证据追加两个计数字段，继续沿用账号隔离和 append-only 规则。

## 方案比较与决定

1. **SQLite 持久化累计字节（采用）**：成功文件后与既有状态更新同一事务持久化；重启续跑直接恢复，旧数据通过 schema 迁移兼容。
2. **每次查询时按 hash 表重新聚合**：无需字段迁移，但跨 run 的旧 hash 可能被误算为本次进度，且库存刷新会改变历史进度；不采用。
3. **只在浏览器内累计**：刷新/重启丢失且不能反映服务端扫描恢复状态；不采用。

## 验收

- Store/API/扫描回归验证字节状态跨关闭重开、追加事件证据、schema 16 迁移和非法负数拒绝。
- Downloader 回归验证新运行总量、暂停续跑累计与剩余、完整文件成功后才记字节、失败/重试/取消不重复累加、无剩余候选时总量收敛。
- WebUI 回归验证文件/字节显示、0 字节和状态、运行进度详情折叠仍可使用。
- 全仓 Go 测试/vet、WebUI/userscript、Windows AMD64/Linux AMD64/Linux ARM64 包门禁和 ZIP/私有数据检查通过。
- 只做本地模拟验证；不在真实百度账号启动大扫描或执行任何删除。
