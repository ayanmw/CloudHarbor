# 下载磁盘空间安全与恢复设计

## 目的

本项目用于持续后台下载，但本地文件传输目前没有预检目标卷剩余空间。空间不足会在内容请求或写入过程中才被操作系统发现，任务只得到通用文件系统错误。传输代码保留 `content.part`，重试能使用其现有长度继续 Range 下载，但管理页不能说明失败是否由空间不足造成，也没有记录当时需要/可用容量的本机证据。

本批在 Windows/Linux 上检查目标下载卷的可用容量，协调同一进程的并发下载预留，并区分空间不足与容量查询失败。记录不足时不启动该文件的百度内容请求；传输中遇到磁盘满则保留受身份文件元数据绑定的部分文件，明确失败原因，允许用户释放空间后通过现有手动重试续传。

## 当前源码依据

- `internal/downloader/downloader.go` 的 `downloadLocalFileWithSlotHeld` 调用 `transfer`；文件内容下载和本地写入在 `internal/downloader/transfer.go` 的 `transfer` 内完成。
- `transfer` 在检查并装载 `partial.json` 后，以 `content.part` 当前长度确定 Range 偏移；只有完成 SHA-256 校验后才生成 `complete.json` 并发布最终文件。下载失败不删除 partial。
- `internal/downloader/scheduler.go` 对百度可重试错误安排自动退避，对普通本地 `os.PathError` 记录为失败；`errorClass` 目前只归类为 `filesystem_error`。
- 任务错误已经显示在任务列表；失败任务可使用既有 retry 操作人工重试。系统重启后任务和 attempt 事件保存在 SQLite。
- 配置下载根目录允许使用 Windows 本地/共享路径及 Linux 挂载目录；项目发布目标为 Windows AMD64、Linux AMD64 和 Linux ARM64。

## 五项用户结果

1. **下载前知道目标卷是否有空间。** 在请求文件下载链接/内容之前，以目标本地路径查询当前用户可用空间；需要量按文件大小减去已存在且身份匹配的 partial 长度计算。容量不足时该文件不产生百度内容请求。
2. **并发下载不重复占用同一份空闲容量。** Downloader 按文件身份预留剩余字节；写入成功后减少预留，失败/取消/完成后释放。检查可用量时扣除其他活动传输尚未写入的预留，避免并发任务都依据同一空闲空间通过准入。
3. **空间不足与容量不可查询有明确区别。** 任务错误分别指出容量不足或无法读取目标卷空间，并给出目标本地路径、所需字节、观测到的可用字节和本机 UTC 检查时间。未知容量按安全失败关闭，不启动该文件内容请求。
4. **传输过程中耗尽空间不会被当成普通网络错误。** Windows/Linux 的磁盘满错误归类为 `local_storage_full`，不进入 provider 自动重试；保留 partial 和原任务记录，不发布未验证文件。
5. **释放空间后可安全续传并审计上次失败。** 页面继续使用现有失败任务重试入口；下一次会重新查询容量，只为剩余字节申请空间，并沿用现有 Range/最终 SHA-256 校验。任务 attempt event 记录容量检查本机 UTC、目标路径、所需/可用字节和错误类别；不把本机时间写成百度观测时间。

## 方案与取舍

1. **仅在系统写入失败后报告磁盘满。** 无额外预检，但先前已消耗百度流量；并发下载可同时写满磁盘，页面也不能在启动前解释所需容量。本方案不选。
2. **只在每个文件开始前独立查询可用空间。** 能提早拒绝单项下载，但多个并发任务会同时看到相同空闲容量并一起通过。本方案不选。
3. **目标卷预检、并发预留、写入错误分类与 partial 续传合并。** 每次新/续传前查询系统可用空间，并在进程内协调剩余字节预留；写入中的空间耗尽记录为本地存储错误。复用当前任务失败/人工重试、SQLite attempt event 和已验证 partial 发布机制，不增加数据库 schema 或自动重试。采用此方案。

## 技术约束与失败语义

- Windows 使用操作系统返回的“当前用户可用字节”；Linux 使用目标挂载点可用字节。调用前创建/核验传输目标父目录，保证查询命中实际目标卷。测试可注入容量查询函数，不依赖填满真实磁盘。
- 容量检查仅是开始时证据，不构成文件系统锁。外部进程、其他设备、配额变化仍可能在检查后消耗空间；写入错误分类和 partial 保护必须保留。
- 同一 Downloader 进程内的预留按剩余待写字节递减。进程重启后旧 reservation 不恢复：操作系统的可用空间查询反映实际落盘后的空间，已写入的身份匹配 partial 从其长度计算剩余量。
- partial 仅当 `partial.json` 与当前 fs_id、路径、size、mtime、MD5 一致时作为续传凭据。任何容量判断都不能放宽现有 SHA-256、Range 响应和最终发布校验。
- 空间不足/容量查询失败记为普通终态 `failed`，仅经用户手动重试；不自动循环重试，也不自动清理其它下载文件。
- 目标盘异常、共享断开或权限问题如不属于可识别的磁盘满错误，仍按通用文件系统失败处理；不得把所有写入错误误报为空间不足。
- 不做远端网盘写操作，不删除/移动本地文件，不新增自动空间回收，不读取 NAS 凭据，不更改 `.env`/路径设置。

## 验收

- 单文件容量不足时，在本地 mock 观察到 0 次下载链接/内容请求，SQLite 任务失败事件包含正确本地时间与容量证据。
- 续传只计算 remaining bytes；相同内容 partial 可续传，错误身份 partial 不得获得空间预留或进入 Range 恢复。
- 多个并发任务不能超出可用容量预留；成功写入后预留按字节减少，取消/失败释放预留。
- 注入 Windows/Linux 磁盘满错误时，状态分类为 `local_storage_full`、不安排 provider 自动重试、不发布最终文件且保留有效 partial；释放模拟空间后手动重试成功并得到正确 SHA-256。
- 容量查询失败会明确标记未知并阻止百度内容请求；容量足够时保持已有下载行为。
- 全仓 Go 测试、vet、WebUI/userscript、Windows AMD64/Linux AMD64/Linux ARM64 构建及 `.121` 包/源码快照/私有运行数据校验通过。
- 本机模拟和构建不能替代目标 NAS/SMB 容量报告及断盘恢复验收；本轮不以本机结果宣称 NAS 验收。
