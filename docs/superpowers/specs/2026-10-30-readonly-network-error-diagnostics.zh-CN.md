# 只读网盘请求网络错误诊断

## 背景

手动添加预检和网盘目录读取失败时，页面直接显示受保护 API 的文本错误。当前 API 已显示结构化 HTTP 状态与百度错误码；认证、取消和超时也有分支。但 DNS 失败、传输超时和连接建立失败仍可能落到通用提示，用户难以判断 NAS 网络、DNS 或网盘账号问题。

## 目标

- 对只读网盘请求的 DNS、网络超时和连接错误给出简短、可采取行动的中文提示。
- 对无法分类的错误保留现有通用提示；结构化 HTTP/百度错误码保持原行为。
- 在现有 intake 和 cloud 页面直接展示同一安全提示，无需增加新的错误响应格式。
- 只读错误明确可安全重试；不把远端写操作失败改写成可重试，也不自动重发移动、删除或改名。

## 方案

1. **在服务端 `readFailure` 依据可检查的错误类型分类（采用）**：复用 `errors.As` 识别 `net.DNSError`、`net.Error` 和 `net.OpError`，返回固定提示，不返回错误字符串。这样使用已有 API 文本响应，适用于目录读取和手动预检。
2. 返回原始底层错误：信息更具体，但 `url.Error`/传输错误可能携带请求 URL 或凭据，不能采用。
3. 由网页依据 HTTP 状态推测网络原因：服务端已有真实错误类型，HTTP 状态不能区分 DNS、连接和读取超时，推断会误导用户。

## 提示规则

- DNS 解析失败：提示检查 NAS DNS/网络；只读请求可在修复后重试。
- 网络超时：提示检查网络/代理并稍后重试只读请求。
- 建立连接失败或传输中断：提示检查 NAS 网络/代理，修复后可安全重试只读请求。
- 其他错误：保留通用安全提示；如果是 `baiduapi.APIError`，继续展示 HTTP 状态和百度错误码。
- 用户界面只显示服务器返回的安全提示文本。任何分支都不显示 URL、令牌、原始错误消息或堆栈。

## 约束与非目标

- 仅适用于不会改变网盘状态的 GET/预检读取错误；`failure` 写操作处理保持原样。
- 不增加自动重试、重试按钮、网络诊断请求、日志或数据库字段。
- 不改变预检确认流程、unknown 隔离规则或任何百度远端操作。
- 用模拟错误验证；真实百度预检是只读且不作为本版本发布门槛。

## 验收

- API 测试覆盖 DNS、超时、连接错误、结构化百度错误及普通错误，并确认响应不包含请求 URL/凭据。
- 页面测试确认预检将 API 的安全错误提示展示给用户。
- 全仓 Go 测试、vet、WebUI/userscript 与三平台预览包门禁通过。
