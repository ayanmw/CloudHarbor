# 远端操作事件时间线按状态筛选

## 意图

单笔远端操作可能有多条追加状态事件；在独立历史页按状态筛选后，可快速定位失败、未知或确认事件，并继续分页读取更早证据。

## 行为

- 单笔操作详情增加事件状态筛选：全部、待确认（prepared）、已确认（confirmed）、结果未知（unknown）、失败（failed）。
- 应用筛选时只清理该 operation ID 的旧事件页，从最新事件重新查询；更早事件沿用所选状态。
- 清空筛选恢复该 operation ID 的完整时间线。
- 无匹配事件显示空结果；不存在 operation ID 仍返回 404。

## 技术方案

- SQLite 事件页查询增加可选状态谓词，并继续按 `sequence DESC`、`operation_id` 限定、有界 `limit+1` 取页。
- API 接受可选 `status`，拒绝重复或非枚举值；返回字段、HTTP 状态、递归敏感字段遮蔽及 no-store 保持不变。
- 前端将每笔 operation 的筛选值和请求序号隔离保存；旧状态/旧游标请求不能覆盖当前时间线。状态选择后点击“筛选事件”提交，避免下拉菜单每次改动都发请求。

## 安全边界

- 只读当前下载目录绑定的 SQLite，不访问百度 API。
- 不新增重发、放行、确认、删除或历史清理入口；unknown 仍不可执行。
- 不改变事件内容或持久化，不增加 schema。

## 验收

- Store：四种状态筛选、跨操作 ID 隔离、过滤游标、空匹配但操作存在、未知 ID 404 和非法状态拒绝。
- API：状态转发、重复/非法参数 400、UTC/证据脱敏/no-store 和错误隐藏。
- WebUI：状态应用重置游标、后续页沿用筛选、清除回到全部、旧状态响应被丢弃、空结果和证据转义。
- 全仓 Go 测试/vet、WebUI/userscript、Windows/Linux AMD64/Linux ARM64 构建和 ZIP 私有数据门禁通过。
