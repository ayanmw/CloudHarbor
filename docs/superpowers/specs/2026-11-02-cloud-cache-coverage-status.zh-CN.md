# 全盘扫描状态与当前缓存覆盖状态分开展示

## 背景

全盘扫描运行状态 `complete` 表示该轮扫描队列已结束；它不保证所有缓存目录目前仍是 `complete`。例如确认的远端变更或其他本地缓存失效会把受影响目录标为 `stale`，而原扫描运行仍保持 `complete`。缓存搜索已经按未完整目录数计算覆盖状态，但全盘扫描状态接口/进度区域主要展示运行状态，用户容易把“运行结束”理解为“当前缓存完整”。

## 目标

管理页同时呈现不可变的扫描运行状态和当前 SQLite 缓存覆盖状态，并准确显示不完整目录数量及观察时间。读取摘要只访问本地 SQLite，不调用百度接口；两种状态不互相覆盖。

## 决策

- `GET /api/cloud-inventory/scan` 保持现有顶层状态字段兼容，并新增嵌套 `inventory_coverage` 摘要。
- 扫描状态、缓存 generation、覆盖计数和更新时间从同一个 SQLite 只读事务读取，避免在并发扫描/缓存更新时拼接矛盾摘要。
- 覆盖状态沿用缓存搜索规则：扫描运行中为 `scanning`；扫描运行结束且未完整目录数为 0 时为 `complete`；有扫描状态但仍有不完整目录时为 `incomplete`；无扫描记录时为 `unknown`。
- 覆盖读取失败时整个状态读取失败，页面显示状态不可读；禁止使用旧缓存计数冒充当前摘要。
- 页面分别标注“本轮扫描状态”和“当前缓存覆盖”，显示不完整目录数量、缓存代次和扫描状态更新时间；不自动启动重扫或改变 stale 目录。

## 验收标准

1. 扫描运行 `complete` 且仍有 stale/缺失目录时，接口同时返回运行完成与 `inventory_coverage.status=incomplete` 及准确计数。
2. `complete` 且不完整目录数为 0 时，覆盖状态为 `complete`；扫描运行中为 `scanning`；无运行记录为 `unknown`。
3. 运行状态、覆盖计数、缓存代次与更新时间来自同一 SQLite 快照。
4. SQLite 覆盖摘要读取失败时 API 不返回部分旧摘要，页面不会宣称缓存完整。
5. UI 明确区分扫描结束与缓存覆盖；只读页面加载不会额外请求百度或启动扫描。

本变更不修改远端扫描调度、缓存失效语义、下载队列或远端操作。
