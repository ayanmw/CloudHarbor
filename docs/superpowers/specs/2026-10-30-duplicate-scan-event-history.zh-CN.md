# 重复文件扫描事件历史

## 目标

把 SQLite 中已持久化的重复扫描状态转换事件以只读时间线展示，帮助用户在长时间扫描、暂停、重试、失败或重启后了解进度变化。

## 行为

- 网盘管理页的重复文件清理区域提供“扫描事件历史”折叠区；用户展开/点击加载后，按需请求本地 SQLite，不触发百度请求、扫描启动/暂停或文件操作。
- API 按账号隔离，默认读取最新 20 条事件；支持 `before_sequence` 加载更早事件，单页上限 50 条。返回事件序号、run ID、状态、阶段、UTC 记录时间和解析后的证据，以及可空的下一页游标。
- 首屏展示最新事件；时间线按旧到新排列，加载更早事件时追加到前面并去重。状态/阶段/时间/证据字段均作为不可信数据转义后展示。
- 历史为空时明确显示“暂无扫描事件”；读取失败保留重试入口。迟到响应不得覆盖用户切换到其它扫描记录后的视图。
- 事件证据仅包含已有 SQLite 持久化内容；不新增写入频率或扫描过程事件。结果未知等状态照原样显示，不提供重试/恢复/删除入口。

## 边界

- 继续使用当前 append-only `cloud_duplicate_scan_events` 表，不迁移数据库，不访问百度 API。
- 只展示状态转换事件，不承诺逐文件实时日志；逐文件进度仍以当前扫描状态为准。
- 不改变扫描、暂停、恢复、退避或远端删除行为。

## 验收

- Store 覆盖账号隔离、最新页/更早游标、排序、空页、上限与无事件。
- API 覆盖认证后只读 GET、分页游标、参数重复/非法值拒绝和错误本地化。
- WebUI 覆盖显式按需加载、追加更早事件、字段转义、空态、失败重试和过期响应丢弃；展开历史不触发其它写 API。
- 全仓 Go 测试/vet、WebUI/userscript、三平台构建和 ZIP/来源快照/私有数据检查通过；不执行真实账号写操作。
