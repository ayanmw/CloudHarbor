# .161 本地迁移历史工作台

本项目按用户既有最佳推荐实施授权继续，原目录内联，不使用worktree、不自动提交或push。.160已冻结，最终ZIP与验收证据在releases同级.160-validation.md。

选择独立Vue迁移历史页，而不是继续在旧/cloud追加明细，原因是旧页把文件操作、扫描与迁移证据堆叠，历史难以定位。复用已有SQLite和HTTP历史能力，不新增迁移算法、删除入口或数据库表。

本版五项用户交付：
1. `/settings/migrations` 独立紧凑历史表格，状态、阶段、来源/目标、数量和时间分列，空结果及读取失败始终可见。路径工作台提供直达入口。
2. 状态、路径关键词和开始UTC日期范围筛选，草稿与已提交条件分开；分页/URL回退保留已提交上下文，坏查询不发送API。offset是实时列表偏移，不声称数据库快照。
3. 记录详情抽屉，固定所选迁移ID与列表观察，明确历史记录不代表当前磁盘核验，来源/目标/错误/时间完整可核对。
4. 按记录ID读取关键事件，分页精确sequence游标、保留UTC原值和原始证据；换记录/改条件/离页取消旧响应，事件查询不会重发迁移。
5. 按所选ID导出完整证据、按已提交筛选导出摘要；显示5000摘要/100事件上限和失败，不下载部分结果或用默认latest代替所选ID。

已核实API：GET `/api/settings/local-migrations` 返回entries/total/offset/limit/next_offset，默认20上限50；status/q/started_from_utc/started_through_utc沿现有解析。GET `/{id}/events` 默认20上限50，before_sequence为int64；GET `/{id}/export` 上限100事件，summary `/export` 上限5000。现有列表计数与事件sequence是数字，需最小可选字符串DTO以免JS舍入，旧默认及导出原始JSON不变。不得从舍入数字构造精确游标。

所有读取单在途；401停止并回登录；旧结果保留时明确历史，不能沿用为新筛选分页权限。导出绑定发起时ID/已提交条件，原始字节不重新序列化；错误不污染其他区域。BFCache/迟到与18091本机mock验证沿现有模式。最终一个独立review、桌面/390px/键盘、完整Go/vet/前端/旧页/脚本/三平台与ZIP快照门禁后发布.161。无真实账号、目录或授权文件操作，不把模拟当NAS验收。
