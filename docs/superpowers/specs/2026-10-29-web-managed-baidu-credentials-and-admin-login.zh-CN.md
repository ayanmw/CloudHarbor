# 网页首次配置百度应用与管理员表单登录

状态：用户已确认实施；当前实施中。

## 目的

新用户在授权页能找到百度网盘开放平台入口，并能在网页首次保存 AppID、AppKey、SecretKey、SignKey，不必先编辑环境变量。管理界面改用密码表单登录，避免浏览器 Basic Auth 原生弹窗及其与 WebSocket 的兼容问题。

## 已确认需求

- 网页只在百度应用配置为空时显示 AppID、AppKey、SecretKey、SignKey 首次设置表单。
- 四项一起提交并持久化。提交及刷新后不再显示明文，只显示各项首尾少量字符和中间掩码，用于核对；读取接口不得返回 SecretKey、SignKey 明文。
- 网页不能修改或清空已存在的配置。需要更换时，用户停止服务后从命令行/本地配置操作清除或改好配置，再重启。
- 管理员登录用现有 `ADMIN_PASSWORD` 或随机生成的 `admin-key.json` 密码。浏览器用表单提交密码，服务端签发会话 Cookie；管理员会话不自动过期，只能通过登出撤销并清理 Cookie。API/CLI 保留 Bearer 认证，不再返回 Basic Auth challenge。
- 应用密钥与任务/事件历史、本地下载状态及百度云端状态保持不同的存储与证据边界；不会把 Secret 写进任务事件、HTTP/应用日志或前端存储。

## 现状核对

- `BAIDU_APP_ID`、`BAIDU_APP_KEY`、`BAIDU_SECRET_KEY`、`BAIDU_SIGN_KEY` 由配置加载层提供；当前设备授权实际使用 AppKey/SecretKey，AppID/SignKey 尚无其他代码消费者。
- SQLite 任务数据库旁已有私有 `settings.json` sidecar，并由 taskstore 原子写入；SQLite 事件表只记录任务状态与操作证据。
- 管理页、API 和 WebSocket 当前统一经过 `management.Gate`，接受 Basic 或 Bearer；随机管理员密码保存在 `admin-key.json`。当前没有网页登录会话或登录页。

## 方案比较与建议

1. **推荐：新增独立私有 `baidu-app.json` sidecar。**复用 taskstore 的路径安全检查、原子替换和私有目录权限；配置和任务/事件数据库、下载模式 `settings.json`、用户 OAuth Token `credentials.json` 分开。文件保存 AppID、AppKey、SecretKey、SignKey，不含 Token。网页首次写入成功后锁定为只读。停服后删除此文件可重新显示首次配置表单。
2. **并入现有 `settings.json`。**改动较少，但会把应用 Secret 和下载模式放进同一文件，降低配置隔离清晰度。
3. **把应用密钥存入 SQLite。**持久性可实现，但 SQLite 不会自动加密 Secret，且会让应用凭据进入任务数据库备份；对本项目现有 sidecar 边界没有明显收益。

采用独立 sidecar 后，Secret 仍为本地明文，依赖下载目录的 OS 权限保护；不声称加密。Windows 沿用下载目录 ACL，POSIX 沿用 taskstore 的私有文件权限和原子保存约定。需要使用者保护整个状态目录及备份。

## 拟定行为

### 应用配置

- 配置解析按以下顺序进行：先读取项目 `.env` 中的四项应用凭证，再由非空进程环境变量覆盖同名值；最终环境配置为空时，读取 `nas-downloader/queue/baidu-app.json`。最终没有配置值时视为空并允许网页首次设置。合并后的环境配置优先于 sidecar。
- 四项凭证必须作为一组匹配使用：合并后的环境配置四项都非空时整组优先；四项都为空时整组回退到 queue sidecar；若合并后的环境配置只提供其中部分，启动失败，避免拼接不同来源的凭证。sidecar 损坏或格式不合法时失败关闭，不静默回退为空。
- 命令行更换环境配置时，修改 `.env` 并重启；若合并后的环境配置四项留空或移除，则回退使用 queue sidecar。要恢复网页首次配置，需清空 `.env` 和进程环境中的四项并删除 queue 目录中的 `baidu-app.json` 后重启。网页首次保存只在最终解析结果为空时允许。
- 如果最终配置为空，授权页显示首次设置表单。服务端校验四项非空、长度有界，并以“仅当配置仍为空”的原子写入防止并发或重复覆盖。已设置时返回 409，前端不重试覆盖。
- 成功保存后，服务端原子持久化配置并立即更新当前进程中的授权服务和凭证管理器；更新过程必须串行化，确保并发授权、刷新 Token、验证账号不会读取到混合的新旧密钥。更新成功后立刻清除浏览器输入框，不把明文放入 localStorage/sessionStorage 或页面 URL，页面显示服务端生成的掩码提示。刷新或重启后页面只读显示掩码。
- 掩码由服务端生成，只返回首尾少量字符；短值按长度缩短显示。页面状态接口不返回完整值。四项配置若来自环境配置或 queue sidecar，也只显示掩码和来源，不提供网页编辑。
- 凭据记录中已有的 AppKey 需要兼容：启动时检测它与最终应用配置是否冲突；冲突时失败关闭并给出本地恢复说明，不能自动清除用户 OAuth Token 或账号绑定。

### 管理员网页登录

- 增加公开的 `/login` 页面及登录/登出端点；除这些入口外，其余页面、HTTP API 和 WebSocket 继续受认证保护。
- 表单只输入现有管理员密码，不创建第二套密码。正确密码后创建密码学随机、不含密码的服务端会话，Cookie 设置 `HttpOnly`、`SameSite=Strict`、`Path=/` 和远期 `Expires`；TLS 直连或配置 `PUBLIC_ORIGIN` 时带 `Secure`。服务端会话没有自动过期时间，用户点击登出后服务端撤销会话并发送清理 Cookie；会话记录须跨进程重启保留。浏览器可自行清理或限制 Cookie 存活期。
- 未登录访问普通页面重定向到登录页；API 和 WebSocket 返回 401，不带 `WWW-Authenticate`。Bearer CLI 仍可用于脚本。HTTP Basic 不再作为认证方式。
- 登录提交同样检查 Origin 和 Fetch Metadata；现有受保护写请求的 Origin/CSRF 校验继续生效。会话密码比较保持常量时间；登录失败有界限流，不记录密码、Cookie 或原始请求体。
- Cookie 只携带不可预测的随机会话凭据；服务端持久化会话凭据的哈希、创建时间与撤销时间，不存储 Cookie 明文或管理员密码。登出后记录撤销时间并清理浏览器 Cookie。重启后仍拒绝已撤销的会话。

## 非目标与限制

- 不在网页显示或回填 SecretKey 明文，不提供网页编辑/清空/轮换现有应用密钥的功能。
- 不自动更换百度 OAuth 账号，不解除既有账号绑定，不清理 OAuth Token 或任务历史。
- 当前实现使用 OAuth 设备码授权，不接收 OAuth `redirect_uri` 回调，因此无需回调页地址或反向代理 URL。授权页应说明这一点；若未来切换到需要 redirect URI 的授权模式，再设计并实现可访问的回调端点，届时通过用户配置的公网 HTTPS 地址（反向代理场景由用户自行配置）注册到百度平台。
- 不把本地表单、模拟服务或掩码状态当成真实百度授权成功证据。
- 不承诺目标 NAS/SMB 的断电耐久；sidecar 原子替换的语义仍依赖实际文件系统。

## 验收标准

- 空配置显示首次表单；合法输入仅写入一次，成功后输入框清空并显示掩码，授权服务无需重启即可使用新配置；刷新及重启后仍只显示掩码。
- 并发/重复提交、非法/超长/不完整配置、`.env` 部分配置均失败关闭，不覆盖已有凭证、不泄漏 SecretKey/SignKey；`.env` 四项完整配置优先，留空时正确回退到 queue sidecar。
- sidecar 写入使用安全路径、临时文件与原子替换；重启读取成功；损坏记录报错而非静默丢弃。
- 未登录页面进入登录流程；错误密码拒绝；正确密码发 HttpOnly 会话；API、WebSocket 在登录后可用；会话重启后仍有效且没有自动过期，登出后立即失效并清理 Cookie；匿名 API/WS 为 401；响应无 Basic challenge；Bearer CLI 仍通过。
- 恶意/跨站 Origin、跨站 Fetch Metadata、登录暴力尝试、伪造 Cookie、Secret 回显和日志泄漏均有回归覆盖。
- 全模块测试、vet、可用的 race 检查、Node UI 测试、Windows/Linux AMD64/Linux ARM64 构建和独立发布包校验完成后交付；真实百度 OAuth、NAS/SMB 与目标浏览器仍单独标注待验收。

## 实现约束与剩余细节

- 立即生效是明确需求，不能以提示重启替代。实现需提供凭证管理器与授权服务器的安全重配置入口；持久化成功与运行态更新要有清楚的失败恢复语义，避免出现磁盘已保存但内存仍用旧值，或内存已更新但持久化失败的状态。配置首次保存成功后即锁定，不能通过网页再次修改。
- 管理员会话没有自动过期，服务端撤销状态必须持久化，登出需同时撤销服务端会话并清理当前浏览器 Cookie。实现采用 SQLite 会话记录，记录随机会话标识的哈希、创建时间、撤销时间；不得记录 Cookie 明文。手动清理 Cookie 只会让当前浏览器停止携带该凭据，服务端记录继续保留用于审计/拒绝重放；通过停止服务后运行 `-revoke-admin-sessions` 撤销全部网页会话。
- 删除 `baidu-app.json` 是网页配置的本地重置方式；若凭证文件中记有不同 AppKey，仍需按本地恢复说明清理旧 OAuth 凭证后重新授权，但保留账号绑定和下载任务记录。
- 持久且无限期会话意味着浏览器 Cookie 被复制或设备丢失时风险持续到显式撤销。管理界面提供当前会话登出；管理员可通过 CLI 全局撤销，撤销记录保留在 SQLite。
