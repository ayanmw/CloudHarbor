# 网盘移动目标目录选择器

## 意图

网盘管理页当前要求用户在 `prompt` 中手输移动目标绝对路径。改用实时目录选择器，减少路径拼写错误，并让目标目录来自当前百度列表。

## 目标

- 点击文件或目录的“移动”后打开目标选择器，默认定位当前浏览目录。
- 可浏览子目录、返回上级、分页，并明确显示当前将要选择的完整目标路径。
- 只有用户点击“移动到此目录”时才调用现有 `/api/cloud/mutations`；取消、关闭或浏览目录都不产生远端写操作。
- 继续复用现有移动 API、源对象身份复核、下载队列暂停、结果未知隔离和成功后列表/缓存刷新。
- 输入和展示的远端名称/路径继续 HTML 转义；过期目录读取响应不得覆盖最新选择。

## 方案与取舍

1. 保留自由文本输入：改动小，但拼写错误和路径格式问题仍由用户承担。
2. 使用实时目录选择器：以现有分页列表逐层导航，只通过经过读取的目录路径选目标；增加少量 UI 状态，但不改 API 或远端语义。**采用此方案**，更符合网盘文件管理页面的操作方式，并保持“浏览只读、最终按钮才写入”的边界。
3. 选择器加路径搜索：大目录中跳转更快，但扩大交互/API 范围；当前目录分页已足够，先不增加。

## 安全与行为约束

- 目录列表使用现有受保护 GET `/api/cloud?dir=...&offset=...&limit=...`。
- 目标仍由现有服务端验证；UI 不绕过对象身份校验或队列维护锁。
- 目录层级冲突、移动到自身/后代等情况仍由后端规则拒绝。
- 不支持上传，不新增远端操作类型，不自动提交。

## 验收

- 选择器默认显示当前目录；分页、子目录导航和上一级路径正确。
- 选择目标前不会调用 mutation；取消或关闭不会写入；确认后只调用一次 mutation，body 的源身份与所选目标路径准确。
- 列表请求失败显示安全错误，旧请求迟到时不会覆盖当前目录；恶意名称按文本显示。
- WebUI、全仓 Go/vet、userscript、Windows/Linux AMD64/Linux ARM64 构建及发布 ZIP 校验通过；真实账号仅可做目录读取验证，不执行移动。
