# 目录刷新明细检索与导出设计

## 目的

在 `.93` 已能按需分页查看单次目录刷新明细的基础上，补齐筛选、检索、统计、导出和复制能力，使用户能从大量变化记录中定位对象并留存单目录证据。该主题合并为一个预览批次，不新增刷新或百度远端写操作。

## 五项独立交付

1. **按变化类型筛选**：新增、删除、元数据变化、身份变化可独立筛选；页码和游标随筛选条件重置。
2. **按对象检索**：关键字匹配旧/新快照的完整路径、名称或 fs_id；大小写不敏感，按路径/名称子串或 fs_id 十进制文本匹配；最多 128 个 Unicode 码点。
3. **显示事件完整分类计数**：在明细面板展示该目录事件全部变更的分类计数和总数，不受当前类型/关键字筛选影响，并标出筛选命中数。
4. **导出单目录明细**：用户显式点击后导出所选 run/event 与当前筛选匹配的完整快照 JSON；同一 SQLite 只读快照，最多 5,000 条，超限整份拒绝；无账号指纹。
5. **复制对象核对信息**：旧/新快照分别提供复制路径和 fs_id；无安全上下文剪贴板权限时显示可理解的失败提示，不把复制误报为成功。

## 方案与取舍

- 仅在浏览器已加载的 50 条内筛选/搜索实现简单，但会漏掉后续页结果，也不能准确显示完整分类计数，因此不采用。
- 在 SQLite 对已持久化快照做服务端筛选与检索，保留稳定游标，并以只读快照导出，结果完整且与现有账号隔离模式一致；这是本设计采用的方案。
- 新增可搜索列和迁移索引可优化超大变化事件的文本搜索，但需要额外 schema 与回填。首版先用事件序号索引定位单事件，再对其有限变化行读取并匹配 JSON 快照；若真实数据规模证明不足，再按测量结果优化。

## 接口与数据约束

- 现有 `GET /api/cloud-inventory/refresh/changes` 接受可选 `kind` 和 `q`，继续要求 run/event 与账号身份匹配；拒绝重复/未知参数、非法类型和超长查询。
- 分页游标限定在同一 run/event/kind/query，任何筛选改变时前端回到第一页并忽略旧响应。
- 响应包含该事件未筛选的分类计数、全部总数、匹配总数、当前页和下一游标；总数不得由已加载页面推算。
- `GET /api/cloud-inventory/refresh/changes/export` 使用相同筛选；单一只读 SQLite 事务读取事件和全部命中明细，超过 5,000 条拒绝整份。远端路径/名称作为数据编码，不执行。
- API/导出不返回账号指纹；时间仍区分本机记录 UTC 与百度目录观测 UTC。
- 复制按钮只写入本机剪贴板，不触发网络请求。

## 非目标

- 不发起刷新、不访问百度、不改变缓存和队列、不改动明细 append-only 记录。
- 不新增数据库 schema；不扩大既有整轮运行导出的内容或上限。
- 不对历史 `.93` 包回溯修改。

## 验收

- Store/API 覆盖类型筛选、Unicode 查询、路径/名称/fs_id 匹配、稳定分页、完整计数不随筛选改变、账户/run/event 隔离、错误参数和空结果。
- 导出覆盖全命中集合、筛选一致、UTC/旧新快照证据、指纹隐私、5,000 边界和超限原子拒绝。
- WebUI 覆盖筛选/搜索重置游标、跨页保留筛选、迟到响应忽略、空/错误状态、转义、显式下载和剪贴板成功/失败。
- 完成后再以五项门槛确定 `v0.8.30-preview.94`；全仓 Go 测试/vet、WebUI/userscript、三平台构建和 ZIP/来源快照/私有数据核验通过。上述实现门禁使用本机 SQLite/mock。打包后另按用户既有授权进行真实账号只读启动/空目录刷新冒烟；结果见 releases 同级验证记录，不以此声称非空明细已在真实账号上验收。NAS/SMB 未验收。
