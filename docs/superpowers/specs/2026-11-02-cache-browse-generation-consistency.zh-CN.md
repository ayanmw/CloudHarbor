# 本地缓存浏览分页代次一致性

## 背景

网盘目录的本地缓存会被全盘扫描、局部刷新和已确认的远端操作更新。缓存浏览与搜索使用 offset 分页；如果用户在翻页期间缓存变化，后续页可能跳过或重复条目，页面也可能把迟到的旧响应渲染到新目录上。

## 目标

让本地缓存目录浏览和搜索的连续分页绑定同一个 SQLite 缓存代次。代次变化时拒绝旧页，页面回到第一页读取最新缓存，并保留明确的提示。

## 决策

- 复用 SQLite 已有的账号级单调 `cloud_inventory_generations.generation`，不新增迁移或持久化游标。
- 本地缓存列表和搜索响应返回 `cache_generation`；下一页请求可附带同名参数。
- 如果请求代次与 SQLite 当前代次不同，返回 HTTP 409 和固定代码 `cache_generation_changed`，不返回旧分页数据。
- 当前页条目、分页总数、目录大小和代次从同一 SQLite 只读快照读取。大小缓存命中/重算仍可在该事务中完成。
- 页面只在缓存目录/搜索的第一页建立代次；后续页携带代次。收到 409 后清除旧代次、回到第一页，并提示缓存已更新。
- 丢弃不属于当前浏览请求、目录、模式或代次的迟到响应。实时百度分页契约不变。
- 本地缓存代次只说明 SQLite 内容一致性，不表示百度端原子快照，也不替代目录的 `complete/stale` 覆盖状态。

## 验收标准

1. 同一代次内，目录和搜索分页返回既有稳定排序与结果。
2. 缓存发生变化后携带旧代次请求返回 409，包含新代次且没有条目负载。
3. 页数据、总数、目录大小与响应代次来自同一个 SQLite 事务快照。
4. 页面在缓存代次冲突后自动回到第一页，只提示一次且不会循环重试。
5. 慢旧请求在切换目录、搜索词、浏览模式或代次后完成时，不覆盖当前页面。

不改变百度远端操作、扫描调度、缓存失效和未知结果隔离规则。
