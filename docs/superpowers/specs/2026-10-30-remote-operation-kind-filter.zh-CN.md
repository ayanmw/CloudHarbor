# 远端操作历史按类型筛选设计

## 目标

在管理页远端操作历史中按 `mkdir`、`move`、`rename`、`delete` 筛选，方便从长期记录中定位对应操作；当前筛选同时适用于分页结果和摘要 JSON 导出。

## 方案

- 类型筛选是本地 SQLite 历史查询的可选条件，不访问百度 API，也不改变任何远端或本地队列状态。
- Store 对 `remote_operations.operation_kind` 使用参数化等值条件，并与现有状态、关键字和 UTC 时间条件组合。
- API 只接受四种已支持的操作类型；空值表示全部类型，其他值返回 400。
- 网页在历史筛选栏增加操作类型选项；搜索、自动应用筛选和清空操作都保持一致。摘要导出带上当前类型筛选，导出元数据也记录它。

## 验收

- Store 对每种合法类型按 `operation_kind` 过滤；不存在的类型被拒绝。
- API 将类型条件传给 Store，拒绝未知值；摘要导出保留筛选条件。
- WebUI 请求列表及导出时都发送所选类型，清空后请求不再带类型参数。
- 全仓 Go 测试、`go vet`、WebUI/userscript 测试及三平台打包通过。

## 不在范围内

- 不添加批量远端操作、unknown 放行或重发入口。
- 不改 SQLite schema；现有操作类型列为 `operation_kind`。
