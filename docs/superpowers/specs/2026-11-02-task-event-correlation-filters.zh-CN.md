# 下载任务事件关联 ID 筛选

## 意图

同一下载任务会跨多次尝试，也可能执行源项移动/删除等网盘后处理。现有事件时间线可按事件类型和本机 UTC 日期筛选，但排查某次具体下载尝试或远端操作时，仍要手动浏览事件并比对 ID。扩展现有时间线，让用户按事件中的 `attempt_id` 或 `operation_id` 精确聚焦关联证据。

## 目标与批次

1. Store/API 支持精确 `operation_id` 筛选，并与任务 ID、事件类型和 UTC 日期条件组合。
2. Store/API 支持精确 `attempt_id` 筛选，并与其他条件组合。
3. 事件卡片显示关联 ID 的明确操作，点击后将该 ID 带入筛选并从最新匹配事件开始浏览。
4. 关联 ID、类型和日期筛选共享同一个匹配总数及稳定 sequence 分页；刷新和较新/较旧翻页保留全部条件。
5. 用户显式导出时复用全部筛选条件，同一 SQLite 只读快照最多 100 条，超限整份拒绝并继续遮蔽敏感证据。

## 非目标

- 不新增跨任务全局搜索或远端操作历史页面功能。
- 不改变下载任务状态、调用百度 API、执行远端写入或自动重试。
- 不新增 SQLite 列、表或迁移；不改变既有 event sequence、全量导出上限或 UTC 字段语义。
- 不对 ID 做模糊匹配、前缀匹配或大小写转换。

## 方案与取舍

1. **只在当前已加载页筛选。** 不改 Store/API，但事件跨页时会漏项，匹配总数及导出也不准确，因此不采用。
2. **另建相关操作搜索页。** 可以集中搜索，但会复制事件时间线、分页和导出流程，并混合跨任务边界；本次仍围绕已有单任务时间线，因此不采用。
3. **扩展现有单任务 SQLite 查询和事件卡片。** Store 对 `operation_id` / `attempt_id` 使用参数化精确等值条件，原只读事务同时计算 count 和 page；卡片上的显式操作保留类型/日期条件并回到最新匹配页。无新 schema，沿用当前接口和脱敏规则，改动集中，采用此方案。

## 行为与输入规则

- 查询参数为可选 `operation_id`、`attempt_id`；只接受各一个值，单值 UTF-8 长度为 1..128 字节，不允许首尾空白或控制字符。非法/重复/未知参数返回 HTTP 400。
- 两个 ID 同时提供时以 AND 精确匹配；空值表示未启用该条件。Store 参数化 SQL，不拼接用户提供的值。
- 查询始终限定指定 task ID，事件、总数、sequence 页从同一 SQLite 只读事务返回。
- 点击某条事件的操作/尝试 ID 时仅设置被点击的 ID，清除另一个关联 ID；现有事件类型和 UTC 日期筛选保留。筛选条件更改后回到最新页并废弃迟到响应。
- 分页、手动刷新与导出保留 operation/attempt 两项条件。导出仍显式点击、最多 100 条、超限整份拒绝、`Cache-Control: no-store` 和现有递归字段遮蔽不变。
- ID 对应的事件不存在时返回空结果与 0 命中，不改变 404 规则；task 不存在仍为 404，Store 不可读仍为 503。

## 验收

- Store：operation、attempt、二者 AND、与 kind/date 组合、错误输入、不同任务隔离、零命中、稳定分页，以及 ID 筛选导出 100/101 边界。
- API：ID 长度/空白/控制字符/重复/未知参数校验、同一条件计数和导出、默认兼容、404/413/503 语义。
- WebUI：ID 控件保真、事件卡片 ID 操作、安全转义、只重置关联 ID、保留类型/日期、刷新/翻页/导出携带两类 ID、迟到响应保护。
- 发布：全仓 Go 测试/vet、WebUI/userscript、Windows AMD64/Linux AMD64/Linux ARM64 构建、ZIP 载荷哈希和私有状态数据检查。

## 执行约束

- 在主 checkout 内联实现；不使用 worktree、不提交或推送。
- 保留现有真实账号状态目录；包完成并验证前不停止/迁移 `.144` 运行状态。
- 只读健康/SQLite 本地状态检查，不执行百度请求、下载、远端写入、NAS/SMB 测试或历史目录清理。
