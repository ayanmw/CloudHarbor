# 局部目录刷新历史与请求额度审计补齐

## 目标

让局部目录刷新运行历史可靠呈现本轮范围、累计请求预留和重试/暂停/额度追加过程。当前状态、可筛选运行列表、事件页和 JSON 导出均从同一持久化来源读回；运行中的请求预留必须与摘要原子更新。请求预留代表“发起 GET 前已消耗额度”，崩溃窗口仍可能使其高于实际 HTTP 数量。

## 现状证据

- `cloud_inventory_refresh_state` 持有当前检查点和请求额度。
- `ReserveCloudInventoryRefreshRequest` 事务只更新状态表；历史运行列表从事件表推导，因而运行中的请求数与最近事件快照可能落后。
- 局部刷新没有专用 run 摘要表；其事件不包含持久化重试截止字段，重试调度也没有独立事件类型。
- 额度耗尽当前记为通用 `paused` 事件；恢复事件仅有累计额度快照，无法直接看出本次追加量。
- 全盘扫描已使用 `cloud_scan_runs` 投影并在请求预留事务中更新用量，可作为本地实现模式。

## 采用方案

新增 `cloud_inventory_refresh_runs` 可变摘要投影，按账号/run 唯一。字段包括不可变根目录与开始时间，以及最新状态、阶段、当前目录、页/条目/待扫计数、请求额度/预留数、最近更新时间和错误。SQLite schema 32 迁移从旧事件回填所有历史运行；能取得的旧值来自开始事件和最后事件，不能推断的内容保留已有证据。

状态转换、请求预留、追加额度及摘要投影在同一 SQLite 事务更新；追加事件仍 append-only。新增 `retry_scheduled` 与 `request_budget_reached` 事件类型，事件行保存本次重试截止和本次追加额度数量（不适用时为 NULL/0）。历史列表和摘要导出读取投影，事件/证据导出保留完整追加事件。

页面明确显示根目录范围、累计额度、已预留数、最近本机记录 UTC；事件详细说明退避等待截止、额度耗尽及本次追加数量。继续沿用 SQLite-only 历史查询，不对百度发请求。

## 独立用户结果与验收

1. 运行列表/摘要导出展示根目录和累计请求额度；旧事件回填后仍能读取历史。
2. 每次请求额度预留同事务更新运行摘要；关闭重开后状态、运行列表和导出一致。
3. 暂时失败排定重试时追加 `retry_scheduled` 事件，精确保留本机 UTC 截止与错误摘要；不把本机计划标成百度观测时间。
4. 额度耗尽追加专属 `request_budget_reached` 事件，并保持检查点和旧发布缓存；不发送超额 GET。
5. 恢复时记录本次追加额度数量，运行列表/事件页/证据 JSON 均展示累计额度与追加证据。

所有写入验证事务失败原子回滚、事件只追加、跨账号隔离、迁移旧 sequence/索引/trigger、SQLite 关闭重开及预算 N 最多 N 个 GET。运行历史的网络请求字段一律标注为耐久预留数，不声称与已发送 HTTP 一一对应。

## 非目标

- 不改变全盘扫描额度、自动重试分类、指数退避或百度请求节流。
- 不根据网盘内容推断远端变更成功；不涉及远端写入、自动解除 unknown、真实账号和 NAS/SMB 验收。
- 不记录每个 GET 的单独事件行，避免把高频请求变成无界事件流；当前总量由事务性摘要投影提供。
