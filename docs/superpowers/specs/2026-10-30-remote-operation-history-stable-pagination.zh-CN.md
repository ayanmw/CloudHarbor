# 远端操作历史稳定游标分页

## 背景

独立只读远端操作历史页已支持筛选和 offset 分页。用户翻页期间若有新操作插入列表顶部，后续 offset 会整体偏移，可能重复或跳过历史记录。历史记录按创建时间及操作 ID 已有稳定排序键，可以使用 keyset 游标续页。

## 目标

- 历史页使用 `(created_at_utc, operation_id)` 游标加载下一页，顶部新增记录不改变已浏览的页边界。
- 保持当前筛选条件不变，上一页/下一页可以往返浏览。
- 保留现有 offset API 行为，兼容既有调用方；offset 与游标参数不能混用。
- 每次响应的匹配总数表示该次查询时的实时总数，不承诺跨多页固定快照。

## 方案

在 SQLite 查询中按 `(created_at_utc, operation_id)` 降序排序。游标页使用严格小于最后一条记录的键值读取 `limit+1` 行，并在单个只读事务内读取当前筛选总数及页面。接口返回下一页游标。前端为已访问页保存游标栈，筛选、刷新时清空游标并从第一页开始。

保留 offset 模式以兼容现有客户端；新历史页切换到游标模式。相比固定导出/临时快照表，此方案不增加数据库迁移、状态表或清理策略，并能抵御常见的新记录头插导致的分页漂移。

## 边界

- 只读本地 SQLite，不调用百度 API，不改变网盘、下载队列或操作状态。
- 操作记录不删除；若状态筛选下既有记录状态发生变化，实时筛选结果仍可能变化。
- `total` 是实时计数，不是第一页时冻结的快照总数。
- `unknown` 仍显示为隔离状态；不增加重发、放行、删除入口。

## 验收

- Store：游标边界严格、不重不漏、同一时间戳以 operation ID 稳定排序、筛选和账户绑定语义不变、空页/非法游标处理正确；插入更新排序头部的新记录后，旧游标仍从原边界继续。
- API：合法游标返回下一游标；参数缺失、重复、格式错误以及与 offset 混用返回 400；offset 旧调用仍可用。
- UI：首屏、下一页、上一页、筛选、清空和刷新正确重置/复用游标；翻页期间新增一条顶部操作时不重复旧页末项；计数文案说明为实时匹配总数。
- 全仓 Go 测试/vet、WebUI/userscript、三平台构建、ZIP 哈希/来源快照/私有数据检查通过。
- 不执行真实账号写操作。
