# 管理员会话失效后的跨页面恢复

## 目标

管理 Cookie 会话失效时，所有受保护页面统一转到登录页，并在登录成功后返回原页面。当前页面的只读请求、表单提交、任务操作和文件导出均不得在登录后自动重放。

## 已核实的问题

1. `/operations` 的列表、事件和导出请求，以及 `/cloud` 的目录刷新明细/运行/筛选导出，把 HTTP 401 当作普通错误展示，页面不跳转登录。
2. 入队页只提示管理员登录失效并要求手动刷新，登录成功后不会返回原入队页面。
3. OAuth 页的状态读取、应用配置读取/保存和授权操作未统一处理 401；部分错误显示原始服务端响应。
4. 任务页的任务操作、扫描、任务事件、任务状态读取和账号健康检查没有统一处理会话失效；轮询版继续每 2 秒/5 秒请求，WebSocket 版每 3 秒重连。
5. OAuth、云管理和任务列表的后台状态轮询在会话失效后未全部停止。

以上按五个独立页面工作流计入 `.103` 候选。它们共享登录恢复目标，但需要分别覆盖各自不同的请求/交互路径。

## 设计

- 在共享前端脚本提供一次性会话失效处理：根据 `location.pathname + location.search` 构造 `/login?next=...`，跳转后返回简短中文提示。
- 复用登录页现有 `next` 校验和同源导航，不改变 Cookie、Bearer CLI、服务端会话时长或登录限流策略。
- 列表、OAuth 配置等读取收到 401 时触发统一跳转；写操作或导出收到 401 时只触发跳转并终止本次交互，不自动重试。
- OAuth 状态轮询遇到 401 后停止定时器；其他非 401 暂时错误继续按当前行为展示/重试。
- 所有受保护任务页/API 读取遇到 401 时停止对应轮询；WebSocket 版取消重连，云管理页清理扫描、目录刷新、重复扫描状态及迁移轮询计时器。
- 保留其他 HTTP 状态码现有错误处理和已实现的 `/cloud` 会话恢复行为。

## 验收

- 五个页面工作流分别有回归覆盖，断言登录地址包含编码后的当前页面路径/查询参数。
- 同一页面多个并发 401 只触发一次导航。
- OAuth 状态 401 后定时轮询不再请求；主动重试不会自动重复任何受保护写操作。
- Web UI 回归、全仓 Go 测试、`go vet`、userscript 回归及三平台发布包门禁通过。
- 仅本机自动化验证，不声称真实百度或 NAS/SMB 验收。
