# 全局任务事件历史

## 目标

提供独立的全局只读任务事件历史页，使管理员无需逐个展开任务，即可跨任务定位下载、队列和源操作事件，并导出有限范围内的脱敏证据。

## 方案选择

- 在每个任务卡片中增加跨任务切换：与单任务模型不匹配，任务列表仍是进入历史的前置步骤。
- **新增独立全局历史页（采用）**：复用 SQLite 追加事件和管理会话，提供固定快照、组合筛选和有界导出；不与实时下载状态轮询耦合。
- 在 `/api/status` 中嵌入事件：会扩大高频状态响应并把审计查询和下载队列轮询绑定，不采用。

## 用户结果与验收

1. 新增管理员保护的全局事件页/API；读取现有 SQLite `job_events`，展示 task ID、事件 sequence、类型、记录 UTC 时间、关联 ID 和递归脱敏证据，不触发百度 API 或队列变更。
2. 同一查询可组合 task ID、固定事件类型、operation ID、attempt ID、UTC 日期范围或精确 RFC3339 时间范围；日期与精确范围互斥，使用 `recorded_at_utc` 的左闭右开语义。
3. 当前非类型筛选范围返回事件类型命中数和总数，与事件页使用同一只读 SQLite 事务快照；类型快捷筛选保留其他条件。
4. 首页确定 `as_of_sequence`；后续翻页以该序号上界和 `before_sequence` 游标读取旧记录，新增事件不会改写当前浏览结果、总数或类型计数。
5. 页面支持当前条件下的完整 JSON 证据导出，最多 1,000 条，超限整批拒绝；导出记录过滤摘要、UTC 生成时间和 `as_of_sequence`，响应使用 `Cache-Control: no-store`。

## 数据库与接口约束

- SQLite schema 从 v38 升至 v39，只新增事件查询索引，不修改、回填或删除历史事件。
- 为本页常用的 task ID、类型、操作 ID、尝试 ID 和记录时间查询创建可验证的索引；继续使用事件表全局自增 sequence 做稳定顺序。
- 首次读取的 `as_of_sequence`、计数、类型计数和页面数据必须来自同一只读 SQLite 事务；后续请求必须传回该上界。
- 游标和 `as_of_sequence` 为非负十进制整数；若 `before_sequence` 大于上界、或上界大于数据库当前最大 sequence，拒绝请求。
- 导出使用公共事件 DTO；不得序列化 SQLite 账号/内部 scope 信息。证据沿用现有递归遮蔽。
- 所有路由由现有管理会话保护；缺失/失效登录状态走既有登录页，不提供匿名入口。

## 不在范围内

- 事件删除、修改、保留期清理、全文搜索或新建事件。
- 访问百度网盘、改变任务/队列/缓存状态，或通过历史页执行重试/移动/删除。
- 改造已有单任务事件页的筛选语义。

## 验收边界

- Store/API/UI 自动化、SQLite v38→v39 迁移/崩溃恢复、索引查询计划和三平台打包验证本地实现。
- 真实任务历史体验仅在真实账号后续产生事件后进行；本批不运行下载或远端写操作。NAS/SMB 不影响本地 SQLite 历史页，不作为本批验收依据。
