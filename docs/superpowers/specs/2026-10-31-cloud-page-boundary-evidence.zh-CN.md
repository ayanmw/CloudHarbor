# 云目录分页边界证据

## 目的

减少全盘扫描和指定目录刷新在偏移分页期间因远端目录变化而静默漏项的情况，并保证暂停、崩溃和重启恢复后仍执行相同的边界核验。当前客户端每页请求 `limit+1` 条，仅返回前 `limit` 条；多取的一条只用于判断是否还有下一页，身份被丢弃。

## 目标

- 将每页多取的一条文件作为下一页边界预期，不增加百度 API 请求次数。
- 将边界对象完整身份保存在 SQLite 扫描状态；当前页与边界证据、偏移检查点在同一事务提交。
- 继续扫描时要求新页首项与已保存边界一致（fs_id、路径、名称、类型、大小、provider mtime、可用 MD5）。不一致时失败关闭，不提交该页，不发布目录 complete。
- 全盘扫描和目录局部刷新使用相同规则；停止后重启继续时保留边界证据。
- 旧 SQLite 状态迁移时边界为空。偏移大于 0 但没有边界的旧检查点必须从该目录偏移 0 重新开始，避免无证据地跨越已有页边界。

## 非目标与边界

- 不声称百度提供原子快照，也不声称边界身份相同即可证明任意并发变化下完整。
- 不自动重扫整个目录，不提高每页请求数，不改变远端操作身份复核和扫描互斥。
- 此规则只能发现边界对象发生替换、改变或消失的可观察漂移。对边界对象不变的并发编辑，仍须保留“扫描期间页面观测，不是单一远端时刻”的解释。

## 方案

采用现有 `limit+1` 响应中的 lookahead identity，在 SQLite 同页事务里保存为下个 offset 的边界。通过同页前后完整身份比较发现跨页漂移；发现漂移时保留先前已提交页，但目录保持不完整，允许重新启动该目录扫描。独立额外请求会增加限流和耗时，故不采用。

## 验收

- 百度 API client 回归证明边界对象来自现有多取一条响应，且没有额外 HTTP 调用。
- 全盘扫描与目录刷新模拟第二页边界对象被插入、删除或身份改变；都必须失败关闭且目录不可 complete。
- SQLite close/reopen 后仍执行同一核验；旧 schema 升级后的非零偏移检查点不在缺少边界证据时继续。
- SQLite 页数据、next offset、boundary 与状态事务一致；失败提交不得只保存其中一部分。
- 全仓 Go 测试/vet、WebUI/userscript、迁移恢复和打包门禁通过。
