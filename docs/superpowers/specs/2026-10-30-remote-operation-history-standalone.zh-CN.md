# 独立只读远端操作历史页

## 背景

当前远端操作历史已支持本地 SQLite 分页、状态/类型/关键字/时间筛选、摘要 JSON 导出、单笔事件查看和脱敏证据导出，但入口嵌在网盘管理页的折叠区。只需审阅历史时，用户仍要进入同时含远端文件变更入口的页面。

## 目标

- 新增独立 `/operations` 管理页面，只展示远端操作历史。
- 网盘管理页提供“只读操作历史”入口；下载任务/其他导航提供合理返回链接。
- 独立页复用现有筛选、分页、事件详情和摘要/单笔证据导出。
- 未知结果仍明确显示隔离；页面不提供重发、放行、历史清除或任何网盘写操作。
- API 和 SQLite schema 不变，页面读取仍只访问当前下载目录绑定的本地 SQLite。

## 方案

将远端历史区迁移到独立嵌入式 HTML 页面，继续使用现有 `cloud_operations.js` 和受保护 GET API。网盘管理页移除历史折叠区和专属脚本引用，只保留独立页入口。这样不会复制第二套交互状态，也不会让只读历史入口暴露网盘变更控件。

独立页默认直接呈现筛选与列表；初始加载只访问本地操作历史 GET。状态/类型/关键字/时间过滤、分页和导出仍走已有 API。保留同源会话认证、登出按钮和用户输入/证据的现有转义方式。

## 非目标与安全边界

- 不新增远端 API、数据库字段或历史记录保留/删除策略。
- 不改变网盘管理页文件浏览、队列暂停、mkdir/move/rename/delete 的行为。
- 不访问百度 provider，不修改网盘对象，不允许人工处理 unknown。

## 验收

- `/operations` 返回独立历史页；其内容包含既有筛选/分页/导出和退出登录，不包含文件浏览或网盘写操作控件。
- `/cloud` 可通过明显链接打开 `/operations`；页面自身能返回网盘管理。
- 独立页加载会触发受保护 SQLite 历史 GET；列表、筛选、分页、事件详情和导出回归继续通过。
- 包含路由/嵌入资源的全仓 Go 测试、WebUI/userscript、三平台构建和 ZIP 私有数据门禁通过。
