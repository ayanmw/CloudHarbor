# 缓存变化后刷新不完整目录清单

## 背景

不完整目录清单按需从 SQLite 读取。用户加载清单后，完成一次局部缓存刷新或成功执行网盘远端变更，当前页面可能继续显示旧 generation 与旧路径，直到手动点“刷新记录”。

## 目标

当本页可确认缓存已更新时，若不完整目录清单已加载，则自动从 SQLite 第一页重读。保持用户当前原因筛选与路径搜索；不完整清单的刷新不得额外调用百度 API。

## 决策

- 本页关联的局部刷新进入 `complete` 后，刷新已加载的不完整目录清单。完成 run ID 处理后即解除关联，2 秒状态轮询不会重复刷新。
- 远端变更 API 成功返回后，刷新已加载的不完整目录清单；请求失败不将其当作缓存变更，不额外刷新此清单。
- 重读使用当前页面筛选控件值，游标及旧 generation 清空，从第一页获取最新快照；既有 generation 冲突恢复逻辑继续生效。
- 该清单请求只访问 `/api/cloud-inventory/incomplete-directories`。远端操作原有浏览器列表刷新行为不变。
- 不增加服务端 API、SQLite schema、后台轮询或隐式百度请求。

## 验收标准

1. 已加载清单时，本页局部刷新完成会重读一次清单；未加载时不发请求。
2. 后续重复状态轮询不会重复刷新已完成 run 的清单。
3. 清单重读保留原因与路径筛选，清除旧游标和 generation，从第一页开始。
4. 清单自动重读只调用本地 SQLite 读取 API，不调用百度文件列表 API。
5. 远端变更成功后刷新已加载清单；请求失败时不刷新该清单。
6. 未更改刷新协议、远端操作策略、缓存事务和不完整目录判定。
