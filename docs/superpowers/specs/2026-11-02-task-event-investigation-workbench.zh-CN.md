# 任务事件调查工作台

## 目标

扩展每个下载任务的只读事件时间线，让用户可以更精确地限定本机记录 UTC 时间、查看锚点事件附近的上下文、了解各事件类型的全量命中数，并快速定位或复制单条脱敏证据。

## 范围

1. 时间筛选支持 UTC 日期兼容项及精确到秒的 RFC3339 时间范围；精确范围采用左闭右开，不能与日期范围混用。
2. 按任务 ID 和正数事件 sequence 读取固定上下文窗口：最多较早 5 条、锚点、较新 5 条；只从该任务读取，全部从同一只读 SQLite 事务取得。锚点不存在返回未找到，不得跨任务返回记录。
3. 在当前筛选（不含事件类型本身）下汇总所有持久化类型的匹配数；各计数与当前页/命中总数使用同一 SQLite 只读快照。类型计数可一键替换类型条件并回到最新匹配页。
4. 事件卡片可一键改为筛选该事件本机记录 UTC 当日；保留关联 ID 和日期以外的既有条件，清除时间精确范围。
5. 每条事件可复制经现有递归敏感字段遮蔽逻辑处理的 JSON 证据；复制失败显示明确状态，不影响过滤和导出。

## 安全和边界

- 所有查询只读本机 SQLite，不触发百度 API、下载、缓存刷新或远端操作。
- 时间字段仅表示本机记录时间 `recorded_at_utc`；不混用百度发生、云端观察或 HTTP 响应时间。
- 上下文固定最多 11 条；不能由请求参数扩大。
- 类型汇总固定由源码事件类型白名单生成；未知历史类型保持可见为“其他/未识别”或不计入可筛选项，不把任意数据库值当作安全的可过滤输入。
- 复制与上下文均复用事件导出脱敏规则；绝不把账号凭证或账号指纹加入新 DTO。

## 验收

- UTC 精确时间过滤的边界包含/排除、无效/混用参数、分页、导出均有 Store/API 回归。
- 上下文覆盖首尾边界、错任务锚点、缺失锚点、固定 11 条上限及返回顺序，并验证只读快照。
- 类型汇总覆盖零值类型和混合筛选，结果与相同 SQLite 快照一致。
- WebUI 回归覆盖新时间条件跨页/刷新/导出、类型计数过滤、当天快捷筛选、复制成功/失败及上下文窗口状态。
- 全仓 Go 测试、vet、WebUI、userscript、三平台打包、ZIP/SHA/source snapshot 通过。

## 明确不做

不增加 schema，不新增全局跨任务事件页，不改变事件写入、不自动导出、不读取云端、不执行远端操作。
