# 自动监控列表请求退避与重启恢复

## 目标

百度自动监控目录列表请求遇到可重试错误时，尊重 `Retry-After` 并采用有上限的指数退避；将账号隔离的截止 UTC 持久化到 SQLite，重启后继续遵守；请求成功后清除旧退避。退避期间扫描触发不调用百度 API。`/api/health` 和任务页展示下次自动重试时间。

## 规则

1. 只针对自动队列监控目录的 `ListDir` 可重试失败退避；其它扫描和远端写操作行为不变。
2. 本地等待从 30 秒开始指数增长，封顶 15 分钟；`APIError.RetryAfter` 优先于本地等待，最终等待最多 1 小时。
3. SQLite 状态按稳定账号指纹隔离，保存失败次数、固定错误码、等待毫秒、绝对 `retry_at_utc` 和本机 `updated_at_utc`。不写入错误原文，不向 API 暴露账号指纹。
4. 下一轮在调用百度前检查状态；未到期则返回扫描 skip，不创建虚假扫描历史，不访问百度。
5. 百度目录列表成功后清除退避；不可重试失败不保留退避。升级前失败没有截止证据，schema 迁移不推断或回填。
6. 健康 API 显示 retry UTC 与剩余秒数，并将 `next_scan_time` 指向该截止时间；页面说明正在等待自动重试。

## 非目标

- 不改变 30 秒后台轮询 tick，不改变手动“立即扫描”的调用入口；调用仍受 Downloader 的持久冷却门禁。
- 不对下载、移动、删除或其它网盘写请求自动重试。
- 不把 provider 原始错误文本写入历史/API/UI。
- 本机 mock 不代表真实百度限流策略或 NAS/SMB 验收。

## 验收

- SQLite v40→v41 原子新增状态表，升级无历史推断、跨重启读回、账号隔离和成功清除。
- 可重试 503 能保留 `Retry-After`；冷却内重复扫描没有额外 provider 请求；到期成功清除状态。
- 指数退避、上限、不可重试失败分类和 `Retry-After` 上限有回归。
- health JSON 与任务页呈现同一绝对 UTC；正常、失败和扫描历史语义不被混淆。
- 全仓 Go 测试/vet、WebUI/userscript、三平台构建及发布 ZIP/source snapshot 检查。
- 真实状态目录启动验收只读 health/UI/SQLite，不主动启动全盘扫描，不做下载和远端写操作。
