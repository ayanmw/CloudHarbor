# 网盘库存页批量 upsert 设计

## 意图

降低全盘扫描将远端目录页写入本地 SQLite 时的语句执行开销。当前每个提供方页通常最多包含 100 项，代码已在事务内复用预编译语句，但仍逐项调用 SQLite。Windows 本机基准约为 10–12 ms/100 项；该数据只用于本地前后对照，不代表 NAS/SMB。

## 目标与非目标

- 在单个现有 SQLite 页事务中，以有界多行 INSERT/UPSERT 保存库存项，减少每页 SQL 执行次数。
- 保持 fs_id 冲突更新、目录移动时旧子树清理、完整页 stale reconciliation、扫描队列和 generation 同事务提交。
- 不改变 provider 分页、重启检查点、账号隔离、远端操作、缓存时间或完成性语义。
- 不改变数据库 schema，不引入依赖，不推断目录大小或扫描完成状态。

## 实施方案

- 对唯一 fs_id 的页项按原页序处理目录项；目录之间的连续文件段以多行 upsert 写入，每批最多 80 项，每行 11 个绑定参数，低于 SQLite 常见 999 变量限制。这样旧路径清理与同页目录元数据更新仍保持原有顺序，目录状态写入及待扫描标记仍在同一事务内完成。
- 若 provider 页含重复 fs_id，则退回原顺序逐项 upsert，以保留同一项在页内重复出现时的 last-write-wins 行为。80 项为实现侧安全上限，不更改远端页大小。
- 所有写入、 stale reconciliation、扫描进度与 generation 仍由原页事务整体提交或回滚。

## 验收

- 回归覆盖普通页、混合文件/目录、目录移动和同路径替换、重复 fs_id 顺序、失败回滚、generation 与缓存一致性。
- 本机 benchmark 前后对照报告耗时和分配；若没有稳定收益或出现显著分配/维护成本回退，则撤回批量路径。
- 全 taskstore/项目测试、vet 和独立预览包门禁通过；明确标记真实百度与 NAS/SMB 未验证。
