# 独立 NAS 文件服务与轻量 Client：长期设计草案

日期：2026-11-16。仅规划，不开发、不安装依赖、不复制上游代码、不启动服务。当前活动版仍 v0.8.32；本设计不属于该版交付内容，也未获得下一版切版授权。

## 已确认目标与边界

用户确认单用户、多设备，预留设备级目录权限；多用户与公开分享后置。链路为百度等外部云盘→本站持久文件库↔Client。外部云盘授权不可用时，本站文件仍可独立访问。下游配置只需连接 token 和本地目录；首次默认上游→本地，后续双向另阶段交付。既有百度监控下载保持，不默认将设备改动回传百度。

## 方案比较与推荐

1. 整体 fork AList/OpenList：快速获得多存储浏览，但会引入完整应用框架、第二套权限和升级责任；不能仅凭 WebDAV 能力认定设备同步、删除恢复、幂等证据均已解决。不推荐作为当前主线。
2. 可选外部组件＋本站薄适配（推荐）：保留本站队列、证据、界面；优先评估成熟传输组件，本站只补设备授权、受控文件服务和同步语义。组件按需引入，不强制用户同时安装多个网盘系统。
3. 全部自研：可精确控制，但成本最高；只自行实现项目特有语义，不重写通用传输、预览和协议基础。

以上为技术建议，未做集成原型，不声称复用一定节省工期。实施前以固定提交的小型兼容性验证决定采用组件还是维持现有传输；不先建通用插件框架。

## 两项配置的下游体验

上游：选择发布目录与允许能力→生成“设备连接 token”→复制。建议每台设备一个 token，便于独立撤销；不是要求客户端再填账号、AppKey 或管理员密码。同一 token 多次恢复同一设备时绑定保持，复制到另一设备不静默注册成另一端；可提示上游另建 token。

下游：粘贴连接 token→选择本地目录→展示上游、远端目录、只读／可写与同步方向摘要→连接。默认网盘→本地，不依据首次缺失删除文件；已有同名不同内容保留为冲突，不覆盖。高级设置不作为必填项。

单独随机 Bearer 串不能发现服务器。建议连接 token 采用可复制的版本化连接串，内部携带 HTTPS 上游地址和高熵秘密；这是一项输入，仍然是敏感凭据，不是加密容器。地址不藏第二个手填步骤，客户端解析后明确展示目标；禁止自动向其他 origin 重定向并附带秘密。私网 HTTP 仅在显式确认的可信局域网场景启用，不静默降级 TLS。

服务端只保存秘密摘要、token ID、允许根目录、能力、撤销状态与设备绑定；客户端凭据独立保存，不出现在 URL 查询、日志或同步记录中。每设备 token 与绑定密钥是技术建议，不是用户已指定的协议；密钥生成和绑定全自动，不增加手动配对步骤。之后每次请求校验 token 与绑定凭证，具体协议留实施前细化。首期不强制过期，但必须支持撤销／重置；撤销后后续请求失败，活动传输在下一受控检查点停止。重置设备需上游明确确认，不靠复用秘密自行接管。连接串窃取风险通过 HTTPS、一次展示与设备绑定降低，不宣称绝对防复制。

首期每设备一个发布根与读／写／删除能力即可，不做继承 ACL、角色系统或跨目录权限表达式。权限调整影响旧游标、旧下载链接和未执行操作；执行时重新鉴权，缓存不可越权。根身份变化停止同步，不把换盘当删除。

## 最小内部结构与证据

保留普通目录＋本地持久盘 SQLite；不引入对象存储、分布式队列、微服务、P2P/NAT 中继或虚拟盘驱动。数据源和客户端元数据分开；本站文件有独立 ID／内容版本，不使用百度 fsid 作主键。下载目录接入文件库需用户明确选择，不迁移现有下载或暴露凭据目录。

文件写入在暂存区完成校验后发布。文件替换和 SQLite 提交无法假设同一事务，使用可恢复意图／完成记录，重启只读核对后补齐元数据。变化序号负责同步顺序，UTC 分别记录观察、执行、提交；本地扫描与 API 证据区分。直接文件修改通过扫描收敛；无法确定改名时记录未确认关联，不虚构身份。

API 仅先覆盖受控目录列表、元数据、内容读取、上传会话、基础变更、设备状态及变化分页。明确版本、操作 ID、内容条件和游标过期后的重新建档。回收与删除记录先于删除传播；客户端只在落盘校验与本地日志提交完成后推进游标。回收站与初始同步基线不能仅依赖可过期缓存。

## 发布约束与未定项

阶段计划见同日计划文档。首版完整闭环优先于实现全部 API；平台建议 Windows 为先，需实施范围批准时确认。精确 API 路径、数据库表、组件版本和是否支持跨盘回收留到对应阶段详细设计，不先写用不到的框架。双向同步、分享、多用户均不挤入首版。所有阶段分别报告自动化、真实文件、重启、NAS/SMB与可见 UI 验证，不互相替代。
