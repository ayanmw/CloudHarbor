# 网盘目录局部刷新设计

## 意图

用户在网盘管理页浏览或查看目录大小时，可以刷新当前目录及其子树的本地 SQLite 缓存，不必每次重新扫描整个百度网盘。这样外部客户端造成的远端变化可以在选定范围内同步到本地目录列表和大小缓存。

## 目标

- 在当前目录执行只读递归扫描，分页读取目录内容并更新本地缓存及目录大小。
- 状态、队列、偏移量、页数、项目数、开始/更新时间和错误原因持久化；服务重启后可从检查点继续。
- 子树扫描的缓存状态和队列与全盘扫描分开保存；不能把子树扫描完成伪装为全账号全盘扫描完成。
- 同一账号同一时间只允许运行一种 inventory 扫描；暂停的扫描保留游标，重新开始时续跑。
- 扫描范围内每个目录只在末页成功写入后标记 complete；失败或暂停的部分路径保持 stale/scanning，目录大小显示未完整。
- 当前目录可继续浏览；子树扫描成功后刷新列表和本地聚合大小。
- 目录局部扫描和全盘扫描共用远端 API 节流及 `cloudMutex`；扫描队列中的目录及子树阻止可能破坏分页游标的远端变更。

## 非目标

- 不定时自动扫描，不并行扫描多个目录，不增加上传功能。
- 不重新计算文件 SHA-256，不删除或修改百度网盘内容。
- 不宣称局部扫描完成代表全盘缓存刚刚在同一时刻完成一致性快照。
- 不取代全盘扫描；首次初始化、全账号完整性恢复和用户选择根目录时仍使用全盘扫描。

## 约束与验收

- SQLite 当前 schema 15；新增 schema 16 migration 必须事务安全、向前迁移并校验表/索引及 `PRAGMA integrity_check`。
- Refresh 状态、运行队列、inventory 页写入和检查点推进需要在同一个 SQLite 事务内提交，避免崩溃后游标前进而数据页未落盘。
- SQLite `cloud_inventory_scan_state` 继续只表示全盘任务；新增子树状态用独立表，队列也独立存放。
- 局部扫描开始时将选定目录和已有后代标为 stale，并推进 inventory generation；扫描完成后按每个目录的远端列表恢复该目录 complete。
- 缓存更新仍按 `fs_id` 核验路径/类型；远端对象在扫描期间被移走或替换时由完整父目录列表更新身份，旧子树需 prune，无法证明的目录不得保留为 complete。
- HTTP 接口使用现有管理认证。`POST /api/cloud-inventory/refresh` 接收 `{ "directory": "/path" }`，`GET` 查询最近一次局部刷新状态，`DELETE` 暂停；响应包含刷新根路径和持久化进度。
- 页面提供“刷新此目录及子目录”按钮、单独的局部刷新状态与暂停动作。完成后重新读取当前目录和本地聚合大小；不阻塞网盘浏览。
- 通过标准：store migration/reopen 与事务回滚回归、递归子树扫描及失败/暂停续跑测试、全盘状态隔离测试、API/UI 检查、全仓测试与 vet、跨平台构建和 `.55` 预览包校验。

## 方案比较与选择

1. **只刷新当前目录的直系列表**：改动小、API 调用少，但如果子目录内容有变化，父目录聚合大小仍然过期或必须显示不完整，不满足用户想查看正确目录大小的用途。
2. **为选定路径建立独立持久化子树扫描状态和队列（采用）**：递归更新选中路径及后代，支持限速、暂停、崩溃恢复和精确进度；增加一套 SQLite 状态/队列及页面控制，但全盘状态保持独立、范围最清楚。
3. **复用全盘扫描任务，将当前目录作为新起点**：实现更少，但会混淆全盘 complete 状态、覆盖全盘检查点，并可能让重复项/空目录预览误以为其他目录也已扫描。此方案不采用。

## 实现选择

- 局部任务每账号仅保留最近一次状态；相同路径可续跑，改变路径前必须先让已有任务完成或显式暂停后继续原范围。
- 子树扫描的状态表与队列表分离于全盘状态；共用 page listing 校验、cache upsert、size generation 和远端扫描锁。
- 若全盘扫描持有可续跑队列（running 或 paused），拒绝启动局部刷新；局部刷新未完成时同样拒绝全盘扫描。任务完成或用户暂停后方可启动另一种扫描。
- 局部扫描仅在远端对应目录列表最后一页确认后删除本地未见条目并标记该目录 complete；分页中断保留已有旧条目但状态为不完整。
