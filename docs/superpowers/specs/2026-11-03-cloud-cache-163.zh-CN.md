# .163 缓存扫描工作台

.162已完成并冻结，继续用户最佳推荐持续实施授权，原目录内联，不worktree/自动commit/push。现有文件工作台把高级扫描链接到旧/cloud，本版集中重构缓存构建与刷新管理，避免在多个页面寻找运行状态。

选择`/cloud/cache`独立Vue工作台，复用已有SQLite检查点与scan/refresh API，不改扫描算法、缓存发布事务或频率策略。相比再次拆分数个缓存小版本，本版把全盘与指定目录刷新一并交付；去重、空目录删除与更深历史审计仍保留旧高级入口，不删能力。

五项用户交付：
1. 缓存覆盖与当前运行总览：全盘扫描、指定目录刷新分区，阶段/目录/页数/项目数/剩余量/观察UTC清楚展示。读错保留旧证据，不把无记录当读取失败。
2. 全盘扫描开始/暂停/恢复：默认扫描至完成，有限请求预算仅显式高级选择，明确是工具上限而非百度官方额度。恢复旧有限检查点时不能擅改用户策略。
3. 指定目录及子目录刷新：规范路径确认、根目录全账号范围提示、暂停/恢复及当前目录进度；不清空已有可读缓存，沿已有发布语义。
4. 后台进度与失败恢复：面板可收起，继续浏览文件，单在途轮询；展示服务器计划重试UTC、失败、预算暂停与跨重启检查点来源，不把离线时间或重试等待冒认为扫描工作。
5. 运行证据查看：按固定run_id查看最近运行、关键事件与导出，原始UTC/精确ID与游标，不把最新运行冒认旧运行。完整高级历史/变更明细保留直达入口。

已核实API：GET/POST/DELETE `/api/cloud-inventory/scan` 与 `/refresh`，refresh POST有directory/request_budget/request_limit_mode；两类runs/events/export已接。部分接口有严格query白名单，最小可选字符串精度接线须连同白名单与旧默认兼容验证。具体DTO/阶段/暂停/恢复结果先现场核实，不猜测枚举。

默认完整扫描，不预设未经证实的百度每日配额；遇到明确限流响应或确定规律才降频，既有重试/Retry-After保持。单次确认消费，不自动重发开始/恢复写请求；未知先读回状态，按ID/时间证据核对。pagehide/BFCache/401/迟到隔离。测试只用本机合成状态与mock，不访问真实账号或移动授权，不声称NAS验收。
