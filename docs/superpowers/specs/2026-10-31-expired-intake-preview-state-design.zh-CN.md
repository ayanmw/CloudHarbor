# 入队预检有效期与路径维护互斥设计

## 意图

入队预检只在创建它的进程启动批次、授权 epoch 和两分钟有效期内可提交。当前记录加载后仍以 `preview` 状态显示；重启或授权变化后虽已不能提交，却会继续显示为“预检记录（未提交）”，并因状态不是 `finished` 持续阻止监控目录和本地下载路径修改。

源码审查还发现路径维护检查与入队操作准入没有互斥：`SetManagedPaths` 先检查历史记录、再设置队列维护状态；`startIntake` 不检查该维护状态。预检或提交可在两步之间开始，路径设置也不会等待已准入的入队操作结束。若提交期间切换监控目录，移动请求使用提交开始时捕获的旧目录，而移动结果核验读取当前目录；可能造成已移动项目未进入新目录扫描，且记录进入待核对状态。此类远端结果仍须按未知状态隔离，禁止自动重发。

此外，入队历史保留创建时的 `QueueDir`，但启动加载时要求每条历史记录的 `QueueDir` 必须等于当前监控目录。网页允许修改监控目录而不会重写或删除已完成历史，因此切换目录后重启会因旧记录校验失败而无法启动。未知移动结果的重新核对也通过当前目录查目标，不能可靠核实原目标目录中的文件。

远端网盘管理操作也在取得队列维护状态前读取当前监控目录，并用该值判断能否移动/删除监控目录本身。若路径设置在读取与远端操作进入维护状态之间完成，远端操作可能基于旧目录完成保护判断。路径变更准入必须与路径敏感远端操作共享同一边界，操作使用获取边界后的目录快照。

路径设置自身也在维护准入之前读取当前路径。并发的第二次设置若先读取旧路径、随后在第一次设置释放维护区后才成功取得维护区，仍会用旧本地路径作为迁移源。第二次迁移可能遗漏第一次设置后成为当前目录的文件，造成文件留在未配置的目录中。

## 目标与范围

- 列表 API 将重启、授权 epoch 变化或有效期届满的预检投影为 `expired`，网页明确标记“预检已失效（未提交）”。
- 只有当前启动、当前授权 epoch 且仍在两分钟有效期内的预检继续阻止路径设置；`running` 操作维持阻止。
- 路径维护与预检、提交、重新核对共享一个原子准入边界：路径变更开始后不再接受新的入队操作；路径变更判断与运行中操作不能穿越彼此的临界区。已准入的操作须结束或使路径变更明确失败后，才能切换路径。
- 监控目录在一次入队操作中保持固定；预检记录、移动目标、结果核验和队列注册必须指向同一目录快照。
- 入队记录按其保存的创建时目录进行历史结构校验和远端结果重新核对；有效旧记录不得因当前监控目录变化而阻止程序启动。切换当前监控目录不得改写旧记录或丢失 `unknown` 隔离证据。
- 路径敏感的网盘远端操作在路径维护互斥范围内读取监控目录快照；并发修改路径时，不得使用旧目录错误放行对当前监控目录的移动或删除。
- 每次路径设置取得维护准入后重新读取当前路径，并基于该快照校验/迁移；串行完成的连续设置不得沿用等待前的本地迁移源。
- 提交仍使用现有启动批次、授权 epoch、有效期和源对象重核验；不得让失效预检重新获得提交能力。
- 原始预检文件不改写、不删除；完成记录及 `unknown` 隔离逻辑保持原语义。

## 实现方案

1. **原子维护准入 + 按记录目录校验 + 查询时派生状态（推荐）**：让路径维护、入队操作与路径敏感远端操作使用同一 admission gate。路径变更先封闭相关操作准入，随后在 gate 内重读当前路径、确认没有运行中的远端操作和有效预检，并基于新快照完成设置或迁移；如果不能安全进入维护则明确失败并恢复准入。入队操作从预检到完成或明确停止期间持有其操作准入。一次操作只读取一份监控目录快照并贯穿核验、移动和登记；加载和重新核对历史记录时使用记录自己的 `QueueDir`。记录列表仅对返回副本把失效 `preview` 映射为 `expired`，存储保留原始创建事实。
2. **持久化失效迁移或仅加状态检查**：把失效记录写成 `expired`，或只在 `startIntake` 检查维护标志。前者让读取触发写入并引入迁移/并发语义；后者仍无法封闭“路径检查后、维护标志设置前”的竞态，也不能等待在途操作；均不采用。

采用方案 1，因为 `Boot`、`Epoch` 和 `Expires` 描述的是预检当前能否继续提交的有效性，而不是远端移动结果；查询投影可以如实呈现失效，同时保留创建时的持久化记录。

## 验收

- 同一进程、授权 epoch 相同且未过期：列表仍为 `preview`，路径设置被阻止，提交原行为不变。
- 进程重启、授权 epoch 变化、或有效期已到：列表显示 `expired`；不能提交；路径设置不再被该预检记录阻止。
- 并发交错验证：在路径检查前、维护准入期间及远端移动期间启动预检/提交/核对；任何交错均不能让监控目录在一次操作中变化，也不能让远端已移动项目因核验目录不一致而遗漏登记。路径维护未成功时路径与运行状态保持原值。
- 已生成的历史记录在切换监控目录并关闭、重开程序后仍可加载；旧未知结果重新核对仍只检查原记录目标并保持隔离语义。
- 并发切换监控目录与移动/删除目录操作时，操作必须基于准入后取得的当前目录执行保护校验；当前监控目录不可被路径切换竞态绕过保护。
- 并发发起两次本地下载目录迁移时，后取得准入的请求必须从前一次完成后的当前目录读取/迁移；不能把更早的路径快照当作迁移源。
- 原始 intake JSON 仍保持 `preview` 且未被 GET 改写；`running` 仍阻止路径设置；`finished` 与每项 `unknown` 的现有隔离不变。
- 网页为 `expired` 显示清晰的“已失效、未提交”状态，不提供确认/提交入口；历史排序与分页保持不变。
- 过期状态、路径/入队互斥、历史记录跨目录重启与旧目标核对、路径敏感远端操作互斥、并发本地迁移读取旧源路径分别记录为用户结果；累计达到五项后再编号发布。

## 非目标

- 不删除、清理或重写入队历史。
- 不修改 SQLite 或 JSON 记录格式，不增加后台计时器。
- 不发送百度请求，不移动、不下载、不改变任何远端对象。
