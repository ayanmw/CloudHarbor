# 下载任务暂停/取消状态与耐久性

## 目标

暂停或取消一个目录型队列任务时，目录下载中的子文件/子目录会因共享 context 被取消；根任务和未完成后代目前可能显示互相矛盾的状态。此外，手动取消和重试修改内存状态后若 SQLite 写入失败，没有恢复旧状态。本版同时修复这两类独立问题，并补全取消重试等待任务时丢失的截止时间证据。

## 推荐行为

- 根目录任务的活动尝试收尾后，若持久队列状态仍为 `paused`，检查内存任务视图中的云端路径后代。
- 仅将状态为 `failed` 且错误严格等于 `context canceled` 的后代改为 `paused`；这是现有子项取消路径直接产生的错误文本。
- 用户取消目录任务时，将已有 `paused` 后代以及取消收尾时的 `context canceled` 后代改为 `cancelled`；已完成和真实失败后代保持原状态。
- 仅匹配根云端路径下的后代路径，避免影响其他顶层任务及相似前缀目录。
- 已 `done` 的子项和具有实际失败原因的子项保持原状；暂停后代清空错误和瞬时速度，并让任务统计缓存失效。
- 子项状态只是目录任务当前运行的内存视图。持久化的 SQLite 权威状态仍是根队列任务；恢复后由正常递归下载流程重建/更新子项。

## 安全与兼容

- 不改变单文件任务、全局队列暂停、maintenance、重试次数或源项目操作状态。
- 不因一个普通下载失败而暂停其他子项；只有根任务最终仍是用户 `paused` 时才做收尾协调。
- 不新增 SQLite 字段或迁移，不写远端请求。
- 目录任务正常失败/成功时不重写后代状态。
- 取消或手动重试的 SQLite 事务失败时，恢复任务原状态、错误、时间/计数等内存字段；既有队列故障 fail-closed 行为仍生效。
- 取消事件证据保留被清除的 `retry_wait` 截止 UTC；此时间是本机既有计划，不是百度观察时间。

## 验收

回归覆盖暂停和取消的直接文件/嵌套后代、已完成和真实失败后代保留、重试等待截止证据、Cancel/Retry 的 SQLite 失败回滚，以及单文件续传无回归。随后运行 downloader 与全仓门禁、三平台构建和 preview 包核验。仅本机/mock 验收，不连接真实百度账号或 NAS/SMB。
