持久化任务执行网盘改名或删除前，会按 `fs_id` 重新读取当前元数据；文件 ID、路径、名称、大小、修改时间、目录标记或 MD5 与已完成下载的源信息不一致时，跳过源操作并将任务标记失败。此检查只是操作前核对，百度 API 没有把条件检查与改名/删除合并为原子操作；下载期间仍应避免在网盘端移动、替换或编辑正在处理的项目。请求结果未知仍保持隔离，不自动或人工重发。

若操作前复核发现源身份变化，旧任务会持久化为“源项已变化”，不能手动重试旧元数据。等后台扫描读取到新的云端元数据后，才会创建/执行对应的新身份任务；如果云端列表仍返回旧版本，该任务会继续等待，避免反复下载和重复触碰源项。

v0.7.2 修复下载链接的 access_token 查询参数处理：特殊字符正确编码，不会把 Token 追加到 fragment，也不再将相似参数或路径文字误认为已有 Token；已存在的 Token 和签名 query 原文保留。v0.7.1 加入的 RUN_AS 普通用户运行配置继续适用。

v0.7.1 新增 Compose 的可选 RUN_AS=UID:GID，便于使用普通用户与专用可写目录；留空保持 0:0，不自动修改已有文件 owner/ACL。使用与迁移边界见下文。

包含 v0.7.0 的可选 PUBLIC_ORIGIN，支持外部 HTTPS 代理转发到 HTTP 后端的管理请求和 WebSocket。设置方法与网络边界见下文；未配置时保留原来的回环/SSH 转发方式。默认 443 与数字端口会规范化，认证和未知结果隔离不变。

包含 v0.6.3 修复：凭证轮换成功且新扫描已确认同一文件版本后，旧下载迟到返回认证拒绝，不再让任务重新等待下一次定时扫描。只有明确的旧凭证指纹、新凭证有效和新扫描资格匹配时才继续；无扫描、版本变化、过期或同一凭证再次拒绝仍等待授权。测试反馈可记录是否长期停留在“等待授权”、账号状态及任务状态，不发送 Token 或凭证文件。

包含 v0.6.2 修复：没有 Content-Length 的分块下载提前结束、少于网盘文件大小时，进入既有有界退避与续传；持续失败仍受 MAX_RETRIES 限制。重启后保留临时数据、重试预算与截止时间，必须新扫描确认后才能继续。声明长度不匹配、错误 Content-Range 和超长响应仍拒绝。请勿在重启时删除 `.nas-downloader`。

包含 v0.6.1 修复：大文件 SHA256 校验接入任务取消，取消恢复校验时保留完整临时文件。可在独立测试目录用大文件测试取消和停止服务，再重启检查保留的数据；取消会在读取块之间生效，不能中断操作系统中已阻塞的磁盘读取。结果未知且无完成凭据的目录继续隔离，暂不提供人工放行。

## 测试前准备

1. 在网盘新建 `/NAS_Download_Queue_preview`，只放用于测试的文件副本。该目录必须由你提前创建。
2. 默认 keep 模式会将成功下载的顶层项目改名为 `.可删除`；不是无副作用的只读同步。目录内子项不逐项改名。自动删除仍可通过界面选择，但首轮建议使用默认模式。
3. 下载期间不要新增、替换、移动或编辑正在处理的云端项目。当前 API 流程没有条件删除，也没有远端目录快照锁。
4. 使用独立的本地下载目录。`.nas-downloader` 存放临时文件、本地 SHA256 凭据和队列记录，重启时必须保留。新版用 OS 锁拒绝第二个写入实例；旧版没有该锁，升级复用目录前必须停止全部旧进程。不要删除 writer.lock 来强行并行运行。
5. 下载优先用硬链接发布；文件系统不支持时，程序会在目标目录创建并校验完整副本，再用“不覆盖已存在目标”的原子重命名发布。因此回退路径需要目标文件系统支持原子 no-replace rename，并在发布时额外留出约一个文件大小的空间与复制 I/O。Linux 使用 `renameat2(RENAME_NOREPLACE)`，其标志支持取决于内核和文件系统；Windows 使用不带 `REPLACE_EXISTING` 的 `MoveFileExW` 并请求 `MOVEFILE_WRITE_THROUGH`。该标志请求 Windows 等待移动落盘完成，但具体 NAS/SMB、FUSE、exFAT 等挂载仍须实测，不能视为物理断电保证。临时副本名先登记为“未拥有”，独占创建成功后再耐久标记为“已拥有”；重启只清理有归属凭据且为普通文件的登记项。强制终止若发生在创建成功、归属凭据写入前，可能留下空临时文件，恢复会保留它以避免触碰无法证明归属的磁盘项。若 no-replace 发布不可用，程序会失败关闭并保留网盘源项。

## Windows

在解压目录打开 PowerShell：

```powershell
$env:BAIDU_ACCESS_TOKEN = '你的 Access Token'
.\Start.ps1
```

默认下载到当前版本目录的 downloads，访问 http://127.0.0.1:18089 。浏览器登录用户名为 `admin`。未设置 ADMIN_PASSWORD 时，密码由程序随机生成，读取：

```powershell
(Get-Content .\downloads\.nas-downloader\queue\admin-key.json -Raw | ConvertFrom-Json).key
```

也可以在启动前设置至少 10 字节的 `$env:ADMIN_PASSWORD`。不要发送这个密码或 admin-key.json。登录表单会创建跨服务重启有效、无自动过期的浏览器会话；点击“退出登录”会撤销当前会话。若设备丢失，请停止服务后运行 `baidu-downloader.exe -revoke-admin-sessions` 撤销全部网页会话。浏览器可能按自身策略限制持久 Cookie 的寿命。自定义目录：

```powershell
.\Start.ps1 -DownloadDir 'D:\NAS-preview-downloads' -Port 18090
```

Ctrl+C 停止；再次执行同一命令恢复。不要把 Token 写到提交文件或发送到反馈中。也可以直接运行 bin/windows-amd64/baidu-downloader.exe；其他运行设置从进程环境变量读取，百度应用凭证也会读取当前工作目录 `.env` 中的四个 `BAIDU_APP_*` / `BAIDU_SECRET_KEY` / `BAIDU_SIGN_KEY` 值。启动不强制要求 Token 或应用凭证；未授权时可以进入管理页面，但扫描和下载暂停。

## 网页授权与自动续期

已有有效 Access Token 时可以继续按上面方式启动。若要使用网页授权及后台自动续期，先在[百度网盘开发者平台](https://yun.baidu.com/union)创建应用，复制 AppID、AppKey、SecretKey、SignKey，再在登录后的 `/oauth` 页面首次填写。网页不会回显明文，保存后立即生效；已有环境配置时环境配置优先，网页不能覆盖。

```powershell
$env:BAIDU_APP_ID = '你的应用 AppID'
$env:BAIDU_APP_KEY = '你的应用 AppKey'
$env:BAIDU_SECRET_KEY = '你的应用 SecretKey'
$env:BAIDU_SIGN_KEY = '你的应用 SignKey'
.\Start.ps1
```

管理员登录后打开 `/oauth`，获取授权码，用百度账号完成授权，再点击“已完成百度授权，开始验证”。成功后凭证会保存并应用，后台重新扫描。页面不显示完整 Token。还可同时提供 BAIDU_REFRESH_TOKEN 作为首次启动凭证。

应用凭证保存在 `downloads/.nas-downloader/queue/baidu-app.json`，与用户 OAuth Token 文件 `credentials.json`、账号绑定 `account.json` 和任务数据库分开。非空进程环境变量优先于 `.env`；环境四项全部为空时回退读取 `baidu-app.json`。四项需成组提供。SecretKey/SignKey 以本地明文保存，依赖 POSIX 0600 文件权限或 Windows 下载目录 ACL；请保护整个状态目录及备份。用户 OAuth Token 仍保存在 `credentials.json`，不要共享凭证文件或含它们的备份。

当前网页登录使用 OAuth 设备码流程，不需要回调页 URL。若百度控制台对所选应用类型强制要求 OAuth 回调 URL，请先确认应用类型；当前程序没有授权码回调处理器，不能把管理页地址当作回调地址。

同一下载目录固定绑定一个百度账号，更换账号请使用新目录。首次从旧版本迁移时只能绑定当前验证到的账号，请核对账号。临时刷新失败退避重试；旧凭证过期或被拒绝时暂停新任务，显示 auth_wait，恢复后必须重新扫描确认。仅有 Access Token 且不知到期时间时，如实显示到期未知；没有刷新能力时需要重新授权。

可通过 `-MaxParallel 1 -MaxRetries 3 -RetryBackoffSeconds 5` 调整调度。并发上限 1..32；MAX_RETRIES 为首次失败之后的自动重试次数（0..20），指数退避上限 5 分钟。重启中断不消耗失败重试预算。元数据请求总超时 30 秒，下载空闲 90 秒无数据才超时，正常持续传输没有短总时限。

### 可选普通用户运行（v0.7.1 起）

新的 Compose 配置可在 .env 设置 `RUN_AS=UID:GID`，例如 `RUN_AS=1000:1000`；应使用实际部署账号的 `id -u` 和 `id -g`，不要假定 NAS 账号就是 1000。留空保留现有 0:0 行为，应用不会自行切换身份或修改已有目录权限。

启用前先由部署账号创建空的 `downloads` 目录，确认该账号可读、写并遍历该目录，随后启动容器。bind mount 的实际 UID/GID、文件系统权限与 NAS ACL 仍决定是否可写；RUN_AS 只设置容器进程身份，不授予目录权限。不要用 `chmod 777` 或删除 `.nas-downloader` 绕过错误。

已有目录可能含旧 root 创建的 0600 凭证/状态。切换身份前停止全部旧实例并备份，先用新目录测试；确需迁移旧目录时，由管理员核对路径与备份后调整该专用目录及状态文件的 owner/ACL。程序不会自动递归 chown/chmod，也不要为测试改变共享下载目录的权限。

源码镜像的运行目录已由 `/root` 移到 `/app`，使指定普通 UID 可以访问程序；发布包镜像原已使用 `/app`。已在 WSL Docker/AMD64、临时 ext4 bind mount 验证普通 UID 启动、重启、状态权限、第二实例锁及不可写目录失败；不能替代厂商 NAS ACL、SMB/FUSE 或 ARM64 实机验收。v0.7.0-preview.1 及更早原包尚无 RUN_AS 配置行，v0.7.1 起直接提供该变量。

源码仓库的 Compose 也支持可选 `BAIDU_REFRESH_TOKEN` 和 `ADMIN_PASSWORD`，与发布配置一致。源码根 `.dockerignore` 排除本地 `.env`、Git、下载和私有状态等内容，避免进入 `COPY . .` 构建层；自定义下载目录仍应放在源码树外。源码多阶段镜像已实际构建并用普通 UID 验证启动；其现有版本字段仍是 dev/unknown，不能代替带 BUILD-INFO 和哈希的独立发布包。

## HTTPS 反向代理（v0.7.0 起）

在代理处终止 HTTPS、转发至 HTTP 后端时，设置 `PUBLIC_ORIGIN=https://nas.example:8443`，值为浏览器实际访问的 HTTPS 来源（域名及非默认端口，无路径前缀、query、fragment 或用户密码）。PowerShell 可在启动前设置 `$env:PUBLIC_ORIGIN` 或使用 `-PublicOrigin`；Linux 使用 `export PUBLIC_ORIGIN=...`，Compose 在 .env 填写。程序本身仍监听 HTTP，不管理 TLS 证书。

代理需转发 Authorization、Origin 和 WebSocket Upgrade/Connection，支持长连接；后端保持回环或私有网络限制。服务只信任显式 PUBLIC_ORIGIN，不依据 Forwarded/X-Forwarded-* 放宽校验。配置后管理页应从该 HTTPS 地址访问；直接本机 HTTP 的浏览器 Origin 不再匹配。未配置时保留原来按请求 TLS/Host 校验的规则，回环与 SSH 转发仍可用。

已验证本机 TLS 代理到 HTTP 后端的管理 POST/WSS、认证及恶意 Origin 拒绝；未验证具体 NAS 厂商代理、真实浏览器原生 Basic 登录框或用户证书部署。v0.6.3-preview.1 及更早包尚不支持此配置。

| 正常停止后重新启动 | 根任务历史和默认模式保留；未完成任务须扫描确认源仍在队列才执行 |
| 网络断流/HTTP 429、5xx | retry_wait 展示下次时间，到期后无需手动扫描即可继续；预算用尽后 failed，普通扫描不会重置失败预算 |
| 本地下载阶段取消任务 | 停止后续处理、保留临时数据；源后处理开始后不能取消或重复提交，已发出的云端操作不能撤回 |
| 用相同下载目录启动第二实例 | 明确报目录正在使用，不能同时写入；进程崩溃后 OS 自动释放锁 |
| 不提供百度凭证启动 | 管理页面可登录，健康状态为 waiting_authorization；不发起扫描/下载 |
| 未登录请求页面、API 或 WebSocket | 返回 401；管理认证和百度授权相互独立 |
| 网页授权成功后重启 | 同账号凭证保留并重新验证；不必再次复制 Token |
| 凭证失效或续期暂时失败 | auth_wait / 续期退避；恢复后扫描确认，不消耗下载失败预算 |
| 在任意根任务点击“查看事件” | 首次展开才请求最新事件；时间字段标明 UTC，缺失的时间不显示为伪造值 |
| 点击“更早事件”“返回较新事件”，再刷新任务列表 | 只替换当前事件页，不累积已浏览的事件行；仍能沿游标返回较新页 |
| 重启服务后再查看任务事件 | SQLite 中已提交事件仍可读，未来重试时间标为计划时间 |
| 查看事件结构化证据 | 事件只读，HTML 特殊字符显示为文本；页面不提供修改、删除或解除隔离操作 |

## 取消和手动重试

任务页面和兼容轮询页面均提供立即扫描、根任务取消/重试按钮，按服务端返回的资格显示。每个根任务展示固定 keep/delete 策略、启动次数和下次重试时间。取消后可能仍在排空，等待状态刷新；已发送的云端操作不能撤回。

任务历史较多时，两个页面每页加载 100 条，文件名、进度和大小排序作用于全部任务；页面上的总数及状态卡片也统计完整队列。可以用上一页/下一页浏览历史，切换排序会回到第一页。为兼容旧调用，无分页参数的 `/api/status` 仍返回完整任务列表；管理页使用 `offset`、`limit`（1..200）和 `sort_by`（name/progress/size）请求分页数据。此改进减少浏览器每次更新的数据量和渲染量，但服务启动仍会加载完整队列，分页查询也会扫描队列生成全局统计。

恢复大型历史队列时，程序逐条读取并重建任务，避免同时保留一份完整的原始 JSON 记录映射；已完成等非活动任务不再额外常驻一份实时 Task 副本，下载中的任务仍保留进度。历史仍全部留在内存中的队列记录里，启动依旧需要读取每条任务文件；实际重启耗时会受下载目录所在文件系统影响。升级后可用同一下载目录启动，再检查原有任务总数、状态统计与分页内容均保留。

也可请求 `/api/status`，选 `is_root: true` 的根任务，使用其精确字符串 task_id，避免 JavaScript Number 丢失大整数精度：

```powershell
$adminKey = (Get-Content .\downloads\.nas-downloader\queue\admin-key.json -Raw | ConvertFrom-Json).key
$headers = @{ Authorization = "Bearer $adminKey" }
Invoke-RestMethod http://127.0.0.1:18089/api/status -Headers $headers
Invoke-RestMethod http://127.0.0.1:18089/api/tasks/123/cancel -Method Post -Headers $headers
Invoke-RestMethod http://127.0.0.1:18089/api/tasks/123/retry -Method Post -Headers $headers
```

把 123 换成实际 task_id 字符串。retry 仅接受当前扫描确认存在的 failed/cancelled 根任务，重置失败预算；进行中的任务返回 409，不存在的根任务返回 404。`attempts`、`next_attempt`、`download_mode` 字段分别展示启动次数、下次重试时间和该任务固定的后处理策略。

若通过 ADMIN_PASSWORD 指定密码，请用该密码构造 Bearer 头，不读取随机密码文件。Linux 可使用 `curl -u admin http://127.0.0.1:18089/api/health`，交互输入管理员密码。

全局模式会持久化，只影响以后新登记的任务；已排队的根任务不会因切换全局模式而改变策略。源项目离开队列或被标记时，未完成任务显示需人工核对，不会直接使用旧路径操作网盘。已完成历史仅表示曾经完成，不能代替对后来人工修改/删除本地文件的检查。

按版本号反馈：运行方式/系统架构、测试步骤、预期与实际、脱敏日志、是否重启。不要提交 Token、Secret 或完整下载链接。

## 管理页加入网盘项目

源后处理也有独立完成边界：本地文件完整不代表网盘改名/删除已经完成。新版在发出源请求前持久化 sending，只有严格的同步单项成功响应才能保存 confirmed/done；原先只返回顶层 errno=0 的不完整响应不再当作成功。

若显示“网盘后处理待核对（禁止重发）”（source_unknown），本地成果保留，源路径及 keep 标记目标保持隔离。取消/重试接口返回 409，扫描、更换文件 ID、同 ID 改名和管理页入队都不能解除隔离；当前没有人工放行入口或可靠异步完成查询。不要删除队列日志来重试，也不要把旧版用于处理新版不确定记录；旧版遇到新状态会拒绝启动。升级前停止旧进程并备份整个 .nas-downloader，首轮优先使用新的测试目录。

明确的业务拒绝仍可沿原失败/授权恢复路径处理；发送后的网络错误、5xx、重定向、取消和异步响应可能已产生云端副作用，因此保持结果未知，不按普通下载退避重发。没有真实百度/NAS 证据前，不能把本地模拟故障测试当成这些远端场景已验收。

1. 在队列外准备静止的测试副本，并提前创建配置的队列目录。登录后点击“添加网盘项目”或打开 `/intake`。
2. 浏览云端目录选择项目，也可输入绝对云路径，每行一项、每批最多 20 项。支持分页浏览和跨目录选择。
3. 点击“预检这些项目”，核对源路径、目标路径及固定 keep/delete 策略；预检不会移动文件。冲突、同名、父子目录混选及队列内部项目会被拒绝。
4. 勾选明确确认，再点击“确认移动并加入队列”。此步骤会移动云端项目到固定队列，成功后进入后台扫描。目标不能临时修改，不覆盖、不自动改名；预检 2 分钟过期，重启或认证变化后须重新预检。
5. 查看逐项结果和入队记录。成功、失败、未发送、结果未知分别显示，不能用批次返回成功代替逐项核对。提交断流后查看记录，不盲目重新移动。

**结果未知时目标持续隔离，不会自动重发 Move。按已确认选择，缺少完成凭据的目录暂不提供人工放行入口；目标根目录出现不能证明全部内容完成。**“重新核对可确认的项目”只读取网盘元信息，不能覆盖该限制。已知异步移动尚未提供可靠完成查询，可能持续隔离；不要自行删除 intake 日志来解除隔离。

建议先验证单文件、中文名、目录、目标同名冲突；再核对预检过期、取消勾选无法提交、刷新记录和重启读回。入队页与任务页的策略显示应一致。

目录浏览、入队预检和重新核对均为只读请求。若读取失败，页面会显示安全的 HTTP/百度错误码，并提示可重试读取；该提示不适用于 Move/Delete。远端写操作若结果未知仍必须先查看操作记录，不得盲目重发。

## 网盘管理路径设置与本地目录迁移

- 在“网盘管理”页确认当前网盘监控目录和本地下载目录；未由 `.env` 或启动环境显式配置的路径可在网页修改，并立即影响自动扫描和新下载。
- 显式配置的路径在页面只读；验证启动脚本默认值不会误锁网页设置，复制到 `.env` 并填写路径后页面会显示只读。
- 保存后重启，检查两条路径仍恢复为网页保存值；随后分别通过 `.env`/启动环境覆盖，确认显式值优先。
- 在下载运行、存在未完成入队记录、全盘缓存扫描运行时尝试保存，确认请求被拒绝且旧设置保持不变。
- 网盘目录分页请求共享每次至少 250 ms 的间隔，涵盖实时列表和全盘缓存扫描；下载链接获取仍由下载并发配置控制。这只是客户端节流基线，百度账号/应用实际配额与 429 退避仍需真实账号长时间验证。
- 若同时更改本地路径并勾选“迁移原本地目录”，程序会记录 SQLite 迁移状态，复制全部普通文件、校验 SHA-256 与文件大小后才隔离并删除原目录。冲突、符号链接、特殊文件、占用或核验失败会停止并保留源目录；查看进度和错误后，可排除冲突或关闭占用程序再提交相同路径重试。
- 迁移时下载队列暂停；服务重启会从持久化阶段恢复。运行期间不要手工移动源目录、目标目录或程序状态目录。迁移成功后检查文件和新路径；目标已有同内容文件会复用，不同内容文件不会覆盖。

## 空文件夹清理

1. 完成一次全盘缓存扫描，确认状态为 complete；未完成扫描时页面不会提供候选。
2. 打开网盘管理页“空文件夹清理”，生成候选并检查目录列表、全盘扫描运行 ID 和观测时间。
3. 点击删除后，程序按叶到根逐个重新读取目录身份和实时子项；每项确认成功后刷新当前网盘列表。中途失败或结果未知时停止余下操作，并要求重新扫描和预览。
4. 此流程未在真实百度账号和 NAS 上验收。网盘外部程序仍可能在实时空检查与删除请求之间新增内容；百度 API 不提供原子“仅当目录为空时删除”条件，因此高并发外部改动下仍需小心验证。

## 重复文件扫描与清理

1. 先完成全盘目录缓存扫描。重复扫描仅从完整目录缓存中筛选文件大小冲突组，并依次流式下载文件计算 SHA-256；不会把文件保存到本地临时目录，所需流量约为所有候选文件大小之和。遇到 429、网络超时或暂时认证不可用会按递增间隔重试，SQLite 会保存重试间隔及 UTC 下次重试时间，暂停/重启后按剩余时间继续；身份变化等不可重试错误会停止并记录原因。
2. 扫描可暂停、重启后继续。页面会显示候选处理数量、运行阶段、开始/更新时间和错误；扫描后刷新预览，查看每组拟保留文件、删除项、SHA-256 与各文件摘要核验时间。
3. 可逐个删除或“一键删除预览中的全部多余文件”。删除前会重新读取元信息、下载并核对 SHA-256，再次确认身份后发送删除。任一文件失败、身份变化或结果未知都会停止后续删除；每个已确认删除成功后刷新网盘文件列表。
4. 百度删除接口不支持按摘要/元信息做原子条件删除。网盘外部客户端可能在最后一次身份核对与删除请求间改动文件；程序无法消除该竞态。该能力尚未在真实百度账号和 NAS 上验收。

## 已知边界

- 本地 HTTP 故障测试不等于真实百度账号、真实 NAS 或连续多日验收。
- SHA256 凭据用于检测本地文件变更和确认本次下载的本地身份；不能证明云端提供的内容本身正确。未假定云端 MD5 是普通文件 MD5。
- 当前保证的是代码中的完成判定与进程中断恢复；未验证 NAS 突然断电后的文件系统持久性。
- Linux 版本会对队列/凭据等原子状态更新、关键目录创建和最终文件发布同步父目录；目录同步失败会停止当前步骤，确保网盘源操作不会在 sending 日志未确认落盘时发送。Windows 对原子状态文件替换和最终文件移动请求 `MOVEFILE_WRITE_THROUGH`；Windows 目录创建/删除没有本程序可移植调用的目录 fsync，因此目标 NAS、挂载和存储设备仍需实测，不能仅凭本地成功宣称物理断电耐久。NAS、挂载和存储设备必须实际履行同步请求；本地 ext4/容器测试不能证明物理断电、设备写缓存或控制器持久性。
- 根任务、默认后处理模式、失败次数、重试时间已持久化；目录子任务和实时速度在重启后重新展开，不作为独立队列记录。记录损坏、版本不支持、切换同一存储绑定的 QUEUE_DIR 时启动失败，不静默清空数据。请备份整个 .nas-downloader 后再处理损坏记录。
- OAuth 核心、网页应用、管理认证已实现并有模拟接口和真实本地 HTTP 验证；真实百度设备授权、自动续期和多日运行仍需实测。浏览器原生 Basic 登录与 WebSocket 配合仍需目标浏览器验收；命令行 Bearer/Basic 已验证。
- 任务按钮、管理页入队和油猴路径衔接已实现；油猴真实页面适配尚未验收。管理页云端列表按 `start/limit` 向网盘读取当前页并多取 1 项判断是否有下一页，不再为每次翻页遍历整个目录；上游不提供可依赖的准确总数，翻页也不提供远端快照，期间网盘目录变化可能改变后续页内容。后台队列扫描仍需读取完整队列目录后再核对任务，大型队列的扫描耗时和目标 NAS 表现仍需实测。
- 入队核心和 HTTP/磁盘重启链路有本地模拟服务验证；浏览器入队交互仅用隔离数据夹具验证，真实百度移动、异步完成、管理登录与下载后处理完整链路仍待实测。
- 顶层 `.可删除` 项按原有约定跳过；要重新测试请在网盘恢复原名，并使用新的本地测试目录。
- 只处理静止的队列副本，暂不支持多个实例写同一下载目录。

包内 SHA256SUMS.txt 可用于核对文件传输；它是完整性清单，不是签名。
